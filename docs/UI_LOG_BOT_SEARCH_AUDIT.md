# 全局日志 Bot 名称查找验收

## 基线与用户旅程

基线为 v0.14.0 发布后的 main `1fd4f5ee19feff3f4b66ab9c32203b05fcf8cd1b`。全局 `/logs` 的 Bot 筛选已读取全部分页；125 个合成 Bot 的 390px 截图显示，下拉菜单一次约显示 8 个 Bot，找到列表末尾的 Bot 需要反复滚动。基线截图位于 `.acceptance/ui-efficiency/log-bot-options-final/390-recovered.png`，相关加载与失败记录见 [上一轮验收](UI_LOG_BOT_OPTIONS_AUDIT.md)。这是本地合成浏览器证据，不代表线上 Bot 数量或真实用户耗时。

用户旅程：先从 Bot 列表按名称找到目标，再到全局日志查看该 Bot 的历史与实时记录。当前日志页虽能选到完整列表的末项，却缺少可见的名称查找。

## 本轮验收条件

- 全局日志 Bot 筛选入口在桌面和 390px 手机上可见；打开后直接输入名称，能从完整加载的 125 个 Bot 中找到并选中末项，无需沿长列表滚动。
- 搜索只过滤弹层候选，不改变日志内容搜索、请求参数或清理范围。选中 Bot 后历史和实时日志继续按 `botId` 筛选；清除选择恢复全部 Bot。
- 加载中、零匹配、第二页失败与重试都有准确反馈；未完整加载时不把部分选项当成全部。已选 Bot 在加载失败或零匹配时仍可识别并清除。
- 桌面与手机、鼠标与键盘、中文和英文均可用；方向键、Enter、Escape、输入法组合输入与焦点回归明确，页面无横向溢出。
- 保留 URL 初始 `botId`、分页、实时暂停状态重置、Bot 范围的清理确认及失败恢复；浏览器后退/前进时页面、历史与实时日志范围跟随 URL 一致，不操作真实日志或生产数据。
