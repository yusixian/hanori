# 全局日志 Bot 筛选选项验收

## 当前版本基线

基线为 v0.13.0 发布提交 `ed552c5925c722d2f3be023739d74602c8a33f82`。`/logs` 全局日志页只请求 `GET /api/bots?page=1&limit=100` 来填充 Bot 筛选框。使用 125 个合成 Bot 的生产构建预览，在 1440×900 和 390×844 打开筛选菜单，均只有「全部 Bot」加前 100 个 Bot，不能选择 Bot 125；每档没有页面异常或横向溢出。截图和请求记录位于 `.acceptance/ui-efficiency/log-bot-options-baseline/`。

用户旅程：管理员先在 Bot 列表按名称找到 Bot 125，再进入全局日志页排查其错误，却不能从该页选中这个 Bot。Bot 列表接口支持分页，日志查询接口允许按 Bot ID 筛选，当前限制在面板选项加载。

## 验收条件

- 全局日志页读取全部 Bot 选项，Bot 125 可从筛选框选中；历史日志请求带对应 `botId`，清空筛选后恢复全局日志。
- 选项分页失败时不显示不完整列表，页面提供明确的失败状态和重试；重试成功后才提交完整选项。
- 初始 URL 指定的 Bot、中文/英文、桌面/390px 手机与键盘选择可用；保留日志历史、实时流和清理范围的既有语义。
- 浏览器证据使用合成 Bot 和日志，不执行日志清理、真实 Bot 操作或消息发送。

## 实现与交付

- 面板对 Bot 列表执行完整分页读取，校验跨页总数和最终去重选项数后一次性提交。失败不显示部分选项，显示错误与重试；组件卸载或重试会取消旧请求，避免过期结果覆盖。URL 中已选的 Bot ID 在选项未就绪时仍可显示并继续筛选日志。
- 日志页聚焦浏览器测试 10/10 通过，覆盖 125 Bot 第二页、失败/重试、URL 初始选择、焦点与请求参数；Panel 类型检查、i18n 2435 keys、局部 lint/format 和生产构建通过。
- 生产构建预览在 1440×900 和 390×844 使用 125 个合成 Bot 与空日志，每档 18 个模拟 GET 请求。Bot 125 可选择，日志查询带 `botId=demo-125`，清空后恢复全局请求；第二页失败没有部分选项，重试后恢复完整 126 个菜单项；没有页面异常或横向溢出。截图和请求记录位于 `.acceptance/ui-efficiency/log-bot-options-final/`。
- 公开文档类型/构建与 v0.13.1 版本页桌面/手机 2/2 定向检查通过。Lody 独立只读代码审查未发现 P1/P2，复跑日志页浏览器测试 10/10、i18n 与差异检查通过。另一 Lody 视觉复核未发现阻碍本轮交付的问题；它将大量 Bot 时的菜单查找成本列为下一轮独立 P2。完整 CI 与 GitHub Release 待完成。

## 限制

浏览器使用合成数据，没有读取真实日志、连接真实 Bot 或执行日志清理。完整隔离验收器依赖不可用的 Docker daemon，固定 3100 端口也属于其他项目；这里报告的是聚焦生产预览。当前下拉菜单最多显示约 288px 高的选项视口，手机寻找 Bot 125 仍需长距离滚动；独立体验复核建议下一轮在日志页加入可见的 Bot 名称查找。约 15 个菜单视口是按截图尺寸估算，并非真人计时结果。
