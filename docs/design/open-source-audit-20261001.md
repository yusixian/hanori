# Hanori 与 MCP Platform 开源脱敏复查

日期：2026-10-01。状态：两份独立功能分支完成本地验证；真实配置未启用，尚未创建公开仓库、发布或部署。

## 结论与范围

本轮检查当前跟踪源码、内置生图调用链、配置示例、公开导出文件和本机环境秘密的重复出现情况；没有公开旧 Git 历史，也没有读取生产数据库。没有发现额外内置的真实 PixAI API Key、Telegram token 或 OAuth 凭据。确认并处理了私人服务默认地址、个人 Telegram 示例、昵称、内部文档和 Docker 构建上下文的分发问题。

当前源码已移除历史默认加密 key。旧实例仍须按下文保留实际用钥；本轮未修改真实配置，扫描的「0 命中」不代表线上密钥已经迁移或轮换。

## 本轮修改

### Hanori

- 移除生图 MCP 的私人固定地址。`PIXAI_MCP_URL` 留空时关闭集成；生产接受显式 HTTPS 地址，拒绝 URL 用户名、密码、查询参数和片段。本机 HTTP 仅供开发。
- OAuth token、动态客户端注册、发现结果、PKCE 和 callback state 绑定完整 endpoint。旧版无绑定授权和其他 endpoint 的授权都需重新授权；数据库事务锁内完成 endpoint 校验、旧状态清除和 callback 消费，避免新旧实例交错写入时混用凭据。
- 补齐未配置启动、旧授权状态、并发写入及 callback 隔离测试，并更新公开配置和升级文档。
- 替换六个测试文件中的个人昵称。Gitleaks 限定 manifest 文件路径和哈希行格式，并配合独立内容哈希校验；没有忽略整个 manifest。修复完整哈希位于扫描分块末尾的误报，两套配置共 76 项合成回归通过，真实凭据前后相邻与边界情况仍被阻断。
- 所有环境必须显式提供 `ENCRYPTION_KEY`，Compose 在缺失时提前拒绝启动；新增 `upgrade:env` 离线工具，从维护者指定的旧完整 commit 保留原密钥，可选恢复原图片 MCP 地址。只生成新的 `0600` 配置文件，不覆盖输入、不操作数据库、不输出秘密。

### MCP Platform

- 替换 Telegram Reader 的个人频道、私群链接、消息 ID 和 UI 示例，保留测试原有的大整数及私群前缀语义。
- Docker 上下文改为构建白名单，排除各级环境文件、运行数据、交接记录及私有运维产物。
- 新增随机配置初始化、单机生产 Compose、独立迁移服务、数据库及图片持久卷，以及自部署、备份、升级和恢复指南。初始化拒绝覆盖，权限为 `0600`，不打印秘密。
- 新增 `export:public`、`check:public`、`sync:public`。默认导出指定提交的审核路径，不携带 Git 历史；工作树快照只能审阅。同步默认仅预览，保护社区修改，拒绝共享私有 Git 元数据、脏工作区、主分支和符号链接。
- 公开 README、安全/贡献指南和 Ubuntu CI 使用专门模板；CI 包含独立凭据扫描。内部研究、交接和生产记录不导出，保留审核过的通用部署合同和完整数据库迁移。
- 新增隔离部署演练脚本：随机项目、合成凭据、内部网络、无宿主端口和目录挂载；覆盖迁移、登录、凭据读回、容器重建持久化、独立数据库与文件恢复。40 项行为测试和 Compose 配置检查通过，实际容器演练待 Docker 引擎可用后执行。
- 未擅自添加许可证，现有 Docker 许可标签仍为 `UNLICENSED`。

## 已有实例的升级约束

1. Hanori 本地 `.env` 未显式设置 `PIXAI_MCP_URL`。升级前需要填入自己的完整服务地址，等待旧任务完成，重建后由 owner 重新授权；本轮没有修改真实 `.env`。
2. Hanori 新源码已删除历史默认加密 key，本地 `.env` 尚未显式设置 `ENCRYPTION_KEY`。升级前必须核对正在运行的 commit 和平台 Secret、Compose、进程环境实际生效的密钥，再按公开备份升级指南生成受保护的配置。工具优先保留输入文件中的非空密钥；缺失时从指定旧 commit 恢复默认值，绝不随机替换。现有数据库无需为保留原 key 改写；这不是密钥轮换，也不是已完成生产升级。
3. 产品改名和换源码仓库不应改变已有数据库、volume、组织标识、迁移 journal 或密钥。MCP Platform 的凭据 key ring 同样需要随备份安全保留。
