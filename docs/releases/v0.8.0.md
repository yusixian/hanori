# v0.8.0 — AI 读取缓存头像

AI 现在可在明确请求下读取人物档案中的缓存头像，直接进行视觉分析，无需因为只能获得 `hasAvatar` 而再次索要图片。

## 更新内容

- 新增 `get_profile_avatar` 工具，按明确 Telegram 用户 ID 读取当前 Bot 的缓存头像；普通回复与续聊均支持。
- 图片以真正的图像消息进入模型上下文，支持当前 OpenAI 兼容与 Google 适配器；每次请求最多读取三个头像。
- 复用个人化隐私规则：请求者关闭个人化时禁用，目标用户为 off 时拒绝，isolated 头像仅本人可读。档案与缓存按 Bot 隔离。
- 区分无档案、无头像、缓存不可用、权限拒绝和临时故障；不向模型暴露文件路径、存储凭据或永久公开 URL。
- 工具日志与持久历史只记录状态，图片仅保留在当次模型请求。读取头像不改变角色形象或绑定的编辑权限。

操作说明见文档站「角色与提示词资产库」中的「从缓存头像整理外貌」，以及「隐私、历史与记忆」。

## 升级说明

- 从 v0.7.0 升级无需数据库迁移或新增配置。需要启用人物档案记忆，并选择支持视觉输入的回复模型。
- 只读取已有缓存，不临时调用 Telegram 下载头像；旧缓存可能与用户当前头像不同，缺失或损坏时请用户提供图片或等待正常刷新。
- 头像可读不代表允许替别人修改角色；保存外貌提示词继续遵守已有维护规则。
- GitHub Release 与文档构建不代表生产实例已部署。

## 验证范围

针对头像缓存、Bot 隔离、本人/他人隐私、工具状态、普通回复和续聊接线进行测试；用模拟 HTTP 响应验证真实模型适配器发出了图片内容。同步验证文档构建、匿名访问和版本页。没有调用真实模型、读取真实用户头像或发送 Telegram 消息。
