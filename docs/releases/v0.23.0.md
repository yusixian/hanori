# v0.23.0 — 持久定时任务与管理员审批

涵盖 v0.22.0 之后的全部变更（#196 实现 #192，并整合 #117 的调度需求）。

## 功能

- **自然语言提案与审批**：群友可用自然语言提出定时任务，Bot 生成完整计划卡；管理员确认创建、试跑、修改或取消，卡片绑定版本、消息与有效期。
- **持久化日历调度**：支持一次性、固定间隔及指定时区的周/月/季调度，取消 1 天或 7 天的远期上限。月末自动对齐有效日期，夏令时缺失时间顺延、重复时间取首次。
- **独立执行配置**：任务可配置独立 Agent（复用既有子代理），限定源聊天/话题数据范围、投递目标与执行约束。
- **管理与故障恢复**：支持在聊天与面板查看任务和执行记录。服务重启后自动恢复调度，漏跑多个周期只补最近一期；中断任务保留记录且不自动重放，避免重复副作用。
- **失败熔断与对话流畅**：连续 3 次周期失败自动暂停，管理员排查后可恢复；任务配置补充对话不受普通接话冷却阻断。

## 升级与兼容

- 新增任务及执行记录表，升级需运行随附数据库迁移。原有定时器与管理入口保持不变，不自动迁移为新计划。
- 启用持久任务服务后，`set_timer` 改为生成待审批的一次性计划，须经计划卡批准后才生效。
- 源话题过滤依赖消息持久化中的真实话题标记，升级前缺失该标记的历史消息不会被反推归属。配置默认值在执行时继承，执行记录保存当次实际配置。

## 验证边界

本地通过类型、lint、i18n、生产构建、单元测试（4,679 通过，227 跳过）、面板浏览器测试（490 通过）及公开文档浏览器测试（42 通过）。隔离 PostgreSQL 验证了新增迁移、重启补跑去重、中断恢复及隐私/话题范围隔离；因本机缺少 pgvector，未验证完整历史迁移链。真实 Telegram 投递与线上功能需部署后验收。
