# v0.21.1 — 仓库发现与诊断可靠性（未发布候选）

此文件记录待发布变更，尚未创建 tag 或 GitHub Release，产品版本仍为 v0.21.0。

## 改进与修复

- 修复多步 AI 回复只保留最后一步正文的问题：普通回复与选择后的续写都保留工具调用前的正文，避免剧情只剩选择提示或收尾句。
- 补发多步正文时逐步核对 `multi_message` 送达记录，避免把已完整发出的步骤再次拼进收尾消息；部分送达的步骤仍保留完整正文，防止误删未发送内容。
- 管理员可使用 `github_list_repositories` 分页查看当前 Bot 的仓库白名单。仓库指代不明或读取返回 404 时，工具引导先核对列表和已有上下文，避免猜测 owner；普通成员无法枚举白名单。
- 结构化运行诊断默认保留时间由一小时延长到 24 小时，仍受每 Bot 500 条链路、每链路 64 个事件和进程生命周期限制。
- 同一轮重复加载同一个不存在的 Skill 或参考资料，第三次失败后停止后续工具调用，转为文字说明；日志记录固定失败码和尝试次数。
- 修复工具 JSON Schema 转换后丢失运行时校验和默认值填充的问题。提示词资产新建支持省略 `id` 或传 `null`；缺省备注和固定标记会正确填充，非法参数在写入前拒绝并记录诊断。
- 提示词资产保存返回明确的新建、更新或拒绝原因。存储异常保留脱敏日志，并提醒先核对结果，避免未知写入结果导致重复创建。
- 运行状态明确标记模型、Telegram 主动探针及 GitHub 后台任务读取尚未接入，保留最近观测事件，避免把未知状态误判为故障或健康。

## 升级注意事项

- 无数据库迁移。已有 `RUNTIME_DIAGNOSTIC_RETENTION_MS=3600000` 配置仍保持一小时；需要改为 `86400000` 或移除覆盖并重启服务才能采用新默认值。
- 延长保留时间不会恢复此前已过期、被容量淘汰或重启前的诊断记录。仓库列表表示配置范围，不保证 GitHub 远端可访问。

## 验证边界

本地回归覆盖仓库枚举权限与分页、24 小时过期边界，以及真实 AI SDK 多步调用中的 Skill 失败熔断。真实模型、GitHub 权限和 Telegram 投递需在授权部署后验证；本候选不表示已部署。

资产保存回归通过真实 AI SDK 执行工具参数校验、默认值填充和错误输出；数据库调用使用隔离替身，未操作线上资产，也未新增付费模型或 Telegram 主动探针。
