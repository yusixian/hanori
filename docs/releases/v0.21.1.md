# v0.21.1 — 仓库发现与诊断可靠性（未发布候选）

此文件记录待发布变更，尚未创建 tag 或 GitHub Release，产品版本仍为 v0.21.0。

## 改进与修复

- 修复普通群 GitHub Issue 确认误将回复串当作话题的问题：同一发起管理员换一条回复链后仍能查询、撤销和确认新提案；真正话题继续隔离，身份、聊天和当前权限检查保持有效。拒绝提示区分账号、聊天和话题，日志补充有限的回调元数据。

- yt-dlp 字幕支持语言/来源筛选、平台 CC 优先和 YouTube 自动翻译折叠；查询视频直接返回推荐字幕引用，避免在大量翻译轨道中反复翻页。跨回合失效与未知引用返回独立错误和重新查询提示，真实上游错误仍保留原分类（#184）。
- yt-dlp 配置页补充开始总结视频的步骤、可展开的 Cookies 填写教程和下载限制说明；字段跟随中英文页面语言显示。

- 新增通用 yt-dlp 插件，自动使用全部内置站点提取器读取视频元信息、章节、格式和带时间戳的人工/自动字幕；支持按域名使用加密保存的 Netscape Cookies。总结优先读取字幕，只有简介时明确标记资料来源。
- 通用视频下载复用持久任务、缓存、配额、取消和 Telegram 投递流程；原生 HTTP/HLS/DASH 下载与无网络的 MP4 合并/转换分离，保留 Bilibili 专用插件。元信息未知时长的资源在转换后核验实际时长，下载过程仍受大小与时间限制。

- 图片 MCP 支持在「用量与生图治理」页面填写一个平台域名，自动配置 PixAI、GPT Image 和 Gemini Image。配置由所有 Bot 共享，保存到数据库并立即生效，无需新增环境变量；各供应商仍分别授权。更换平台会清除受影响连接的旧授权，未改变地址的连接保留授权。

- 修复多步 AI 回复只保留最后一步正文的问题：普通回复与选择后的续写都保留工具调用前的正文，避免剧情只剩选择提示或收尾句。
- 补发多步正文时逐步核对 `multi_message` 送达记录，避免把已完整发出的步骤再次拼进收尾消息；部分送达的步骤仍保留完整正文，防止误删未发送内容。
- 管理员可使用 `github_list_repositories` 分页查看当前 Bot 的仓库白名单。仓库指代不明或读取返回 404 时，工具引导先核对列表和已有上下文，避免猜测 owner；普通成员无法枚举白名单。
- 结构化运行诊断默认保留时间由一小时延长到 24 小时，仍受每 Bot 500 条链路、每链路 64 个事件和进程生命周期限制。
- 同一轮重复加载同一个不存在的 Skill 或参考资料，第三次失败后停止后续工具调用，转为文字说明；日志记录固定失败码和尝试次数。
- 修复工具 JSON Schema 转换后丢失运行时校验和默认值填充的问题。提示词资产新建支持省略 `id` 或传 `null`；缺省备注和固定标记会正确填充，非法参数在写入前拒绝并记录诊断。
- 提示词资产保存返回明确的新建、更新或拒绝原因。存储异常保留脱敏日志，并提醒先核对结果，避免未知写入结果导致重复创建。
- 运行状态明确标记模型、Telegram 主动探针及 GitHub 后台任务读取尚未接入，保留最近观测事件，避免把未知状态误判为故障或健康。

## 升级注意事项

- 已生成的 Issue 确认卡及 SHA-256 不会改写。普通群旧卡若仍因旧回复串被拒，可为尚未执行的待确认请求重新发起提案；执行中或结果未知的请求应先核实，不能直接重复创建。

- 图片 MCP 在首次保存页面配置前兼容原来的三个独立环境变量；保存后以页面配置为准，清空后保存也不会恢复旧环境变量。更换平台前应等待已有生图任务完成；旧任务不会转到新平台执行。

- 数据库迁移 `0070` 为视频下载任务增加来源，旧任务保持 Bilibili；`0071` 允许上游尚未提供视频时长，发送前仍必须取得并核验实际时长。更新应用与 media 转换服务镜像后，在插件页面安装并为目标 Bot 启用 yt-dlp；不会自动启用下载或读取浏览器 Cookies。
- 已有 `RUNTIME_DIAGNOSTIC_RETENTION_MS=3600000` 配置仍保持一小时；需要改为 `86400000` 或移除覆盖并重启服务才能采用新默认值。
- 延长保留时间不会恢复此前已过期、被容量淘汰或重启前的诊断记录。仓库列表表示配置范围，不保证 GitHub 远端可访问。

## 验证边界

通用 yt-dlp 使用真实提取器与合成网络响应验证；真实 YouTube 匿名访问可能触发机器人检查，不能保证每个站点、账号、地区和网络出口均可用。未授权部署或操作生产数据。

本地回归覆盖仓库枚举权限与分页、24 小时过期边界，以及真实 AI SDK 多步调用中的 Skill 失败熔断。真实模型、GitHub 权限和 Telegram 投递需在授权部署后验证；本候选不表示已部署。

资产保存回归通过真实 AI SDK 执行工具参数校验、默认值填充和错误输出；数据库调用使用隔离替身，未操作线上资产，也未新增付费模型或 Telegram 主动探针。

图片 MCP 回归覆盖地址规范化、配置持久化、旧配置兼容、所有者权限、并发保存和连接替换，以及桌面和手机页面的保存与错误反馈。数据库使用隔离替身，真实平台 OAuth 和线上生图需在授权部署后验证。

Issue 确认回归贯穿 AI 入站、工具装配、持久提案服务和按钮回调；Telegram、GitHub 及数据库均使用隔离替身。未验证线上按钮或部署效果。
