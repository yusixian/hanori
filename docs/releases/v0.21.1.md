# v0.21.1 — 仓库发现与诊断可靠性（未发布候选）

> 待发布候选：尚未打 tag 或发布 GitHub Release，产品版本仍为 v0.21.0。

## 改进与修复

- **可编辑历史消息**：Bot 历史回复按分片持久化真实 Telegram 消息 ID，重启后仍可定位编辑；编辑校验 Bot 与聊天归属，支持 HTML 和原生 Rich Message 并同步历史（旧历史无 ID 不回填；远端成功但历史同步失败时返回部分成功）。
- **普通群 Issue 确认**：修复普通群误将回复串当作话题的问题，发起管理员换一条回复链后仍可查询、撤销或确认新提案；真正话题继续隔离，拒绝提示区分账号、聊天和话题。
- **通用 yt-dlp 插件与字幕优化**：
  - 新增通用 yt-dlp 插件，支持内置站点提取器读取视频元数据、章节、格式与带时间戳字幕，支持按域名加密保存 Netscape Cookies；总结优先读字幕，仅有简介时明确标注来源。
  - 字幕支持语言/来源筛选、平台 CC 优先与 YouTube 自动翻译折叠，查视频直接返回推荐字幕引用；跨回合失效返回明确重查提示（#184）。配置页补充使用步骤、Cookies 指南与中英文切换。
  - 通用视频下载复用持久任务、缓存、配额、取消与投递流程，分离下载与无网络 MP4 转换；上游未知时长时在转换后核验。
- **图片 MCP 统一配置**：可在「用量与生图治理」填写单个平台域名，自动配置 PixAI、GPT Image 与 Gemini Image，跨 Bot 共享并立即生效，无需额外环境变量；各供应商仍分别授权，更换平台只清除受影响连接的旧授权。
- **多步 AI 回复**：修复多步回复只保留最后一步正文的问题，普通回复与选择续写均保留工具调用前的正文，并核对 `multi_message` 送达记录避免重复拼接。
- **GitHub 仓库白名单**：管理员可通过 `github_list_repositories` 分页查看当前 Bot 允许访问的仓库（普通成员不可枚举）；仓库指代不明或 404 时先核对列表再操作。
- **运行诊断与工具健壮性**：
  - 结构化运行诊断默认保留时长从 1 小时延至 24 小时（仍受每 Bot 500 条链路、每链路 64 事件与进程生命周期限制）。
  - 同一轮重复加载不存在的 Skill 或参考资料，第 3 次失败后熔断并转为文字说明。
  - 修复工具 JSON Schema 转换丢失运行时校验与默认值的问题；提示词资产新建支持省略 `id` 或传 `null`，明确返回新建/更新/拒绝原因，存储异常提醒先核对避免重复创建。
  - 运行状态明确标注未接入的主动探针，避免将未知误判为健康或故障。

## 升级注意事项

- **Issue 确认卡**：已有确认卡与 SHA-256 不变；普通群旧卡若因旧回复串被拒，可为未执行的提案重新发起，执行中或结果未知的请先核实。
- **图片 MCP**：首次保存页面配置前继续兼容原有三个环境变量；保存后以页面配置为准（清空保存不会回退环境变量）。更换平台前请等待在途生图任务完成。
- **数据库迁移**：新增迁移 `0070`（视频下载任务来源，旧任务默认 Bilibili）与 `0071`（允许上游未提供时长，发送前核验）。升级 app 与 media 镜像后在插件页手动安装启用 yt-dlp。
- **诊断保留时长**：若显式设置了 `RUNTIME_DIAGNOSTIC_RETENTION_MS=3600000`，需改为 `86400000` 或移除后重启才生效；不会恢复此前已过期或重启前的记录。

## 验证边界

yt-dlp 使用真实提取器与合成响应验证（YouTube 匿名访问可能触发反爬，可用性取决于站点、账号与出口）。仓库枚举、24 小时诊断过期、Skill 熔断、资产校验、图片 MCP 与 Issue 确认均已通过本地回归测试，数据库与外部平台使用隔离替身；真实模型、OAuth、付费生图与线上按钮需部署后实测。
