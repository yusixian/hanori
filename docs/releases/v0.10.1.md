# v0.10.1 — 对话加载与删除恢复

明确区分对话列表、消息与压缩摘要的读取失败和空态，提供就地重试，并将删除结果与刷新结果分开提示。

## 修复与改进

- **明确失败与空态**：列表、消息和摘要仅在请求成功后展示空态或零总数；读取失败提示错误与 **重试**，同查询下保留旧内容并标明可能过期。
- **防旧请求覆盖**：列表与详情新增刷新入口；切换 Bot、会话或页码后，迟到响应不会覆盖当前视图。
- **可核对的删除流程**：单条消息、摘要和整会话删除均校验 HTTP 与业务结果；结果无法确认时保留记录并提示 **刷新并核对**（仅重拉数据，不自动重删）。
- **拆分删除与刷新反馈**：已确认删除成功但刷新失败时明确提示，待核对刷新成功后再允许继续删除，避免对着陈旧列表重复操作。
- **并发与边界处理**：删除与核对期间禁用相关导航与删除按钮；活动摘要的服务端冲突会明确提示并支持刷新；删除清空最后一页时自动回退有效页码。手机端沿用列表／详情切换与原有删除确认。

## 升级说明

- 无需数据库迁移或新增配置，接口、权限与数据保留规则不变。
- 网络中断后请先刷新核对；关闭或刷新网页不会保留未确认状态。
- 文档站需随应用重新构建部署。

## 验证范围

已通过 21 项会话管理 Chromium 回归、桌面／移动端生产构建模拟 API 验证及公开文档检查。属于本地与合成数据验证，未覆盖真实后端故障、生产删除或真实 Telegram 消息。
