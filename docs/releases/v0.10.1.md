# v0.10.1 — 对话加载与删除恢复

对话列表、消息和压缩摘要现在会明确显示读取失败，并提供就地重试；删除结果与随后刷新页面的结果分别提示，方便先核对再继续操作。

## 修复与改进

- 列表、消息和摘要只有在请求成功后才会显示空态或零总数。读取失败时显示错误和 **重试**，相同查询下已有内容会保留并标明可能过期。
- 列表与详情增加刷新入口。切换 Bot、会话或页码后，较早请求的结果不会覆盖当前页面。
- 单条消息、摘要以及整会话删除均检查 HTTP 和业务结果。请求结果无法确认时保留记录，提示 **刷新并核对**；此操作只重新读取数据，不自动再次删除。
- 已确认删除成功但刷新失败时，页面明确提示“已删除，但未能刷新页面数据”。刷新核对成功后才能继续删除，避免根据陈旧记录重复操作。
- 删除及核对期间暂时禁用相关导航和删除操作；普通读取失败仍可继续浏览。活动摘要的服务端冲突会明确提示，并可刷新最新状态。
- 删除导致最后一页消失时，返回有效页码。手机继续使用列表与详情切换，保留原来的删除确认方式。

## 升级说明

从 v0.10.0 升级无需数据库迁移或新增配置。服务端接口、授权和数据保留规则保持不变。网络中断后请先刷新核对；关闭或刷新整个网页不保留页面内的未确认状态。

GitHub Release 与文档构建不代表生产实例已经部署。

## 验证范围

候选版本通过了21项会话管理 Chromium 回归，覆盖读取失败与真空态、旧请求隔离、三类分页退路、删除未确认、原范围核对、活动摘要冲突、最后页缩页和慢请求重复点击。相关类型、格式、lint、双语校验和 Panel 生产构建通过。

生产构建在1440×900、390×844两档使用全部模拟 API 验证错误恢复，每档24次请求，没有页面异常或横向溢出。公共文档类型、构建以及14项桌面手机匿名访问、搜索、深链和指南检查通过。

这些是本地与合成数据验证，不等同于真实后端故障、物理手机或生产部署；没有读取真实会话、执行生产删除或发送 Telegram 消息。CI、合入和发布结果以对应提交的 GitHub 检查及 Release 为准。
