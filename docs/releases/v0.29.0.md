# v0.29.0 — 模型重试与备用模型

## 新增

- AI 设置支持全局模型恢复策略，以及群聊独立覆盖。每轮额外重试预算为 0–2 次，默认 1 次；备用 Provider 与模型默认不配置。
- 可恢复的上游解析、限流、服务和网络错误会在预算内重试；预算用尽后，可切换一次已配置的备用模型。同一 Provider 与模型不会形成回退循环。
- 工具参数修复与请求重试共享整轮预算；修复阶段只生成参数，不执行工具。已经执行的工具不会因恢复流程被重新执行。
- 恢复日志单独保留有界、脱敏的 HTTP 状态、错误码、请求 ID、Provider、模型和阶段信息，避免被大请求正文挤掉。

## 使用与升级

在 Bot 的 AI 设置中调整重试次数，或从已配置的 Provider 模型目录中选择备用模型；保存后生效。群聊不启用独立覆盖时继承全局设置，独立覆盖可以明确关闭备用模型。

无需数据库迁移。升级不会替换主模型，也不会自动选择备用模型。默认的一次重试适用于未保存恢复设置的实例；将重试次数设为 0 且不配置备用模型可关闭恢复请求。

## 边界与验证

权限、确定的配置或 schema 错误不盲目重试；取消和已暴露内容后的流中断会终止，避免重复输出或工具副作用。重试和备用请求仍受原回合的取消与超时限制，并可能增加上游调用费用。

使用可控 Provider 覆盖成功、失败、共享预算、取消、部分流和工具副作用；浏览器使用可控 API 验证保存重载及桌面/移动端设置。配置入口上线不表示生产已经启用备用模型，生产故障恢复效果未通过修改生产模型来测试。失败请求若上游不提供用量，无法推算其实际计费。
