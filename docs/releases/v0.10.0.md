# v0.10.0 — 人物检索与记忆筛选

人物档案搜索现在可以浏览全部匹配结果，人物与长期记忆之间也有了直接入口；记忆筛选会保存在 URL 中，便于刷新、返回和分享当前范围。

## 更新内容

- 人物档案管理搜索改用服务端分页和真实总数。超过 10 条的匹配结果可以继续翻页，搜索页按最近出现时间和档案 ID 稳定排序。
- 人物卡新增 **查看记忆**，直接进入当前 Bot 下该 Telegram 用户的记忆范围。
- 记忆页支持组合全部、仅通用或指定用户范围，以及分类和内容搜索；修改条件后点击 **搜索** 才会应用，清除筛选会回到第 1 页。
- 已应用的记忆范围、分类、搜索和页码保存在 URL 中，支持刷新、复制链接及浏览器前进/后退。编辑或写入结果尚待确认时，新地址会延后应用，避免把未确认状态与另一组结果混在一起。
- 从人物卡进入指定用户范围后，新建记忆表单会预填该用户 ID，并允许在提交前修改或清空。
- 写入或确认刷新失败时继续显示错误并保留当前草稿；切换筛选前需要先保存或取消正在编辑的记忆。

管理页面的人物搜索不再限制为 10 条。AI 工具内部的人物搜索仍最多返回 10 条，以保持既有模型调用和上下文范围。

## 升级说明

- 从 v0.9.1 升级无需数据库迁移或新增配置，人物档案和记忆的普通读写权限保持不变。
- `GET /api/bots/:botId/memories` 的 `telegramId` 查询参数现在只接受空值、`general` 或十进制安全整数。过去会静默退化为“不筛选”的非法值现在返回 HTTP 400；自定义客户端应在升级前检查参数格式。
- 页面内的错误恢复会保留当前草稿，但离开页面、关闭页面或刷新浏览器时不承诺保留尚未提交的内容。
- GitHub Release 与文档构建不代表生产实例已部署。

## 验证范围

候选版本已通过人物档案 26 项、记忆 24 项浏览器回归，以及后端人物分页与记忆参数契约相关的 43 项测试；相关 Panel 与 Server 类型检查、格式、lint、双语校验和 Panel 生产构建通过。浏览器测试使用模拟 API 数据。

独立临时 PostgreSQL 17 验证了 25 个搜索匹配的 20＋5 分页、真实总数、Bot 隔离、原有搜索字段和同时间记录的稳定排序，AI 搜索仍最多返回 10 条。生产构建在 1440×900、390×844 下验证人物直达记忆、快速前进/后退、刷新、长分类、非法 ID、读取失败恢复和新建预填，无页面错误或横向溢出。公共文档类型、构建及 14 项桌面手机检查通过。

这些验证不等同于生产部署或真实 Bot 行为；没有读取真实头像、修改生产档案或记忆，也未发送 Telegram 消息。CI 和发布状态以对应提交的 GitHub 检查及 Release 为准。
