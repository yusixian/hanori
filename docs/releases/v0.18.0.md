# v0.18.0 — 更新 Lody CLI 与模型列表

Dev Harness 的执行设置新增「刷新 Agent 和模型」与「更新服务器 CLI」，方便获取新模型。这个版本也包含 v0.17.0 之后已合入的 Hanori 界面、任务交付与可靠性改进。

## 新功能

- 执行设置读取 Lody Agent 实际上报的模型与推理强度，支持分页和手动刷新，保留尚未保存的草稿。旧 CLI 未提供能力列表时仍使用兼容列表；YAML 中配置的模型列表继续优先。
- 使用新版 lody-bridge 时，可查看服务器 CLI 版本并更新到官方 npm 最新稳定版。已有任务或活跃会话时拒绝更新；安装失败保留旧版，新 daemon 启动失败时尝试回滚。更新后的 CLI 保存在 `.lody` 持久卷中。
- Dev Harness 支持 `/task`：在项目话题中提交不需要 GitHub issue 的任务，交付 PR 或直接返回结果，并可回复继续会话。
- Dev Harness 支持 `/release`：生成版本计划，经确认并核对目标提交后打 tag，再跟踪发布工作流与 GitHub Release。Lody 回合结束会通过签名回调及时通知 Harness，轮询继续作为备用路径。

## 改进与修复

- Hanori 品牌与统一的工作区界面已应用到面板，改善桌面和手机上的导航、密度、设置表单与登录体验；当前 Bot、RSS 和摘要的空状态与错误状态更加明确。
- 记忆页与生成素材库优先展示内容，摘要历史行间距更均衡，并改善键盘阅读与窄屏布局。
- CLI 连接错误会显示在执行设置中；没有推理强度选项的模型不会继承不兼容的强度参数。更新请求等待时间覆盖安装、daemon 重启与失败回滚。
- 修复 Harness 并发状态写入可能覆盖取消结果的问题，并使请求与事件时间戳及队列排序保持一致；全为数字的短请求 ID 也可用于 `/cancel` 和 `/retry`。
- 记忆新增、编辑与合并统一更新向量，降低内容与检索向量不一致的风险。
- OCR、摘要与记忆整理去除不适用于部分新推理模型的固定采样参数，并为推理留出输出空间；达到输出上限的对话压缩不会覆盖原始历史。
- AI 提示词与工具能力保持一致，统一 AI 设置的边界与编码规则，并改善 GitHub 限流、权限错误和未安装 App 时的错误处理。
- Dokploy Compose 保留域名标签，明确 Traefik 与 app 的共享网络，避免更新后路由丢失。

## 使用与升级

- 无新增数据库迁移。使用 CLI 更新按钮前，需要同步更新 app 与 lody-bridge 镜像；默认 bridge CLI 从 0.100.0 升至 0.103.0，继续保留 `.lody` 持久卷。
- CLI 更新按钮仅限 owner，且只更新服务器上的 Lody CLI。MacBook 等远程执行机的 CLI 和自定义 Agent 需要在对应机器更新；远程 Agent 能力也须在所在机器或 Lody 中刷新。
- 更新期间 Harness 暂停派发新任务。处于运行、初始化或等待权限确认的服务器会话会阻止更新；安装源固定为官方 npm 稳定版。
- 旧 bridge 或本地 CLI 模式下更新按钮不可用。出现「Lody 暂不可达」时，应先检查连接、共享密钥与 daemon；更新 CLI 不会修复认证或网络配置。
- 原先无工具的 `creative_writer`、`code_helper`、`translator` 子代理统一为 `general`；旧名称的单独覆盖不再生效。
- 沿用既有配置与升级备份流程。GitHub Release 发布和运行实例更新是两个独立步骤，静态文档需在下一次构建部署后更新。
