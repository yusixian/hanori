# v0.18.0 — 更新 Lody CLI 与模型列表

Dev Harness 执行设置新增「刷新 Agent 和模型」与「更新服务器 CLI」，并合入 v0.17.0 以来的界面、任务交付与稳定性改进。

## 新功能

- **模型列表刷新**：执行设置直接读取 Lody Agent 上报的模型与推理强度，支持分页、手动刷新并保留未保存草稿。旧版 CLI 回退兼容列表；YAML 中的模型配置仍优先。
- **服务器 CLI 更新**：新版 lody-bridge 支持查看当前 CLI 版本并更新到官方 npm 最新稳定版。有活跃任务或会话时拒绝更新；安装失败保留旧版，新 daemon 启动失败尝试回滚。更新后的 CLI 存放在 `.lody` 持久卷中。
- **Dev Harness `/task`**：在项目话题直接提交无需 GitHub issue 的任务，交付 PR 或返回结果，支持回复续接会话。
- **Dev Harness `/release`**：生成版本计划，经人工确认并核对目标提交后打 tag，跟踪发布工作流与 GitHub Release。Lody 回合结束通过签名回调即时通知，轮询作为兜底。

## 改进与修复

- 面板全面切换至 Hanori 品牌与统一工作区布局，优化桌面/移动端导航、表单密度、登录体验及 Bot/RSS/摘要的空状态与错误提示。
- 记忆页与素材库优先展示内容，调整摘要历史行距，改善键盘阅读与窄屏排版。
- 执行设置直接显示 CLI 连接错误；无推理强度选项的模型不再继承不兼容参数；CLI 更新超时已覆盖安装、重启与回滚。
- 修复 Harness 并发写入可能覆盖取消状态的问题，统一事件时间戳与队列排序；`/cancel` 和 `/retry` 支持纯数字短 ID。
- 记忆新增、编辑与合并统一刷新向量，避免正文与向量脱节。
- OCR、摘要和记忆整理移除不适配部分推理模型的固定采样参数并预留推理空间；触及输出上限的对话压缩不再覆盖原始历史。
- 对齐 AI 提示词与工具能力，统一 AI 设置边界与编码规则，改进 GitHub 限流、权限不足及未安装 App 时的报错。
- Dokploy Compose 保留域名标签并显式声明 Traefik 与 app 的共享网络，防止更新后路由丢失。

## 使用与升级

- 无新增数据库迁移。使用 CLI 更新按钮需同步升级 app 与 lody-bridge 镜像；默认 bridge CLI 升至 0.103.0，保留原 `.lody` 持久卷。
- CLI 更新仅限 owner，且只作用于服务器本机；远程执行机（如 MacBook）的 CLI 和自定义 Agent 需在对应机器自行更新与刷新。
- 更新期间 Harness 暂停派发新任务，存在运行中、初始化或等待权限确认的会话时会阻止更新；旧 bridge 或本地 CLI 模式下按钮不可用。「Lody 暂不可达」需先排查连接、密钥或 daemon，更新 CLI 无法修复配置错误。
- 原 `creative_writer`、`code_helper`、`translator` 子代理合并为 `general`，旧名称的单独覆盖不再生效。
- 沿用既有备份与升级流程。GitHub Release 发布与站点更新相互独立，静态文档需随下次构建部署更新。

## 验证边界

已通过仓库 lint、格式、类型、i18n、单元测试、面板与公开文档浏览器测试及全包构建。CLI 安装、并发拒绝与回滚仅通过隔离测试验证，未在真实服务器执行 CLI 更新，也未在真实 Telegram WebView 验收。
