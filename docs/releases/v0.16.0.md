# v0.16.0 — 在 Telegram 话题里交付小改动

Dev Harness 上线：在专用话题群里一个项目一个话题，发 `/bug` 就能让你 Mac 上的 agent 修好并开 PR，在卡片上查看风险、合并或打回。话题里也可以直接和助手讨论需求、查询 issue 与任务进度，并一键执行它建议的命令。

## 新功能

- **按项目自动建话题**。在面板 **Dev Harness** 页或 Mini App 选择仓库和机器即可接入项目，保存后立即生效；仓库没有 `.cos/harness.yml` 时按脚本和工程文件推断验证命令。`/status` 查看项目、机器和额度。
- **`/bug` 小改动闭环**。`/bug 描述` 会建 GitHub issue，经 lody-bridge 在选定机器上开 Lody 会话；agent 自己验证、交叉审查后开 PR。随 `/bug` 附的截图以签名链接写进 issue，agent 可以直接下载。
- **PR 卡片**。卡片随 GitHub 事件实时更新，显示 T0–T3 风险、CI、合同检查、上下文用量和本周额度。T0–T2 可在卡片上合并；T3 只能在 GitHub 网页上合并。「打回」会请你写原因并发给会话返工，「取消」二次确认后停止会话（PR 保持打开），需要处理时可「重新排队」。
- **日常命令**。`/list` 列出进行中的请求（General 里按项目汇总），`/cancel` 与 `/retry` 取消或重新排队，只有一个进行中的请求时无需参数。
- **话题助手**。在项目话题里直接发文字：助手只读查询本项目的 issue、PR、最近提交、默认分支上的文档和 harness 任务，帮你总结需求、梳理下一步，并给出带按钮的命令建议，点一下即按同一路径执行。每个话题的对话独立，命令与卡片不进入对话；`/new` 清空本话题的对话。助手使用该 Bot 在面板里配置的 AI，未配置 AI 时仍显示命令提示。
- **执行设置**。面板可设置 worker 会话使用的 Lody agent、模型和推理强度，可全局设置也可按项目覆盖。

## 改进

- 有 CI 的仓库在 push 后等待检查登记，登记前不能合并；没有 CI 的仓库等待 60 秒后可合并。
- 每 3 分钟从 GitHub 补齐可能遗漏的 webhook 事件；会话停下却没有交付 PR 时，几分钟内提醒你并附最后一条回复摘录；因机器离线排队超过 15 分钟时在 General 话题提醒一次。
- 添加项目时，状态未知的机器默认勾选，避免保存出没有机器的项目。

## 使用与升级

- 升级前备份数据库，并按常规流程应用 0054–0057 四个数据库迁移。它们只新增 Dev Harness 的表和列，不修改其他 Bot 的数据。
- Dev Harness 默认不启用；只有在 `harness.yaml` 绑定的 Bot 和话题群里生效，其他 Bot 与群聊的行为不变。部署与配置见 [Dev Harness](/docs/integrations/dev-harness)。
- 截图链接需要 `BETTER_AUTH_URL` 能从公网访问；链接不过期，能看到 issue 的人都能打开。
- 助手的调用计入该 Bot 的模型用量统计（来源为 `harness_assistant`），不占群聊 AI 的额度。

## 验证边界

单元测试、浏览器测试、类型检查和格式检查已通过；Dev Harness 的建话题、`/bug` 到 PR、卡片合并已在测试群用沙盒仓库端到端跑通。话题助手、新的卡片按钮、截图链接、CI 登记等待和 webhook 补偿尚未在真实 Telegram、真实模型与真实 GitHub 上验收。
