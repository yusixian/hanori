# v0.16.0 — 在 Telegram 话题里交付小改动

Dev Harness 上线：在专用话题群按项目自动建话题，发 `/bug` 即可让本机 Mac 上的 agent 修复并开 PR，在卡片上直接看风险、合并或打回，也能在话题里和助手讨论需求、查进度并一键执行命令。

## 新功能

- **按项目自动建话题**：在面板 **Dev Harness** 页或 Mini App 选好仓库和机器保存即生效；仓库无 `.cos/harness.yml` 时按脚本与工程文件推断验证命令。`/status` 查看项目、机器与额度。
- **`/bug` 闭环**：`/bug 描述` 自动建 GitHub issue 并经 lody-bridge 在目标机器起 Lody 会话，agent 自行验证、交叉审查后提 PR；随命令附带的截图以签名链接写入 issue 供 agent 下载。
- **PR 卡片**：随 GitHub 事件实时更新，展示 T0–T3 风险、CI、合同检查、上下文用量与本周额度。T0–T2 支持卡片直接合并，T3 须在 GitHub 网页合并；支持「打回」（填写原因发回会话返工）、「取消」（二次确认停会话，保留 PR）与「重新排队」。
- **日常命令**：`/list` 列出进行中请求（General 按项目汇总）；`/cancel`、`/retry` 取消或重排，仅有一个进行中请求时可省去参数。
- **话题助手**：在项目话题直发文字即可只读查询本项目 issue、PR、近期提交、默认分支文档和 harness 任务，梳理下一步并给出带按钮的命令建议（点击按同一路径执行）。各话题上下文独立，命令与卡片不入上下文，`/new` 清空当前话题对话；复用 Bot 在面板配置的 AI，未配置时回退显示命令提示。
- **执行设置**：面板可配置 worker 会话的 Lody agent、模型与推理强度，支持全局默认与按项目覆盖。

## 改进

- 有 CI 的仓库在 push 后等检查登记完成才允许合并；无 CI 的仓库等 60 秒后可合并。
- 每 3 分钟从 GitHub 补拉可能遗漏的 webhook 事件；会话停下未交 PR 时几分钟内提醒并附末条回复摘录；因机器离线排队超 15 分钟在 General 提醒一次。
- 新增项目时默认勾选状态未知的机器，避免保存出无可用机器的项目。

## 使用与升级

- 升级前请备份数据库并执行 `0054`–`0057` 迁移；仅新增 Dev Harness 表与列，不影响其他 Bot 数据。
- Dev Harness 默认关闭，仅在 `harness.yaml` 绑定的 Bot 与话题群生效；配置见 [Dev Harness](/docs/integrations/dev-harness)。
- 截图签名链接要求 `BETTER_AUTH_URL` 公网可达；链接不过期，能查看该 issue 的人均可访问。
- 助手调用计入该 Bot 用量统计（来源 `harness_assistant`），不占群聊 AI 额度。

## 验证边界

单测、浏览器测试、类型与格式检查已通过；建话题、`/bug` 到 PR、卡片合并已在测试群与沙盒仓库端到端跑通。话题助手、新卡片按钮、截图链接、CI 登记等待与 webhook 补偿尚未在真实 Telegram、真实模型和真实 GitHub 上验收。
