# v0.11.0 — 按 Chat ID 或参与者查找会话

对话页新增搜索，可以通过完整 Chat ID 或历史参与者名称，在当前 Bot 的全部会话中查找旧记录，无需逐页翻找。

## 功能与改进

- 输入完整 Chat ID 或名称片段，按 Enter 或点击搜索；Chat ID 精确匹配，名称忽略大小写，特殊字符按字面处理。负数群聊 ID 同样可查。
- 搜索覆盖全部会话，结果按最近活动分页。命中某位参与者时，仍展示完整会话的消息数量、参与者、最近消息和摘要。
- 已提交的条件与输入草稿分别显示；切换条件回到第一页，清除搜索恢复全部会话。搜索无结果、读取失败和陈旧数据分别提示。
- 搜索切换继续隔离旧请求。删除结果待核对时，即使已切换搜索，也会读取原删除范围与当前页面；核对不会自动重复删除。
- 全部删除明确标为 **清空此 Bot 的全部对话**，确认框说明会包含当前搜索结果之外的记录。搜索不会缩小该操作的范围。

## 使用与升级

名称来自保存的聊天记录，可能是历史显示名或当时保存的 username；搜索不会另行查询群名称、当前 username 或人物档案，也不检索消息正文。数字查询也会同时匹配名称片段。搜索条件只保存在当前页面，刷新网页或切换 Bot 后重置。

从 v0.10.1 升级无需数据库迁移或新增配置。列表 API 新增可选 `search` 参数，去除两端空白后最长100字符；原有不带搜索参数的分页调用继续可用。权限、数据保留规则与消息页的系统/工具可见性开关保持不变。

GitHub Release 与文档构建不代表生产实例已经部署。

## 验证范围

候选版本的会话搜索与恢复 Chromium 回归、17项列表路由测试、45项既有会话存储回归，以及3项隔离 PostgreSQL 17 查询测试通过。真实 SQL 覆盖25条匹配记录的分页/总数、完整会话统计、Bot 隔离、字面特殊字符及大整数边界；这3项测试需要显式测试数据库配置，默认 CI 跳过，不能把普通 CI 当作数据库实测。

相关 Panel/Server 类型、格式、lint、双语校验和 Panel 生产构建通过。生产构建在1440×900、390×844两档使用全部模拟 API 验证搜索、分页、空态、失败重试、清除和全 Bot 删除范围，中英文布局没有页面异常或横向溢出。公共文档类型、构建和14项匿名访问、搜索、深链、版本页与指南检查通过。

这些是本地、临时数据库与合成数据验证，不代表生产规模下的搜索性能、真实 Telegram 会话或物理手机行为；没有读取真实会话、执行生产删除或发送消息。CI、合入和发布结果以对应提交的 GitHub 检查及 Release 为准。
