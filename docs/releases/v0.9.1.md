# v0.9.1 — 档案与记忆管理错误恢复

人物档案和记忆管理现在能明确区分加载失败、提交失败和刷新失败，减少误判与重复操作。

## 修复内容

- 列表加载失败时显示错误和重试入口；相同条件下刷新失败时保留已加载内容并标明状态，不再把请求失败显示为没有记录。
- 创建、编辑、删除同时校验 HTTP 状态和业务结果。结果无法确认时保留草稿或列表，提供刷新入口；只有收到成功结果才关闭表单。
- 提交期间禁用相关输入和操作，防止重复点击及后返回的请求清除后来输入的草稿。
- 为列表请求增加过期响应保护，切换 Bot、搜索或筛选后不再被旧结果覆盖；切换 Bot 时重置当前页面的表单状态。
- 分别提示操作成功和随后刷新失败，避免把刷新失败误认为写入失败。

使用方式见文档站「隐私、历史与记忆」中的「在面板维护档案与记忆」。

## 升级说明

- 从 v0.9.0 升级无需数据库迁移或新增配置。
- 记录 API、权限和个人化规则不变；未增加新的搜索范围或筛选能力。
- 草稿仅保留在当前页面，未增加离开页面确认或持久草稿。网络中断后请先检查列表再决定是否重提。
- GitHub Release 与文档构建不代表生产实例已部署。

## 验证范围

验证人物档案与记忆的加载、创建、编辑、删除失败与恢复，提交锁定、过期请求、切换 Bot，以及桌面和手机界面。浏览器使用模拟 API 数据，未修改生产档案或记忆。同步检查文档构建、匿名访问、深链、搜索和版本页；未发送真实 Telegram 消息。
