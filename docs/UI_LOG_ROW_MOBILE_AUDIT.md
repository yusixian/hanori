# 手机日志记录可读性验收

## 基线与范围

基线为 v0.14.1 发布后 main `86f0547ccfce9caa3f78004b800e1b96b42aa4d8`。旧巡检的 `.acceptance/plan.md` 将全局日志手机消息列过窄列为 P2；本轮用当前生产构建和合成日志重新复现，作为实施依据。记录在 390px 宽度时，消息区域为 225.4 CSS px，样本消息占 5 行；同一记录在 1440px 宽度时为 903.4 CSS px、2 行。390px 截图可见级别徽标和展开图标与正文并列，压缩了正文。截图及尺寸记录在 `.acceptance/ui-efficiency/log-row-layout-baseline/`。这是本地合成浏览器证据，不代表真实日志内容分布或用户设备耗时。

全局日志和 Bot 工作区日志共用 `LogEntryRow`，因此本轮同时核对两处记录的窄屏可读性，不改变日志读取或清理接口。

## 验收条件

- 390px 手机上级别与展开入口仍一眼可见，消息与时间、关联信息使用下方卡片宽度；同一样本消息的可用宽度和行数较基线改善，长 URL 不造成横向溢出。
- 桌面布局保持易扫读；全局和 Bot 日志均使用同一改进，中文与英文、历史与实时记录的布局一致。
- 记录仍可用鼠标、触摸和键盘展开；完整元数据与复制 JSON 保持可用。列表加载、空态、错误与重试不因行布局调整回归。
- 使用合成 API 和本地浏览器验证，不读取或删除真实日志。

## 实现与本地验收

- 共享 `LogEntryRow` 在小于 640px 时将级别徽标和展开入口放在第一行，消息和元数据改用下方整行；桌面继续横排。独立 Sol 审查发现初版 Grid 默认拉伸徽标，390px 生产预览截图也复现了该 P2；已增加 `justify-self-start` 与实际宽度回归断言。独立窄复核在最终树重跑聚焦 Chromium 4/4，未发现新的可复现 P1/P2。
- 最终生产构建配合合成 API，在全局日志 390px 中文/英文、Bot 日志 390px 中文、全局日志 1440px 中文验证相同记录。390px 消息宽度从 225.4 增至 324 CSS px，样本从 5 行降到 4 行；1440px 仍为 903.4 CSS px、2 行。四档页面均无脚本错误或横向溢出，键盘 Enter 可展开详情并看到复制 JSON 操作。截图和几何结果位于 `.acceptance/ui-efficiency/log-row-layout-final/`，基线位于同级 `log-row-layout-baseline/`。完整元数据与复制行为另由共享组件浏览器测试覆盖。
- Panel 类型、局部 lint/format 和生产构建通过。公开指南与 v0.14.2 版本页已同步，Docs 类型、构建及定向桌面/手机浏览器 4/4 通过；文案没有新增翻译 key。

CI 和 GitHub Release 待完成。本轮未运行需要 Docker 的完整隔离验收器；浏览器证据来自本地生产构建与合成 API，没有读取或删除生产日志，也未在用户 Android 设备上验证。
