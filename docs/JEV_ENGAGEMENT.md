# JEV 群聊接话

JEV 独立判断是否应该回复以及参与方式，回复仍使用当前选定的模型。现有手动模型选择不受影响。

## 上线顺序

1. 先在开发数据库验证新增 engagement samples migration，再按部署流程应用迁移。
2. 管理面板 → Bot AI 设置 → 回复行为 → 智能群聊接话：配置 TypeSafe 官方 API key，保持运行模式关闭。密钥加密保存，留空保存保留原密钥。
3. 在一个允许发送上下文到该服务的群中单独覆盖为“观察”。观察模式同样调用 JEV 并计费，但不改变原有回答规则。
4. 检查样本的建议、实际准入、耗时、错误及分类费用；人工标记应该接话、应该沉默或不确定。既抽查不一致样本，也抽查双方均沉默的样本。
5. 根据中文聊天数据调整风格、偏好、冷却和阈值。标记数据不足时不要宣称准确率达标。确认延迟和费用可接受后由管理员将该群设为“启用”。不自动切换。
6. 回滚时将单独配置的群设为关闭，或取消群覆盖并将 Bot 默认模式设为关闭后保存。原有触发规则继续生效；无需删除数据表或撤销迁移。

## 行为

- 自然群友：延续对话、相关话题和适当接梗；克制助手：优先明确求助；筛选现有插话：仅过滤原有关键词/随机候选。
- 启用模式下，AI 已启用且权限/隐私允许的私聊、明确 @、回复 Bot 不受 JEV 的沉默判断控制。旧 @/回复开关仅在关闭和观察模式按原语义生效。
- 关键词默认交给 JEV，可开启“命中触发词时直接回答”。
- 主动插话受冷却约束；Bot 在配置的续聊窗口内发言后的高置信度延续对话可跳过插话冷却。窗口默认 120 秒，可设 0–300 秒，0 关闭该豁免。两者仍受用量和并发限制。
- 启用模式真正准入后，参与方式会作为仅限本轮的表达指导交给当前回复模型：直接招呼按问题需要认真回应，延续对话直接接上并避免重复背景，主动加入保持简洁克制且可自然接梗。该指导不替换既有角色提示，不限制工具，也不会写入对话历史或记忆；观察、关闭和故障回退路径不使用它。
- 判断超时或响应无效回到原有触发逻辑，不即时重试；原有随机触发因此仍可能回答。
- 转发正文需要可核对的用户来源；无法核对原作者的转发不进入 JEV 判断。明确 @／回复仍走原有回答流程。
- 文本上下文有时间、条数和字符上限，不另行调用视觉模型识别附件。JEV 不能据此声称看到了图片。
- 建议回答和实际准入并不等于成功发送；演员模型或 Telegram 仍可能失败。

## 评价与费用

### 经常沉默时怎么排查

先分清三个结果：是否回复的模型判断、经过置信度阈值后的策略结果、最终是否准入回复。原因是 `below_threshold` 表示被本地阈值拦下，不是请求失败。

判断在同一次请求中拆为两个独立 Choice：

- `reply`：回答或沉默，置信度用于决定是否准入。
- `participation`：直接招呼、延续对话或主动加入，只决定参与方式。直接招呼和延续对话分别使用 `addressedConfidenceThreshold` 和 `continueConfidenceThreshold`，缺失时均为 0.8；明确应回复的直接招呼不受主动插话冷却限制，延续对话仍需在 `continuationWindowSeconds` 窗口内有 Bot 发言。参与方式不确定时按主动加入处理，仍受冷却限制；不会仅因参与方式不确定而将回复判断改成沉默。

TypeSafe 的 `confidence` 是选项概率分布的确定性，不是回复概率或准确率；本地验证并使用服务端返回值，不定义或反推公式。新样本分别显示回复二选一和参与方式三选一的概率分布，另存原始参与 `choice/confidence`，便于解释降级路由；历史样本缺失参与置信度时明确显示未记录。历史三选一样本仍按原格式展示，不能把两套分布混成一个概率总和。参考：[官方 Confidence 说明](https://docs.typesafe.ai/confidence)。

JEV 的补充偏好只用于回复准入判断，不会自动读取主回复模型的 system/group behavioral prompt，也不改变参与关系问题。面板偏好示例需要显式应用及保存；不会随升级写入任何群。调参步骤和各字段范围见[公开群聊行为指南](../packages/docs/content/docs/guides/group-behavior.mdx)。

配置值不会自动改变，但同一个阈值现在作用于“回答／沉默”的二选一判断，和旧版三选一不等价。建议先在测试群观察新版本样本，结合误插话与漏回复逐步调整，而不是沿用历史置信度推断效果。配置版本包含判断提示版本，以区分优化前后的样本。

判断请求提供 Bot 的 Telegram 名称、用户名和当前群生效的触发词，帮助识别称呼。提示区分直接招呼、隐式追问、旁观聊天和结束交流；自然群友允许简短接梗，克制助手仍偏向明确求助。触发词只是语境线索，不自动覆盖沉默判断。若希望命中触发词就直接回复，需另外开启“命中触发词时直接回答”。

仍然遵守隐私过滤、明确 @／回复的直达流程、主动接话冷却及失败后的原规则回退。两个问题共享一次请求和原有总超时预算；额外问题可能增加输入 Token，费用仍按实际 usage 记录，不能假定成本和延迟不变。

样本保存实际模型版本和策略快照。评估按两阶段/历史三分类分组，并支持精确配置版本筛选；默认全部配置下仍须注意版本混合，不能把历史标注率称作新配置效果。`confidence` 是模型分布的确定程度，不是实测准确率。用户偏好不能覆盖权限和隐私规则。

“忘记我”同时清除含该用户直接或派生内容的样本正文，异步判断返回后也不能重新写回已删除的内容。上下文正文默认 7 天后清除；保留不含消息正文的决策和统计字段。管理接口按 Bot 权限隔离，Mini App 不新增样本查看入口。

分类费用按服务商返回的输入 Token 及当次固化价格估算。官方模型页 <https://docs.typesafe.ai/models> 在方案核实时列出 `jev-1.13.0` 输入 $0.042/百万 Token、输出免费。实际账单以服务商为准，缺少 usage 的请求显示未知成本。

当前聊天模型用量表没有价格契约，因此演员费用和净节省不能据此计算，应显示未计价，另在现有用量页查看实际 Token。新增或减少了多少回复不能直接换算成节省金额。后续价格能力由 #28 统一实现。

## 验证边界

自动测试使用 mock JEV 响应，不消耗真实额度。浏览器测试验证配置和样本操作，不证明真实 Telegram 或 TypeSafe 的延迟、中文判断质量和账单。正式启用前需要上述指定群 shadow 观察。
