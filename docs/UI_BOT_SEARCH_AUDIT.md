# Bot 列表名称查找验收

## 基线与目标

基线 v0.12.1 的 Bot 列表每页显示 12 个。使用 125 个合成 Bot 的桌面和手机生产预览复现：已知末项 Bot 125 的名称，仍需打开页码并跳到第 11 页。截图位于 `.acceptance/ui-efficiency/bot-search-current-baseline/`。

本轮目标是在完整列表中按名称查找，保留现有排序、分页、Bot 详情和启停入口。验收条件是跨页目标可直接找到、筛选总数准确、多页匹配可翻页，清空恢复全部列表；搜索无结果与没有 Bot、加载失败分别处理，桌面/手机和键盘可用。

## 实现与证据

- `GET /api/bots` 新增可选 `search`，先按 Bot 名称不区分大小写筛选，再按既有创建时间和 ID 顺序分页；计数应用相同筛选。输入长度上限 100，去除首尾空白，SQL 通配符转义后做字面匹配。
- 面板输入框将名称条件交给 Refine DataProvider 与服务端；输入停顿 300 毫秒或按 Enter 后提交，清空搜索回到第一页。查询切换时不显示上一个词的卡片；匹配数、无结果提示与重试沿用列表的读取状态。结果变化会向辅助技术播报。
- 路由 SQL 代理测试核对列表与计数条件、分页参数、空白搜索及长度限制；Panel 浏览器测试 8 项通过，覆盖输入、过滤器、分页重置、无结果、清空、输入法和焦点；DataProvider 浏览器测试 2 项通过，核对查询参数。
- 生产构建预览在 1440×900 和 390×844 使用 125 个合成 Bot 的只读 API 夹具。每档 14 个请求，均通过末项搜索、切换搜索时隐藏旧卡片、多页匹配、特殊字符无结果、清空恢复、后台刷新失败和重试；无页面异常或横向溢出。截图与请求记录位于 `.acceptance/ui-efficiency/bot-search-final/`。
- 相关 Panel/Server 类型检查、路由测试 3 项、i18n 2433 keys、改动文件 lint/format 和 Panel 生产构建通过。公开文档类型/构建通过；文档浏览器首次 17/18 项通过，手机搜索弹窗测试未出现弹窗，单项复跑通过，疑似 hydration 时序问题。新版本目录遗漏由定向测试发现并补齐，v0.13.0 页面桌面与手机 2/2 项通过。
- Lody 独立代码审查指出旧查询数据、翻页焦点和输入法确认 3 项 P2；视觉体验复核指出辅助技术缺少异步结果提示 1 项 P2。均已针对性修改并通过聚焦浏览器复验；两条原会话复核确认 4 项关闭，未发现新的重要问题。视觉会话未运行屏幕阅读器，结论不包括实际语音效果。

## 限制

浏览器检查中的账号和 Bot 均为合成数据，不证明生产数据库规模性能或真实 Bot 生命周期行为。路由测试检查生成的 SQL，未在真实 PostgreSQL 中执行。本地完整隔离验收器依赖 Docker，当前 Docker daemon 不可用且固定的 3100 端口属于其他项目；此处采用聚焦浏览器验收，不把它报告为完整隔离验收器通过。未执行生产部署或真实消息发送。
