## v0.10.1 错误恢复

实现基线为 main `acd7b4a41396820c65e202eefe6d1359172e4274`，从 v0.10.0 tag 到该提交只有交付/基线文档更新。先复现相邻流程，再修改面板；服务端接口和权限未变。

### 详情与删除基线补证

同一旧版生产构建、全部 API 合成夹具，1440×900 和 390×844 均复现：

- 消息 GET HTTP500 显示“没有消息”，摘要 GET HTTP500 显示“没有压缩摘要”；两者均没有 alert 或重试入口。
- 消息 DELETE HTTP500 后保留记录但没有界面反馈；摘要 DELETE HTTP200、ok:false 后同样静默。
- 四种场景均无页面运行异常。Sol 保存并查看了8张截图，主代理抽查了两档的读/写错误截图。证据 `conversation-detail-baseline/verify.mjs`、`evidence.json` 和图片，均在 `.acceptance/ui-efficiency/`。

### 实现边界

- 三种分页读取按查询隔离结果，校验 HTTP 与 ok，Abort/token 拦截旧响应；同查询刷新失败保留旧数据并显示陈旧提示。新查询失败不借用旧行、空态或总数，并可重试/返回第一页。
- Bot 切换重建页面。读取错误不会锁住会话导航；删除/核对进行中用同步 ref 和 disabled 控制防止重复与中途切换。
- 单消息、摘要、整会话/全部删除均区分未知结果和已确认成功。未知结果保留记录；确认成功后刷新失败明确提示已删除，核对只发送 GET。
- 删除失败后可继续浏览。保存原删除目标的查询范围；在另一会话/页/标签点击核对时，会额外读取原范围而不覆盖当前页面，必要读取全部成功才允许继续删除。普通刷新和 Retry 在此状态也执行核对。
- 409 活动摘要冲突保留内容并提示；刷新后服务端 active 状态继续禁用删除。最后一页失效回有效页；原两次点击/整会话确认框和焦点行为保留。
- 不提供列表搜索或全历史角色过滤；系统/工具开关仍只过滤当前消息页。

## v0.11.0 会话搜索

实现基线 main `c78fa2b3a2fe7421b63d4523f5744a7ecfcebb57`，产品为 v0.10.1。范围限于在当前 Bot 的全部会话中按完整 Chat ID 或历史参与者名称查找；消息角色开关保持当前页语义。

### 实现与边界

- 服务端 `search` 去除两端空白、最长100字符；名称大小写不敏感，`%`、`_`、反斜杠按字面。纯十进制安全整数也精确匹配 Chat ID，负数可用；数字查询同时匹配名称，超范围数字不转换为舍入后的 ID。
- 查询先确定匹配 chatId，再在当前 Bot 范围聚合完整会话；结果与总数使用相同范围。最近活动降序、chatId 升序作为相同时间的稳定顺序，摘要与最后消息继续保留完整数据。
- 页面分开保留草稿和已提交条件；显式提交、切换条件重置第一页/详情，清除恢复全部会话。空结果与失败区分，旧请求不能覆盖新搜索。条件只保留在当前页面，不写 URL。
- 删除/核对进行中禁用搜索；未知删除结果后可以换搜索，原列表恢复 key 包含搜索条件和页码，核对原范围及当前视图成功才解锁。全 Bot 删除标签与确认框说明包含搜索之外的会话，不改变 DELETE 范围。
- 中文手机实际截图发现长名称把私聊标签挤成两行，限制类型标签不收缩、不换行，让名称截断。
