# JEV 群聊接话与 AI 日志：实现说明及配置指南

关联任务：#66：插话逻辑接入轻量决策模型

本文记录 #73 合入时的实现。后续接话优化将单次三选一拆为“是否回复”和“参与方式”两个独立判断；现行语义及验证方式见 [JEV 群聊接话](JEV_ENGAGEMENT.md)。历史样本仍保留原来的概率与置信度含义。

## 1. 这次解决什么问题

原有群聊回复主要由触发词、明确 @、回复 Bot 和随机规则决定。这次增加一个轻量的“门卫”：先判断当前消息是否值得参与，再让现有聊天模型生成回复。

- **门卫 JEV**：选择继续对话、主动加入或保持沉默。
- **回复模型**：继续使用当前配置的模型、提示词和工具，负责实际回答。

JEV 不接管回复模型选择，也不实施 #28 的自动模型路由、演员模型故障切换或统一定价能力。使用 TypeSafe 官方接口，模型固定为 `jev-1.13.0`。

这次还完善了整个 AI 回复链路的日志，包括普通回复、事件续聊、工具调用和 JEV 决策，不只覆盖 JEV。

## 2. 每条群消息都会判断吗

当群配置为“观察”或“启用”，并选择“自然群友”或“克制助手”时，符合权限和隐私规则的普通群文本消息都会参与判断，**不要求命中触发词或 @ Bot**。

“每条判断”不等于“每条回复”。大多数普通闲聊可以被判断为沉默。

以下情况需要区分：

- 命令及不支持的消息不会作为普通群文本交给 JEV。
- 明确 @ 或回复 Bot 不需要通过 JEV 判断；启用模式下直接进入原有回答流程，仍遵守权限、隐私、停止状态、用量与并发限制。
- 私聊不经过这个群聊门卫。
- “筛选现有插话”只判断旧关键词／随机规则已经选中的候选消息。
- 冷却限制主动接话频率，**不限制 JEV 判断次数**。
- 观察模式会调用 JEV，因此也会产生分类费用。

## 3. 运行模式与接话风格

这两组设置彼此独立。

### 运行模式

| 模式 | 是否调用 JEV                       | 是否改变实际接话行为               |
| ---- | ---------------------------------- | ---------------------------------- |
| 关闭 | 否                                 | 否，继续使用旧触发规则             |
| 观察 | 是，对符合条件的消息判断并记录样本 | 否，实际回复仍按旧规则             |
| 启用 | 是，对符合条件的消息判断           | 是，判断结果控制普通群消息是否接话 |

默认是“关闭”，部署后不会自行启用，也不会自动开始消耗 JEV 额度。

### 接话风格

| 风格         | 适用行为                                             |
| ------------ | ---------------------------------------------------- |
| 自然群友     | 可以延续对话、参与相关话题、适当接梗，像群友一样参与 |
| 克制助手     | 更偏向明确求助和有帮助的信息，普通闲聊尽量不打扰     |
| 筛选现有插话 | 仅过滤旧关键词／随机规则选中的消息，不扩大候选范围   |

可以先用“观察＋自然群友”看它想在哪里插话，再把同一个群切到“启用”。

## 4. 命中触发词后还能沉默吗

**可以。** 启用 JEV 时，“命中触发词时直接回答”默认关闭。这种情况下，即使命中关键词，JEV 仍可判断应该沉默。

| 配置               | 命中触发词后的行为                  |
| ------------------ | ----------------------------------- |
| 启用，直接回答关闭 | 由 JEV 判断，可以沉默               |
| 启用，直接回答开启 | 跳过 JEV 语义判断，直接进入回答流程 |
| 观察或关闭         | 实际回复仍按旧触发词规则            |

如果 JEV 超时、返回无效结果或发生请求错误，会回退到旧触发逻辑，不即时重试。因此，命中触发词的消息在判断故障时仍可能获得回复。这是故障回退，不代表 JEV 选择了回答；旧随机候选也只计算一次。

## 5. JEV 能看到多少上下文

JEV 使用有界的近期群聊窗口，不会把全部历史消息都发送给服务商。

- 限定当前群、当前话题，不混入其他群或私聊。
- 默认最多 20 条，最近 5 分钟，合计最多 6,000 字符。
- 优先保留当前消息；被回复的消息必须满足时间和条数限制，再补最近的上下文。
- 使用文本和媒体附带文字，不额外识别图片、语音或读取附件全文。
- 包括可用的近期 Bot 回复，帮助判断是否延续对话。
- 请求中的参与者使用匿名标记，不发送内部隐私归属 ID。

这与实际回复模型使用的对话历史、记忆和工具上下文是两个独立范围，后者仍使用原有配置。

## 6. 隐私设置如何生效

| 用户设置                  | 对 JEV 的影响                                                                               |
| ------------------------- | ------------------------------------------------------------------------------------------- |
| `/privacy normal`         | 可参与判断；JEV 本身只使用当前群、当前话题的近期上下文                                      |
| `/privacy isolated`       | 可参与当前群判断，不带其他聊天的个人化历史                                                  |
| `/privacy off`            | 普通发言不触发 JEV，也会从其他人的 JEV 判断上下文中排除；主动 @ 或回复 Bot 仍可进入回答流程 |
| `/privacy forget confirm` | 清除相关接话样本正文并切到 off，旧缓冲和迟到结果不能重新带回已作废内容                      |

观察模式同样遵守隐私规则。发送前会重新检查上下文贡献者，保存样本前也会复核。已知转发来源会检查原作者；无法核实用户来源的转发正文不进入 JEV。

**现有隐私语义不是“off 后所有群消息绝不存储、绝不供任何 AI 使用”。** 项目原有规则仍允许群消息进入共享群历史或群总结。JEV 过滤与共享群历史是独立路径；“忘记我”不会撤回 Telegram 群消息，也不能从已经发布的共享群摘要中选择性删除内容。本次没有把隐私系统改成全局禁止存储。

样本正文默认 7 天后清除，保留不含消息正文的决策和统计字段。普通 JEV 决策日志不额外复制样本上下文。

## 7. 面板怎么配置

### 第一步：配置 Bot 默认值和密钥

进入 **Bot → AI 设置 → 回复行为 → 智能群聊接话**。

填写 **TypeSafe API Key**，Bot 默认模式先保持“关闭”，然后保存。密钥加密保存，之后留空表示保留现有密钥；不需要替换原有聊天模型。

建议起步配置：

| 项目                 | 数值                                     |
| -------------------- | ---------------------------------------- |
| 接话风格             | 自然群友                                 |
| 最低置信度           | 0.8                                      |
| 主动插话冷却         | 60 秒                                    |
| 上下文消息数         | 20                                       |
| 判断超时             | 1000 毫秒                                |
| 命中触发词时直接回答 | 关闭                                     |
| 补充接话偏好         | 可填写，例如“可以接动漫梗，争论时少插话” |

超时预算覆盖准备判断上下文与 JEV 请求。置信度表示模型的确定程度，不是实测准确率。

### 第二步：只给一个群开启观察

进入 **AI 设置 → 权限与群组 → 群组覆盖设置**，展开一个已经允许使用 AI 的测试群。

勾选 **“单独配置这个群的接话策略”**，模式改为“观察”，保存。未单独配置的群继承 Bot 默认值；群级单独设置优先。

### 第三步：查看并标注样本

在 **回复行为 → 接话决策样本** 中查看：

- 模型建议和实际准入结果，两者分开展示。
- 判断原因、错误类型、模型／配置版本、延迟、Token 和分类费用。
- 策略快照及尚未过期的上下文。
- 人工标注“应该接话”“应该沉默”或“不确定”。

既检查误插话，也抽查双方均沉默的消息，避免只看到明显错误而漏掉该回复的消息。“已准入”不等于最终成功发送，回复模型或 Telegram 仍可能失败，需要结合日志排查。

### 第四步：启用和回退

判断质量与延迟可接受后，把该群模式切到“启用”并保存，不会自动切换。

主动插话受冷却限制。Bot 最近 2 分钟内发言后的高置信度延续对话可跳过主动插话冷却，但仍遵守用量和并发限制。

停用时，将已单独配置的群改为“关闭”，或取消群级单独设置以恢复继承。**仅关闭 Bot 默认模式，不会覆盖群里的单独启用设置。** 关闭后回到原有触发规则，不需要删表或撤销迁移。

## 8. 费用怎么看

面板按服务商返回的输入 Token 及样本记录的价格快照估算分类费用。方案核实时，官方模型页列出 `jev-1.13.0` 输入 $0.042／百万 Token，输出免费；实际费用以服务商账单为准。

官方参考：<https://docs.typesafe.ai/models>

缺少 usage 的样本显示未知费用；已知费用只是可计算部分，不伪装成完整总额。目前回复模型的用量记录缺少统一价格契约，所以演员费用与净节省显示未计价，不能把少回复几次直接等同于节省多少钱。

## 9. AI 日志与失败排查

日志增强覆盖普通 AI 回复、事件续聊、工具及 JEV。

- 同一次执行共用 `correlationId`，并记录可用的 chatId、userId、messageId、模型和供应商信息。
- 请求和回复保存有界诊断正文；工具保存参数、结果、调用 ID 与耗时。
- 失败保存原始 Error 类型、message、stack、cause，以及上游提供的状态码和响应体。
- SDK 后续只给出 `No output generated` 时，首次 provider 错误仍单独保留，不让通用错误覆盖根因。
- JEV 记录建议、实际准入、概率、置信度、原因、版本、延迟和费用。

进入 **Bot 日志**或**全局日志**：

1. 找到错误记录，展开“完整详情”。
2. 堆栈按真实换行展示，上游 JSON 响应体可直接阅读。
3. 将记录中的关联 ID 填入筛选，查看同一次执行的请求、工具、回复和失败。
4. 级别选“全部”，才能同时看到 debug 级请求和工具详情。
5. 阅读长详情时可暂停实时更新，也可复制原始已保存记录的 JSON。

搜索同时匹配日志消息和 metadata；支持群聊 ID 与关联 ID 精确筛选。实时与历史记录合并去重。

普通诊断内容保留，密钥、Authorization、token、Cookie 等仍脱敏，Token 数量不会被当作凭据隐藏。二进制以摘要表示，超大内容或结构会明确标注截断。旧日志未采集或已截断的字段无法补回；隐私 off 的普通回复不记录输入和回复正文。

数据库保存 debug 日志，终端输出仍受现有 Pino 日志级别控制。保留期限遵循现有普通／错误日志清理配置。

## 10. 合并部署后会发生什么

合并不等于部署，本次没有新增自动部署流程。

新版服务启动会按已有流程执行数据库迁移，新增 `engagement_samples` 表。JEV 默认关闭，旧回复行为继续生效；日志增强随新版生效，不需要单独开关。上线前仍应遵循现有备份和部署流程。

已完成本地定向单元测试、浏览器测试、类型检查、构建、桌面／手机页面验收，以及隔离 PostgreSQL 的迁移、隐私和日志查询验证。真实 JEV、Telegram、中文接话质量、生产延迟与实际账单尚未实测，需通过指定群的观察模式验证。

本说明记录实现与使用语义，具体 PR、CI 和合并结果以此 issue 的后续链接与状态为准。
