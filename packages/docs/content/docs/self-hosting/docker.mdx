## 使用 GHCR 预构建镜像

从已发布镜像对应的 Git 标签下载仓库根目录的 `docker-compose.prebuilt.yml` 和 `.env.example`，放在同一目录。参考第 1 节准备环境，按第 2 节的方式 A 创建 `.env`，将 `NSFW_API_URL` 设为 `http://nsfw-api:3000`。

将 `HANORI_IMAGE_TAG` 设为完整版本标签（含 `v`），也可使用默认值 `latest`。使用其他镜像仓库时，将 `HANORI_IMAGE_REGISTRY` 设为含命名空间的地址，默认值为 `ghcr.io/yusixian`。

```bash
docker compose -f docker-compose.prebuilt.yml up -d
curl -fsS http://127.0.0.1:43100/api/health/ready
```

宿主机默认端口为 `43100`，可通过 `PORT` 修改。升级前[备份数据](/docs/self-hosting/backup-upgrade)，下载目标版本的 Compose 文件，保留原项目目录和密钥，并更新已固定的 `HANORI_IMAGE_TAG`。

```bash
docker compose -f docker-compose.prebuilt.yml pull
docker compose -f docker-compose.prebuilt.yml up -d
```

启动后确认 `/api/health/ready` 返回的 `version` 与目标提交的完整 Git SHA 一致。

## 从源码构建

获取对应版本的源码后，在仓库根目录执行以下步骤。

## 1. 准备环境

确认本机已安装 Docker Engine、Docker Compose 插件、OpenSSL 和 Git（如用 Git 拉取），并准备好持久化数据库 volume、备份目录和 HTTPS 反向代理。

用下面的命令为 `DB_PASSWORD`、`BETTER_AUTH_SECRET`、`ENCRYPTION_KEY`、`PANEL_PASSWORD` 及 `MINI_APP_SESSION_SECRET` 分别生成独立随机密钥：

```bash
openssl rand -hex 32
```

## 2. 创建环境文件

二选一：

**方式 A：手动复制模板**

```bash
cp .env.example .env
chmod 600 .env
```

**方式 B：用 Node.js 22.19+ 自动生成 Docker 专用 `.env`**（无需先装依赖，拒绝覆盖已有 `.env`）：

```bash
node scripts/init-env.mjs --email owner@example.com --url https://bot.example.com
```

替换为自己的邮箱和 HTTPS origin（本机试用可填 `http://localhost:43100`）。脚本会自动生成上述密钥并以 `0600` 权限写入（终端不回显，首次登录密码见 `.env` 中的 `PANEL_PASSWORD`），`DATABASE_URL` 留空以防误连开发库。

无论哪种方式，所有环境都必须填非空 `ENCRYPTION_KEY`；升级或恢复已有数据时保留原值，切勿将 `.env` 提交进版本库或镜像。

## 3. 启动最小服务

```bash
docker compose -p cos-bot-prod -f docker-compose.yml -f docker-compose.direct.yml up -d --build
```

切勿执行 `docker compose down -v`（会删库卷）。更新前先看[备份与升级](/docs/self-hosting/backup-upgrade)。

- **内置 yt-dlp**：app 镜像已内置 Python 与固定版本 yt-dlp 供 Bilibili 字幕及视频流提取，无需额外 profile。源码运行时可在独立虚拟环境执行 `pip install -r infrastructure/bilibili-ytdlp/requirements.txt` 并将 `bin` 加入 `PATH`（缺 yt-dlp 时退回现有 B 站接口）；子进程不接触 Cookie、ASR API Key 或应用秘密，音视频合并仍需 `media` 服务。
- **Traefik / Dokploy 反向代理**：显式设置 `TRAEFIK_DOCKER_NETWORK` 为代理与 `app` 共享的 Docker 网络（升级前沿用原容器的 `traefik.docker.network` 标签值），并从代理容器验证 `/api/health/ready` 可达。使用 Dokploy Domains 管理域名时，保留 Compose 中 `labels` 的列表写法。
- **Dokploy 隔离设置**：务必关闭 **Advanced → Enable Isolated Deployment**，否则平台会给所有服务强加网络，与 `media-worker` 的 `network_mode: none` 冲突并破坏编码 worker 隔离。使用默认 Domains 时设 `TRAEFIK_DOCKER_NETWORK=dokploy-network`，只给 `app` 绑域名；部署前点 **Preview Compose** 确认 `app` 有 `default`、`harness-bridge` 及代理网络、`media-worker` 无 `networks`、编码 worker 仅连 `coding-sandbox`。

### 减少更新时的数据库中断

Dokploy 的 Advanced Command 保持默认 `up -d --build --remove-orphans`，如曾加过 `--force-recreate` 请删掉。普通应用更新只会重建有变动的容器，数据库保持运行。

完整 `up` 会重跑 `db-backup`，`app` 仍等待本次备份成功后启动（勿用 `--no-deps` 绕过）。首次调整后核对数据库容器 ID 与启动时间未变、`db-backup` 退出码正常，再看 ready 状态。可先在本机跑 `pnpm deployment:smoke` 验证。注意应用更新仍有重启窗口，数据库镜像或配置变更仍应走维护窗口，基础镜像建议锁 digest。

## 4. 验证启动

```bash
docker compose -p cos-bot-prod -f docker-compose.yml -f docker-compose.direct.yml ps
docker compose -p cos-bot-prod -f docker-compose.yml -f docker-compose.direct.yml logs --tail=200 app
curl -fsS http://127.0.0.1:43100/api/health
curl -fsS http://127.0.0.1:43100/api/health/ready
```

`43100` 来自 `.env.example` 的 `PORT`（未设时 `docker-compose.direct.yml` 默认映射宿主机 `9600`，容器内始终为 `3000`）。`/api/health` 仅检查进程存活，`/api/health/ready` 会校验迁移、认证、Bot 和必需集成均已就绪。

## 5. 首次登录和启用选项

访问 `BETTER_AUTH_URL`，用 owner 邮箱和 `PANEL_PASSWORD` 登录并在 Settings 修改密码，随后从 `.env` 删除 `PANEL_PASSWORD`，再在面板配置 Bot Token、Provider、备份和可选集成。

启用编码 worker：同时配置 `COMPOSE_PROFILES=coding` 与 `CODING_WORKER_SECRET` 后重建，确认 worker 与出口代理健康且未暴露公网。

### 可选音频转换服务

Bilibili 音频转录需启用 `media` profile（默认关闭）。用 `openssl rand -hex 32` 生成独立的 `MEDIA_WORKER_SECRET`（32~256 个 ASCII 字母、数字或 `/+_=-`，不含空格换行，勿复用其他密钥），写入 `.env` 并设 `COMPOSE_PROFILES=media`（与编码 worker 共用时为 `coding,media`），重建后检查 `media-worker` 状态。

- Compose 已默认配置 `MEDIA_WORKER_SOCKET=/media-control/worker.sock`、`MEDIA_JOB_DIR=/media-jobs`、`MEDIA_WORKER_GID=1000`，通过本机 Unix socket 与临时卷通信（源码部署需自行对齐路径与权限，不能换成公网地址）；`mediajobs`、`mediacontrol` 仅为临时存储。
- 转换容器完全断网、只读根文件系统并限额，只做音频格式转换，不接触 Cookie、ASR API Key 或数据库凭据（下载和上传 ASR 由 app 执行）。此隔离仅针对音频转换，不是第三方插件沙箱。
- Cookie、ASR 地址、密钥和预算在面板按 Bot 配置，并需在[插件管理](/docs/guides/plugins#可选-bilibili-音频转录)显式启用转录。容器健康检查只覆盖本地转换服务，不代表外部链路已通。

## 6. 后续更新

更新前备份数据库，确认工作区干净，拉取已核验版本并重建 app，随后复查 `/api/health/ready`、面板登录、Bot `/status`、一次 AI 私聊与关键集成。

## 隔离部署检查

正式部署前可用本机 Docker 跑一遍抛弃式验收：

```bash
node scripts/smoke-deployment.mjs --check
node scripts/smoke-deployment.mjs
```

- `--check` 仅校验两套隔离 Compose 配置，不依赖 Docker daemon。
- 完整检查会构建当前源码，在两套随机项目名的隔离环境中依次验证迁移、无 Bot Token 启动、owner 登录、匿名文档、合成 Bot 凭据加密、重建持久化、跨环境备份恢复，以及错密钥解密失败与缺密钥拒启（恢复时关闭 bootstrap 密码补建）。
- 加 `--previous-sha <上一支持版本的完整 Git SHA>` 可导出旧提交并验证跨版本升级及迁移不可变性（源码归档无 `.git`，跑基础检查需加 `--sha <完整 Git SHA>`）。
- 脚本不读已有 `.env`，拒绝远程 Docker、外部 volume、宿主机挂载和端口发布；结束后自动清理容器、卷、网络和镜像（失败也会尽量清理并打印残留清理命令）。切勿把生产 `.env` 或备份交给它。

## 正常关停

退出期间先后收到 `SIGINT` 和 `SIGTERM` 时共用同一次关停流程。单步清理失败会记录脱敏错误并以非零码退出，其余依赖步骤仍会继续收尾；强制强杀不具备等待保证。

数据库关闭前，以下后台任务会停止接新并等待在途工作完成：

| 后台任务                                      | 正常关停时等待的工作                                                                  |
| --------------------------------------------- | ------------------------------------------------------------------------------------- |
| 日志、Bot Run、非活跃记忆、互动样本上下文清理 | 已开始的清理查询及诊断收尾                                                            |
| 记忆整合                                      | 当前 Bot 的模型调用后处理（用量结算、记忆写入、向量更新、租约释放）；跳过未开始的 Bot |
| 图片保留清理                                  | 已开始的文件删除、标记写入及并行查询                                                  |
| 用量维护                                      | 已启动的明细清理和过期预留回收事务                                                    |

记忆整合不会撤销已发出的模型请求。提醒调度在关停后停止新投递和重试：未发出的提醒退回可恢复状态，已开始投递的只记录结果、不自动重发。Harness 调度器的等待范围见[调度器关停](/docs/integrations/dev-harness#调度器关停)。

## 用量维护

运行时每日清理用量明细、每分钟回收过期预留。单条预留回收失败不阻断同批其他记录，批次结束汇总报错并留待下一周期重试；启动检查遇回收失败会直接报错。

## 语录渲染服务

默认 Compose 的 `quote-worker` 为 `/q` 和 AI 语录工具提供离线渲染：512 MiB 内存上限、无网络、内置中文与 Emoji 字体，通过 `QUOTE_WORKER_SOCKET` 接收 app 已校验的文字和图片（素材下载仍由 app 完成）。

升级时须同步 Compose 配置并同时重建 app 与 `quote-worker`。启动后检查 `/api/health/ready` 中的完整 Git SHA 及 `quoteRenderer: true`；该服务离线不影响整体 ready 状态，但为 `false` 或本地未配 socket 时语录命令会提示不可用且 AI 不注册语录工具。
