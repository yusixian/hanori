复制 `.env.example` 为 `.env`（或在部署平台配置 Secret），将占位符替换为实际值。

## 数据库和服务

| 变量                 | 用途                                                                                                                    |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`       | PostgreSQL 连接字符串                                                                                                   |
| `DB_PASSWORD`        | Docker Compose 数据库密码                                                                                               |
| `PORT`               | 容器内固定监听 `3000`；`docker-compose.direct.yml` 下作为宿主机映射端口（`.env.example` 填 `43100`，未设时默认 `9600`） |
| `BACKUP_DIR`         | 本地备份目录，未设时用应用默认目录                                                                                      |
| `BETTER_AUTH_URL`    | 生产公开 HTTPS origin，不带末尾 `/` 或路径                                                                              |
| `BETTER_AUTH_SECRET` | Better Auth 会话与加密密钥（至少 32 位随机值）；更换会使已有会话失效                                                    |
| `AUTH_OWNER_EMAIL`   | 首次启动创建 owner 的邮箱                                                                                               |
| `PANEL_PASSWORD`     | 首次 bootstrap 密码；登录改密后删除                                                                                     |

## 本地 Mini App 域名

在根目录 `.env` 中设置 `COS_TOOL_BOT_MINI_APP_ORIGIN=https://mini.example.com`（替换为指向本机 tunnel 的 HTTPS 域名），`pnpm dev:mini-app` 会自动读取。临时切换域名可在命令前覆写该变量；已有环境升级时填入原域名即可沿用 Telegram 里的入口配置。

## Bot 和加密

| 变量                                        | 用途                                                      |
| ------------------------------------------- | --------------------------------------------------------- |
| `BOT_TOKEN`                                 | 首次迁移或开发用的 Telegram Token；长期配置存于面板数据库 |
| `ADMIN_CHAT_IDS`                            | 首次迁移写入的管理员 Telegram ID 数组                     |
| `ENCRYPTION_KEY`                            | 加密 Bot Token、API Key 等敏感配置的稳定密钥              |
| `MINI_APP_SESSION_SECRET`                   | Mini App 独立会话签名密钥                                 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | 可选 Google OAuth，须成对配置                             |

- **必填 `ENCRYPTION_KEY`**：含本地开发在内的所有环境都必须设置非空值，缺失会拒绝启动。应用按原值派生密钥，首尾空格也计入其中。
  - 全新 Docker 实例：按[Docker 部署](/docs/self-hosting/docker)运行 `pnpm setup:env --email owner@example.com --url https://bot.example.com` 生成；
  - 本地开发：复制 `.env.example` 后用 `openssl rand -hex 32` 生成；
  - 已有数据的实例：严禁替换密钥，旧版未显式配置时先按[备份与升级](/docs/self-hosting/backup-upgrade)离线恢复原值。
- `MINI_APP_SESSION_SECRET` 应独立于 `BETTER_AUTH_SECRET` 与 `BOT_TOKEN`，轮换会使现有 Mini App 会话失效。

## AI、媒体和清理

| 变量                                                              | 用途                                                                                                                        |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `EMBEDDING_DIMENSIONS`                                            | Embedding 维度，默认 `3072`；修改后须同步迁移并重建索引                                                                     |
| `NSFW_API_URL`                                                    | 图片安全检测服务基址（支持 `POST /classify` multipart `image`）；未配置或失败时保守加罩。Docker 默认 `http://nsfw-api:3000` |
| `LOG_RETENTION_DAYS`                                              | 普通日志保留天数                                                                                                            |
| `LOG_RETENTION_DAYS_ERROR`                                        | 错误日志保留天数                                                                                                            |
| `LOG_CLEANUP_INTERVAL_HOURS`                                      | 日志清理间隔                                                                                                                |
| `GENERATION_RETENTION_DAYS`                                       | 生图记录与文件默认保留天数                                                                                                  |
| `PIXAI_MCP_URL` / `OPENAI_IMAGE_MCP_URL` / `GEMINI_IMAGE_MCP_URL` | 旧部署兼容用的图片 MCP 完整地址；一旦在面板保存图片 MCP 平台地址即停用                                                      |

### Embedding 校验与历史回填

- 每次 Embedding 响应会校验条数与维度：带索引的结果按索引还原顺序，省略索引则按返回顺序处理；缺项、重复、混用索引或维度不符会按失败降级，不写脏向量。
- 运行历史向量回填脚本时，按本轮开始时的 ID 上界逐 Bot 扫描，每条记录最多试一次，每批请求 5 分钟超时（不含数据库耗时与脚本总时长）。失败项留空供后续重跑，期间发生编辑、已被填充或已删除的记录自动跳过，补充向量不改动编辑版本与更新时间。终端会分别汇总尝试、保存、失败和跳过数；执行前先评估供应商计费。

## NSFW 图片检测

`NSFW_API_URL` 填基础地址（不带 `/classify`）。所有生图供应商共用同一流程，按 `porn + hentai + sexy` 对比阈值（默认 `0.5`）。相册逐张检测，任一张超阈值则整组加罩；调用方主动要求的 spoiler 会保留。

- **本地 Node.js 开发**：先启检测容器 `docker compose -p cos-bot-dev -f docker-compose.dev.yml up -d nsfw-api`，在根目录 `.env` 设 `NSFW_API_URL=http://localhost:43106`（改了 `NSFW_API_PORT` 需同步调整）并重启。
- **Docker Compose / Dokploy**：设为 `NSFW_API_URL=http://nsfw-api:3000`。若从 `.env.example` 复制过配置，务必覆盖其中的 `localhost:43106`（容器内 `localhost` 指向应用自身）。修改后需重建容器或重新部署生效。
- **排查全部被遮罩**：先检查实际运行环境里的变量与连通性；未配置、超时、HTTP 错误或响应无效都会触发保守加罩（不等同于判定为 NSFW）。测试接口：
  ```bash
  curl --fail --max-time 15 -F 'image=@/path/to/test.jpg' http://localhost:43106/classify
  ```
  正常返回包含 `porn`、`sexy`、`hentai`、`neutral`、`drawing` 五个 `0~1` 数值的 JSON。日志出现 `NSFW classification failed; applying spoiler` 表示检测失败，可对照生成记录中的 `failed` / `unavailable` 与 `checked` 排查。

## 公共音频转录账户

ASR 账户在面板 **设置 → 公共音频转录** 统一保存，所有 Bot 共用（不读聊天模型 API Key，无需新增环境变量），凭据用 `ENCRYPTION_KEY` 加密。每家供应商一个账户，默认停用。

- 预置优先级：腾讯云常规录音识别 `16k_zh` → 阿里云百炼北京 `paraformer-v2` → Groq Whisper → OpenAI 兼容服务。腾讯云填 `SecretId` / `SecretKey` 和地域，其余填 API Key；缺凭据或单价未知的账户不会执行（Groq 零单价需管理员确认属免费计划）。
- 公共设置管单价、单任务上限、每日/每月预算及月分钟数（默认预算 CNY `1 / 3 / 10`，USD `0.2 / 0.6 / 2`，分币种统计，免费余额未知按全价预留）；Bot 插件独立管启用、外传开关、Bot 限额和导出。
- 用百炼或向腾讯云传超 5 MiB 音频时，`BETTER_AUTH_URL` 须为供应商可达的公网 HTTPS origin（用于签发有时限的签名音频链接，勿公开分享）；腾讯云短音频直传及 Groq / OpenAI 兼容不依赖此项。仍需按[可选音频转换服务](/docs/self-hosting/docker#可选音频转换服务)启用转换容器。
- 旧版各 Bot 的 OpenAI ASR 配置不会自动迁移，升级后需在公共设置重填凭据，并复核提示清单变化的 Bilibili 插件。每次转录仍需发起管理员在原聊天确认，详见[插件管理](/docs/guides/plugins#可选-bilibili-音频转录)。

## GitHub 与编码 Worker

GitHub App 五项变量必须全填或全留空：`GITHUB_APP_ID`、`GITHUB_APP_CLIENT_ID`、`GITHUB_APP_CLIENT_SECRET`、`GITHUB_APP_PRIVATE_KEY`（单行带字面 `\n` 的 PEM）、`GITHUB_APP_SLUG`。

启用隔离编码 worker 时同时设置：

```dotenv
COMPOSE_PROFILES=coding
CODING_WORKER_SECRET=生成的独立随机值
```

可选的 `CODING_WORKER_URL`、`CODING_WORKER_SOCKET`、`CODING_JOB_DIR`、`CODING_WORKSPACES_DIR`、`CODING_GIT_DIR` 用于指定内部连接与持久化目录。

## 生图供应商与默认预设

以 owner 身份在任意 Bot 的 **用量与生图治理 → 图片 MCP 平台** 填入平台域名（如 `mcp.example.com`）保存，即对所有 Bot 生效（无需改环境变量或重启）。更换平台会清受影响授权，清空保存会关闭三个连接。完整配置与旧变量兼容见[图片 MCP](/docs/integrations/mcp#图片-mcp)。

- 动漫插画默认 PixAI，通用图新配置默认 GPT；每个用途可单独改默认供应商及允许的预设。明确指定「用 GPT / Gemini」仅覆盖当次请求，未连接或停用的供应商不自动回退。
- 已有通用图配置沿用旧路径直到 owner 显式切换；已建任务绑定原供应商和地址，改默认供应商不影响旧任务。
- GPT / Gemini 当前支持文生图，不支持参考图、负面提示词和 seed；请求发往供应商后取消能力有限，以平台任务状态为准。

## 轮换规则

认证 secret、Mini App secret、加密 key、Bot Token、GitHub 私钥、MCP/API Key 和邮箱密码的失效面各不相同。每次只轮换一类，做好备份后再操作，重启后逐项检查健康接口、面板登录、Bot 连通与对应集成。

## 公开文档的搜索与分享

`DOCS_SITE_URL` 是可选的**构建时变量**，填文档对外发布的 HTTPS origin（如 `https://bot.example.com`，不带 `/docs`、查询参数或凭据）。

Compose 部署写入 `.env` 后重建：

```bash
# .env
DOCS_SITE_URL=https://bot.example.com
```

```bash
docker compose -p cos-bot-prod -f docker-compose.yml -f docker-compose.direct.yml up -d --build
```

独立构建文档：

```bash
DOCS_SITE_URL=https://bot.example.com pnpm build:docs
```

- 设置后会为每页生成 `canonical`、Open Graph / Twitter 元信息及 `/docs/sitemap.xml`，生产 `/robots.txt` 指向该 sitemap；换域名须重新构建。
- 留空时文档仍可匿名阅读，但不输出 canonical / 绝对分享链接，sitemap 为空。管理面板与登录页始终标记 `noindex, nofollow`（实际访问控制仍由服务端认证保证）。
- 部署后检查页面源码里的 `canonical`、`og:image` 及 `/robots.txt`、`/docs/sitemap.xml` 匿名可访问性。
