Hanori 是 pnpm monorepo 应用，包含 Telegram Bot、Hono 服务端、React 管理面板、PostgreSQL 数据库和可选的编码 worker。生产环境由 Hono 统一托管 API 和静态面板，应用启动时自动执行数据库迁移。

从 GitHub 获取对应版本的源码和部署模板。使用受访问控制的镜像时，先为部署服务器配置镜像仓库认证。

## 组件关系

| 组件            | 职责                                                 |
| --------------- | ---------------------------------------------------- |
| `server`        | 认证、API、BotPool 生命周期、外部集成和静态资源服务  |
| `bot`           | grammY Telegram 运行时、命令、AI 流程和工具          |
| `panel`         | React 管理面板与 Telegram Mini App 前端              |
| `database`      | PostgreSQL 客户端、Drizzle schema 与有序迁移         |
| `shared`        | 共享类型、命令目录、配置契约与工具函数               |
| `coding-worker` | 可选的隔离 Pi 编码执行器，不持有数据库或 GitHub 凭据 |

## 前置条件

开发环境需要 Node.js `22.19.0+`、pnpm `10.5.2`、PostgreSQL 17（生产镜像带 pgvector）和 Docker Compose。生产环境额外需要：

- 稳定的 HTTPS 公开 origin；
- 持久化数据库 volume 和备份目录；
- `BETTER_AUTH_SECRET`、`ENCRYPTION_KEY` 等独立随机密钥；
- Telegram Bot Token 与至少一个可用 AI Provider（启用 AI 时）；
- 按需准备 Google OAuth、GitHub App、MCP、PixAI、NSFW 检测服务或 coding worker。

## 部署路径

- **本地开发**：启动开发数据库、配好 `.env`，运行 `pnpm dev` 同时起 server 和 panel。
- **预构建镜像**：[一键安装脚本](#一键安装)下载 Compose 文件并生成私有 `.env`。也可按 [Docker 部署](/docs/self-hosting/docker)手动准备环境或从源码构建。
- **容器平台编排**：按 [Coolify](https://github.com/yusixian/hanori/tree/main/examples/deploy/coolify)、[1Panel](https://github.com/yusixian/hanori/tree/main/examples/deploy/1panel) 或 [Dokploy](https://github.com/yusixian/hanori/tree/main/examples/deploy/dokploy) 的部署示例接入 HTTPS，保留健康检查、持久化卷与备份依赖。

切勿把开发库、真实 Bot Token 或生产 `.env` 交给浏览器测试和验收脚本；Mini App 权限流程需在真实 Telegram WebView 中验证。

## 一键安装

准备 POSIX Shell、curl 和 OpenSSL。启动服务需要 Docker Engine 和 Compose 插件。以下命令使用预构建镜像，将安装文件放入 `./hanori`：

```sh
curl -fsSL https://raw.githubusercontent.com/yusixian/hanori/main/scripts/install.sh -o install.sh &&
  sh install.sh --email owner@example.com --url https://bot.example.com
cd hanori
docker compose -f docker-compose.prebuilt.yml up -d
curl -fsS http://127.0.0.1:43100/api/health/ready
```

将邮箱和 HTTPS origin 换成自己的值。本机试用可省略 `--url`，默认使用 `http://localhost:43100`；默认端口在宿主机发布，试用时请用本机防火墙限制外部访问。用 `--dir` 指定其他目录，或同时设置 `--ref` 和 `--tag` 来使用与预构建镜像对应的 Git 标签及镜像标签；从已有源码目录安装可用 `--source-dir`。

脚本以 `0600` 权限生成 `.env`，保留已有文件。首次登录密码见本机 `.env` 中的 `PANEL_PASSWORD`，登录并修改密码后可从环境中移除。

## 推荐顺序

1. 按[配置说明](/docs/self-hosting/configuration)生成并保存密钥。
2. 按[Docker 部署](/docs/self-hosting/docker)启动最小服务（server、panel 与数据库）。
3. 按 [HTTPS 反向代理](/docs/self-hosting/reverse-proxy)接入公开域名，检查 `/api/health` 与 `/api/health/ready`，通过后再登录面板。
4. 添加 Bot、Provider 和备份策略，最后启用可选集成。
5. 后续升级与迁移按[备份与升级](/docs/self-hosting/backup-upgrade)执行。
