更新说明按产品版本组织，适合在升级前快速确认行为变化、迁移要求和已知验证范围。版本页由仓库中的发布说明生成，避免 GitHub Release 和文档站出现两份长期漂移的正文。

## 首个发布基线

- [v0.2.0：群聊参与控制、管理体验与 AI 诊断](/docs/changelog/v0.2.0)

后续版本会出现在文档导航的“版本更新说明”列表中。发布版本与当前实例部署的版本可能不同。

每个版本页会说明新功能、可靠性修复、升级注意事项和验证范围。CI 通过、浏览器测试通过、部署成功和真实 Telegram/外部服务联调是不同的证据层，不能互相替代。

## 如何阅读版本说明

1. 先确认实例当前版本和构建 commit。
2. 阅读“升级说明”，检查数据库迁移、默认值、密钥和外部集成变化。
3. 阅读“验证范围”，区分自动化检查和仍需在实例中确认的行为。
4. 备份后再升级，并在升级完成后检查[健康接口](/docs/reference)。

如果你的实例维护者提供了更具体的部署窗口、回滚步骤或功能开关，以维护者的通知为准。
