title: Telegram 链接读取
description: 配置独立 MCP Platform Reader 的用户账号、白名单与 OAuth，验证读取与撤销权限流程。

Telegram 私有消息链接无法当普通网页抓取。Telegram Reader 运行在独立的 **MCP Platform** 中，通过用户账号和 MTProto 读取白名单内的频道与超级群组，再以只读 MCP 工具对外提供。不需要新建 BotFather bot 或单独部署 userbot。

> 截至 2026-09-21：Reader 的 Admin 配置和 MCP 服务已就绪，但 Hanori 通用 MCP 连接尚未支持其所需的 OAuth 登录与刷新流程（图片 MCP 的专用 OAuth 也不能复用）。完成本文配置后，原 Bot 仍不能直接自动读取群里的链接。

## 面板分工

| 入口                           | 负责内容                                               |
| ------------------------------ | ------------------------------------------------------ |
| MCP Platform Admin `/telegram` | Telegram 应用凭据、用户登录、聊天白名单和链接测试      |
| MCP Platform `/mcp/telegram`   | 受 OAuth 保护的只读 MCP 工具端点                       |
| Hanori 面板 MCP Servers        | Bot 侧工具连接与范围；目前不能仅填 Reader URL 完成授权 |

下文以 `https://mcp.example.com` 指代你的 MCP Platform 公网 HTTPS 地址，操作时替换为实际域名。

## 1. 确认 Reader 服务可用

开始登录前先确认：

1. 目标版本已在部署平台完成发布。
2. MCP Platform 的 `/health/ready` 返回 `200`，Admin `/diagnostics` 显示数据库、迁移和凭据正常。
3. Owner 账号可打开 `/telegram` 页面。
4. 服务器网络能直连 Telegram MTProto（能打开普通网页不代表 MTProto 可达）。

首次引入 Reader 包含 `0013_wonderful_grim_reaper.sql` 迁移。MCP Platform 在 `MIGRATION_MODE=run` 时自动执行，`skip` 时需在部署前手动完成（这是 MCP Platform 的迁移，不是 Hanori 的）。

升级前备份数据库并妥善保管凭据加密主密钥。账号会话加密存在数据库中，无需挂载额外 SQLite session 文件或新增 Telegram 环境变量。首次实测请保持单实例运行，勿在未验证并发锁拓扑前多副本共用同一 session。

## 2. 申请 Telegram 应用凭据

按 [Telegram 官方说明](https://core.telegram.org/api/obtaining_api_id)：

1. 准备一个已注册且正常的 Telegram 用户账号。
2. 登录 [my.telegram.org](https://my.telegram.org)，进入 **API development tools**。
3. 创建应用，获取 **API ID** 和 **API hash**。

API ID/hash 标识应用，用户账号决定可见聊天，MCP Platform Owner 账号负责后台管理，三者都不是 Bot Token。建议用仅加入少量目标聊天的专用账号控制范围（仍须遵守 Telegram 规则）；切勿把 API hash、验证码、两步验证密码或 session 写入聊天、截图或文档。

## 3. 在 MCP Platform Admin 登录

打开 `https://mcp.example.com/telegram`：

1. 在「Reader 配置」填入 API ID 和 API hash，保持 Reader 关闭，点「保存配置」。
2. 在「连接 Telegram 账号」输入带区号的手机号，点「发送登录验证码」。
3. 填入最新验证码；若开启两步验证，继续输入密码完成登录。
4. 确认状态变为「已就绪」且账号正确。

登录挑战有效期 10 分钟，重发冷却 60 秒，连续错误上限 5 次；过期后需重新发起。已保存的 API hash 不回显（留空即保留，更换凭据需同时填 API ID 和 hash），验证码和密码不落库。

## 4. 加入目标并保存白名单

1. 用**刚登录 Reader 的用户账号**在 Telegram 客户端加入目标频道或超级群组。
2. 回到 Admin 点「加载群组和频道」。
3. 先只勾选一个自己创建的测试目标。
4. 确认内容使用权限后勾选声明，打开「启用 Telegram Reader」。
5. 点「保存配置」后再测链接。

原 Bot 在群里不代表该用户账号有权限；公开频道也必须先发现并加入白名单。列表最多拉取最近 100 个对话，自动过滤私聊、旧式普通群、已退出目标和开启内容保护的聊天。

### 合规边界

[Telegram API 条款](https://core.telegram.org/api/terms)和[内容授权条款](https://telegram.org/tos/content-licensing)限制将内容交由 AI 处理，公开内容并非默认获准，例外需相关用户明确、知情且持续同意。Admin 的勾选框只是操作确认，不能替代真实授权；未核实权限前保持关闭，勿将第三方聊天接入 AI。

## 5. 在 Admin 测试首次读取

在自己的测试超级群发一条无敏感信息的消息，复制链接贴进「测试 Telegram 链接」，将「前后各读取的消息数」设为 `0`，点「通过 Telegram 读取」核对正文。

支持规范 HTTPS `t.me` 链接：公开频道用户名链接、`/s/` 预览链接、`/c/` 私有消息链接及带 topic ID 的链接。不支持邀请链接、评论查询参数或其他域名。

| 验收动作                     | 预期结果                   |
| ---------------------------- | -------------------------- |
| 读取白名单内测试消息         | 正文与原消息一致           |
| 读取已获准频道链接           | 返回有限条数的近期消息     |
| 读取非白名单目标             | 明确拒绝，不降级抓取网页   |
| 关闭 Reader 保存后再读       | 拒绝读取                   |
| 重新启用保存并重启应用后再读 | 登录和白名单保留，读取正常 |
| 退出并撤销 Reader 设备       | 再次使用需重新登录         |

频道单次最多读 20 条，单消息前后文最多各 5 条（邻近采样，不保证补齐讨论串，超长会截断）。不支持下载附件、读私聊、发删消息、持续监听或全历史搜索。真号验证只走上述小范围手工流程，勿用开发集成测试直连生产库。

## 6. 用 OAuth MCP 客户端验证

选用支持远程 MCP OAuth 的客户端，按以下参数配置：

| 字段       | 值                                     |
| ---------- | -------------------------------------- |
| MCP 地址   | `https://mcp.example.com/mcp/telegram` |
| 传输       | Streamable HTTP                        |
| 认证       | OAuth                                  |
| 读取 scope | `mcp:telegram:read`                    |

Admin「复制端点」仅复制路径 `/mcp/telegram`，外部客户端需补全域名。按客户端引导以 MCP Platform Owner 身份完成授权；长期使用需客户端支持令牌刷新（访问令牌有效期 10 分钟，勿手抄进静态 headers）。

授权后先调 `list_allowed_telegram_chats` 确认只返回白名单目标，再调 `read_telegram_link` 读同一条测试消息（`url` 填链接，`context` 设 `0`；读频道设较小的 `limit`）。API hash 及已有 PixAI/通知 token 不能复用到此端点；未授权返回 `401` 属正常保护。

Reader 返回文本属于不可信外部内容，客户端应防止提示词注入并限制结果传播范围。

## 7. 接入原 Bot 尚缺的工作

Hanori 通用 MCP 管理器目前只支持静态 headers，图片 MCP 的专用 OAuth 不通用。要打通 **原 Bot → Reader**，后续还需补齐：

- Owner 授权入口、回调校验、加密令牌存储与自动刷新；
- Bot / 用户 / 聊天粒度的访问控制，防止群成员借 Owner 账号跨权读取其他私有群；
- 识别 `t.me` 链接后优先走 Reader，被拒时明确说明而不绕过；
- 令牌过期、应用重启、撤销授权及 Bot 端到端实测。

通用工具治理见 [MCP 服务器](/docs/integrations/mcp)。

## 维护与排错

正常运行无需反复登录。增删目标时先在官方客户端入群/退群，再刷新白名单并保存。

| 现象                                | 排查顺序                                                     |
| ----------------------------------- | ------------------------------------------------------------ |
| 找不到目标群组                      | 核对登录账号、成员身份、群类型、内容保护及最近 100 对话上限  |
| `CHAT_NOT_ALLOWED`                  | 核对白名单已保存、账号仍在群内、未开启内容保护               |
| `INVALID_CODE` / `INVALID_PASSWORD` | 输入最新验证码或正确两步验证密码，避免连续重试               |
| `LOGIN_EXPIRED` / `SESSION_EXPIRED` | 重新登录，勿多处共用或复制 session                           |
| `READER_BUSY`                       | 等当前操作完成后重试，勿并发连点                             |
| 配置冲突                            | 刷新页面确认无他人同时编辑后再保存                           |
| 网络超时                            | 检查服务健康及服务器到 Telegram MTProto 的网络，勿先轮换密钥 |
| MCP 401 / 403                       | 检查 OAuth 授权、scope、资源地址与令牌刷新，勿关认证         |

临时停用直接关闭 Reader 保存；彻底停用点「退出并撤销此设备」（不影响该账号其他设备；若网络异常导致撤销失败，在 Telegram 客户端设备管理中手动踢掉）。

版本回退前先停用 Reader，并确认旧版兼容迁移和加密凭据格式，不要删除迁移记录或让旧版轮换新凭据。
