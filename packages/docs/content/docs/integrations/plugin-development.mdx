API v1 插件由清单与预构建 ESM 入口组成。宿主在服务端导入入口，为每次 AI 回复创建独立会话。SDK 定义接入方式，不提供进程隔离或沙箱。

## 发布文件

公开 GitHub 仓库根目录必须包含：

```text
hanori.plugin.json
index.mjs
```

入口必须能够直接在 Hanori 的 Node.js 22.19.0 或更高环境运行。把依赖预先打包进发布文件，或使用 Node.js 内置模块；不要依赖宿主私有包、开发机器的 `node_modules` 或安装后构建。安装器不执行依赖安装、构建脚本、Git hooks 或子模块更新，不接受符号链接与子模块。发布树最多 512 个条目、32 MiB，清单最多 64 KiB。

安装源使用公开 `https://github.com/owner/repository` 和完整 40 位小写提交 SHA。宿主核对实际取回的提交，并保留不可变版本。更新必须维持同一插件 ID；`hanori.bilibili` 与 `hanori.netease` 保留给内置插件。

## 清单与配置

```json
{
  "apiVersion": 1,
  "id": "example.hello",
  "name": "Hello plugin",
  "version": "1.0.0",
  "description": "A synthetic read-only example.",
  "author": "Example author",
  "config": [
    { "key": "greeting", "label": "Greeting", "type": "string", "default": "Hello", "max": 120 }
  ]
}
```

插件 ID 使用小写字母、数字及点或连字符分段，最多 100 字符；版本为语义化版本字符串。配置支持 `string`、`text`、`number`、`integer`、`boolean`、`select`，可声明必填、默认值和边界，`select` 提供值与标签。

秘密字段使用 `string` 或 `text` 并声明 `secret: true`，不能带默认秘密。每个 Bot 的配置独立保存；公开 API 只返回普通值和已配置秘密的字段名。更新时，普通值写入 `configuration.values`，秘密写入 `configuration.secrets`：秘密字段省略或空字符串保留旧值，`null` 明确清除。

保存与启用请求带 `expectedRevision` 和当前 `manifestHash`。清单改变会阻止未审核配置执行，作者不能通过保持版本号不变来避开清单审核。更新、回滚、卸载和重新安装都会使旧修订失效；卸载保留制品及配置草稿，但会停用所有关联 Bot。

## 入口与会话

```js
export default {
  apiVersion: 1,
  createSession(context) {
    return {
      tools: [],
      searchProviders: [],
      dispose() {},
    };
  },
};
```

`createSession` 可以返回 Promise。`context` 提供：

| 字段            | 含义                                                                      |
| --------------- | ------------------------------------------------------------------------- |
| `actor`         | 当前 `botId`、`chatId`、可选 `userId`、`isAdmin`、`isPrivate`、`readOnly` |
| `configuration` | 当前 Bot 已保存、已启用且经过清单审核的配置；秘密只在服务端出现           |
| `signal`        | 会话关闭、配置变化、插件停止或宿主关闭时取消                              |

引用、缓存和正在执行的任务放在会话内，不要用模块级状态共享 Bot 数据。工具的 `execute` 和检索的 `search` 各接收操作信号，网络请求应同时响应会话与操作取消；取消后不接纳迟到结果。`dispose` 释放资源并停止任务，可以返回 Promise。保持顶层导入轻量，不在导入时启动网络、定时器或任务。

宿主限制入口加载、会话创建和调用的等待时间，并在调用前后重新检查安装及 Bot 配置。超时只限制宿主等待，不能强制终止忽略取消的 JavaScript 或进程；作者必须实现取消和资源释放。

可选 `check(context)` 返回 `{ success: boolean }`，用于有意义的已保存配置检查。没有该钩子时，面板只创建、校验并销毁会话。不要把这个默认测试当作真实服务连通性或账号认证证明。

## 可选扫码登录

清单声明 `"login": { "type": "qr" }` 后，面板提供统一扫码登录界面。入口同时实现 `startLogin(signal)`，返回私有登录会话：

```ts
interface LoginAttempt {
  qrUrl: string;
  poll(signal: AbortSignal): Promise<
    | { status: "waiting" | "scanned" | "expired" }
    | {
        status: "authorized";
        secrets: Record<string, string>;
        account: { name: string };
      }
  >;
  dispose?(): void | Promise<void>;
}
```

`qrUrl` 是平台提供的 HTTP(S) 扫码内容，面板本地生成二维码，不通过外部图片服务。`startLogin` 的信号覆盖会话生命周期，`poll` 还须响应单次操作信号。每个尝试使用独立 Cookie jar；创建与轮询不得自行写 Bot 配置。插件应限制登录请求的目标、跳转、大小和超时，不能把私有平台响应或原始异常返回给页面。

返回 `authorized` 前必须调用平台账号接口验证登录，不能仅凭“已扫码”或某个成功状态码判断。`secrets` 仅包含清单中已声明的秘密字段，值为非空字符串；账号名用于显示，应为有界纯文本。秘密仅在服务端返回宿主，宿主核对安装版本、清单和 Bot 配置修订后合并并加密保存。公开状态只有保存成功后才变成 `connected`。

宿主绑定当前管理员网页会话、插件和 Bot，限制并发并串行轮询，最短轮询间隔为 2 秒，扫码会话最多 5 分钟。持久化开始前，关闭、过期、配置改变或插件停止会取消尝试；进入 `saving` 后不再承诺取消写入，确认结果后才报告 `connected`，结果不确定时报告 `save_unknown` 并提示重新加载配置。`dispose` 应销毁 Cookie jar、停止定时器并释放资源。插件不应在模块级缓存凭据。登录不会自动启用插件；现有配置待审核时，需先审核保存再开始登录。

可在不修改面板的情况下实现第三方扫码登录。该扩展仍属于可信服务端插件能力，不提供远程浏览器、密码表单或插件代码沙箱。TypeScript 契约见 `packages/shared/src/plugin-login.ts`。

## 工具

每个工具声明 `name`、`description`、JSON 对象 `inputSchema`、`effect`、`access`，实现 `execute(input, signal)`。本地名称匹配 `[a-z][a-z0-9_]{0,39}`，同一会话不能重复；宿主会加命名空间，不要在插件内猜测最终工具名。

`effect` 为 `read_only` 或 `mutating`，`access` 为 `all` 或 `admin`。宿主按身份筛选管理员工具，只读上下文排除修改工具。声明不是代码沙箱：作者仍负责实际行为、租户隔离、服务器授权和副作用确认。

工具最多 32 个，JSON Schema 最多 16,384 字符，工具参数 JSON 最多 32,000 字符，结果 JSON 最多 64,000 字符。结果必须可以 JSON 序列化。模型生成的参数是不可信输入；`inputSchema` 不代替执行时校验，作者需要验证类型、长度、枚举、未知字段和引用归属。

不要把秘密、认证头、带签名的私有 URL 或原始异常放进结果或日志。需要读取外部资料时，限制主机、协议、重定向、大小、超时和正文长度，按页返回并保留来源。外部正文仅作资料，不能变成执行指令或用户授权。

## 检索来源

`searchProviders` 最多 16 个，每项声明本地 `id`、`scope`、`description`、`pagination`，实现 `search(request, signal)`。`id` 与 `scope` 使用工具相同的本地名称规则。来源名称会加插件命名空间，`scope` 保持声明值；描述应说明是关键词检索、列表浏览还是链接查询。

请求包含 `scope`、可选 `provider`、`query`、`page`、`limit` 和可选 `filters`。按真实能力声明 `native` 或 `single_page` 分页；默认要求非空查询，只有支持无关键词浏览的来源才使用 `allowEmptyQuery: true`。自定义过滤字段应声明 `filters` 契约，并在执行时再次验证。

结果包含 `status`、`items`、`hasMore` 和可选 `truncated`。每项有稳定 `id`、`title`、`summary`，可选 `url`、`content`、`source` 和有界标量 `fields`。`content` 留在宿主当前轮的引用存储中，摘要检索不直接返回它；宿主生成搜索引用，使用 `read_reference` 按需读取。若另有客户端资源引用，放在 `fields` 中并在后续工具里验证；这与宿主搜索引用是两个不同引用。

搜索必须只读，不发送消息、改计数、下载音频、隐式转录或启动后台作业。`hasMore` 只表示确有下一页；单页响应被数量或文本边界裁剪时用 `truncated`，不能假装 page 2 能取回剩余内容。区分 `empty`、`unavailable`、`forbidden`、`rate_limited`、`upstream_error` 与 `invalid_request`。

## 从示例开始

仓库 `examples/plugins/hello/` 提供零依赖 `index.mjs`、清单和可复制的 Node.js smoke test。它包含 `greet` 只读工具、`hello` 范围的合成检索、参数验证、取消与 `dispose`，没有外部服务或秘密。

先在示例目录执行 README 中的本地验证，再复制到独立公开仓库的根目录，修改 ID、作者与版本并发布审核过的提交。不要把 Hanori 仓库子目录直接当作安装源。实际 TypeScript 契约以 `packages/shared/src/plugin-runtime.ts`、`packages/shared/src/search.ts` 和清单校验为准。

发布前验证合法与非法参数、身份筛选、会话间数据隔离、并发与取消、正文与缓存上限，并检查结果不会携带秘密。外部 API 的真实可用性、授权与费用需要单独验证；纯合成 smoke test 只证明本地契约。
