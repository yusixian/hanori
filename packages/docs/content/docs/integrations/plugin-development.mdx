API v1 插件由清单文件和预构建 ESM 入口组成。宿主在服务端导入入口，每次 AI 回复创建独立会话。SDK 只定义接入契约，**不提供进程隔离或代码沙箱**。

## 发布文件

公开 GitHub 仓库根目录必须包含：

```text
hanori.plugin.json
index.mjs
```

- 入口须直接在 Node.js 22.19.0+ 运行：第三方依赖需预先打包，或只用 Node.js 内置模块，不能依赖宿主私有包、本地 `node_modules` 或安装后构建。
- 安装器不跑依赖安装、构建脚本、Git hooks 或子模块更新，拒绝符号链接与子模块。发布树上限 512 个条目、32 MiB，清单上限 64 KiB。
- 安装源为公开 `https://github.com/owner/repository` 加完整 40 位小写提交 SHA。宿主校验实际拉取的提交并固化版本；更新须保持同一插件 ID。`hanori.bilibili` 与 `hanori.netease` 保留给内置插件。

## 清单与配置

```json
{
  "apiVersion": 1,
  "id": "example.hello",
  "name": "Hello plugin",
  "version": "1.0.0",
  "description": "A synthetic read-only example.",
  "author": "Example author",
  "config": [
    { "key": "greeting", "label": "Greeting", "type": "string", "default": "Hello", "max": 120 }
  ]
}
```

- 插件 ID 仅含小写字母、数字、`.` 或 `-` 分段，最多 100 字符；版本为语义化版本。
- 配置字段支持 `string`、`text`、`number`、`integer`、`boolean`、`select`（含值与标签），可声明必填、默认值和范围。
- 秘密字段用 `string` 或 `text` 加 `secret: true`，不能设默认值。各 Bot 配置独立，公开 API 仅返回普通值和已配置的秘密字段名。更新时普通值写入 `configuration.values`，秘密写入 `configuration.secrets`：省略或空串保留旧值，`null` 清除。
- 保存与启用请求须携带 `expectedRevision` 和当前 `manifestHash`。清单变更会拦截未审核配置（保持版本号不变无法绕过）。更新、回滚、卸载和重装都会令旧修订失效；卸载保留制品与配置草稿，但会停用所有关联 Bot。

## 入口与会话

```js
export default {
  apiVersion: 1,
  createSession(context) {
    return {
      tools: [],
      searchProviders: [],
      dispose() {},
    };
  },
};
```

`createSession` 可返回 Promise。`context` 包含：

| 字段            | 含义                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------ |
| `actor`         | 当前 `botId`、`chatId`、可选 `userId` 和 Telegram `threadId`、`isAdmin`、`isPrivate`、`readOnly` |
| `configuration` | 当前 Bot 已保存、已启用且通过清单审核的配置（秘密仅在服务端可见）                                |
| `signal`        | 会话关闭、配置变更、插件停止或宿主关停时触发取消                                                 |

- 状态、缓存和在途任务放进会话实例，禁止用模块级状态跨 Bot 共享数据；顶层导入保持轻量，勿在导入时发网络请求或启定时器。
- 工具 `execute` 和检索 `search` 均接收操作级 `signal`，网络请求须同时监听会话与操作信号，取消后丢弃迟到结果；`dispose` 负责释放资源和停任务（可返回 Promise）。
- 宿主限制入口加载、会话创建与调用的等待时间，并在调用前后重检安装及 Bot 配置。超时仅停止宿主等待，无法强杀忽略取消的 JS 代码，插件须自行响应取消并清理资源。
- 内置 Bilibili 的持久转录与视频下载由宿主托管后台任务：当前轮次的 `dispose` 不会终止已接纳任务，但修订、授权、配额和取消仍由宿主核对。第三方插件不能借此绕过会话生命周期或跨 Bot 留存凭据。
- 可选钩子 `check(context)` 返回 `{ success: boolean }` 用于检测已保存配置；未实现时面板仅验证会话创建与销毁，不代表外部服务连通或账号有效。

## 可选扫码登录

清单声明 `"login": { "type": "qr" }` 且入口实现 `startLogin(signal)` 时，面板自动提供扫码登录界面：

```ts
interface LoginAttempt {
  qrUrl: string;
  poll(signal: AbortSignal): Promise<
    | { status: "waiting" | "scanned" | "expired" }
    | {
        status: "authorized";
        secrets: Record<string, string>;
        account: { name: string };
      }
  >;
  dispose?(): void | Promise<void>;
}
```

- `qrUrl` 为 HTTP(S) 扫码内容，由面板本地生成二维码。`startLogin` 信号覆盖登录会话，`poll` 同时响应单次操作信号。每次尝试须使用独立 Cookie jar，不得自行写 Bot 配置，并限制目标主机、跳转、体积与超时，勿将私有响应或原始异常透传给前端。
- 返回 `authorized` 前必须调平台接口确认登录状态，不能只凭「已扫码」判定。`secrets` 仅含清单声明的秘密字段（非空字符串），`account.name` 为有界纯文本。秘密在服务端经宿主校验版本、清单和修订后加密保存，保存成功才将公开状态切为 `connected`。
- 宿主按管理员网页会话、插件和 Bot 串行限流轮询（最短间隔 2 秒，总限时 5 分钟）。进入 `saving` 前关闭、过期、改配置或停插件都会取消尝试；进入 `saving` 后不再保证取消，结果不确定时返回 `save_unknown` 并提示重载。`dispose` 须销毁 Cookie jar 和定时器，勿在模块级缓存凭据。
- 登录不自动启用插件；配置待审核时须先审核保存再登录。该能力仍属可信服务端插件，不提供远程浏览器、密码表单或沙箱。TypeScript 契约见 `packages/shared/src/plugin-login.ts`。

## 工具

每个工具声明 `name`、`description`、JSON 对象 `inputSchema`、`effect`、`access`，并实现 `execute(input, signal)`。

- 本地名称须匹配 `[a-z][a-z0-9_]{0,39}`，同会话不重复；宿主自动加命名空间，勿在插件内猜测最终名称。
- `effect` 为 `read_only` 或 `mutating`，`access` 为 `all` 或 `admin`。宿主按身份过滤管理员工具，只读上下文排除修改工具。声明不替代代码内的租户隔离、权限校验与副作用确认。
- 硬性上限：最多 32 个工具、单 Schema 16,384 字符、入参 JSON 32,000 字符、出参 JSON 64,000 字符，出参须可 JSON 序列化。模型入参不可信，`execute` 内仍须校验类型、长度、枚举、未知字段与资源归属。
- 勿在结果或日志中输出秘密、认证头、签名私有 URL 或原始异常。读取外部内容时限制主机、协议、重定向、大小、超时和正文长度并分页返回；外部文本只作资料，不能当成指令或授权。

内置 Bilibili 可选注入宿主 `VideoDownloadPort`（`download_video` / `cancel_video_download` 为 `mutating/admin`，`get_video_download` 为 `read_only/admin`）：

- 下载只收 `sourceUrl`，查询和取消只收任务 ID；发送目标、路径和 Cookie 由宿主按当前 Bot/聊天/用户/话题绑定，不接受模型传参。仅管理员明确要求下载回传时创建，不在检索、缺字幕或 ASR 后隐式触发。
- 拉取 Bilibili DASH 音视频流后在隔离 ffmpeg 中 stream copy 合并 MP4 并流式上传 Telegram（不用 yt-dlp 本体，不自动 ASR）。受时长、体积、日次、缓存 TTL、缓存预算和磁盘余量限制，且受 Telegram 50 MB 上限约束。数字配置未设 `max` 时宿主仍校验安全整数与范围；缓存预算须至少覆盖单视频上限的 2 倍加 1 MiB。
- 返回状态如实保留 `sending` / `delivery_unknown`：取消不撤回已发消息，未知投递不自动重发，缓存过期仅删服务器副本。

## 检索来源

`searchProviders` 最多 16 个，每项声明本地 `id`、`scope`（同工具命名规则）、`description`、`pagination`，实现 `search(request, signal)`。来源名由宿主加命名空间，`scope` 保持原值；描述写明是关键词检索、列表浏览还是链接查询。

- 请求含 `scope`、可选 `provider`、`query`、`page`、`limit` 及可选 `filters`。分页按真实能力声明 `native` 或 `single_page`；仅支持无关键词浏览的来源设 `allowEmptyQuery: true`。自定义 `filters` 须声明契约并在执行时重检。
- 返回含 `status`、`items`、`hasMore` 和可选 `truncated`。每项含稳定 `id`、`title`、`summary`，可选 `url`、`content`、`source` 及标量 `fields`。`content` 存进宿主当前轮引用存储，摘要不直接下发，由 `read_reference` 按需读取；插件自有的客户端资源引用放 `fields` 并在后续工具里校验。
- 搜索必须只读，禁止发消息、改计数、下音频、隐式转录或启后台任务。`hasMore` 仅表示确有下一页；单页裁剪用 `truncated`。状态码须准确区分 `empty`、`unavailable`、`forbidden`、`rate_limited`、`upstream_error`、`invalid_request`。

## 从示例开始

`examples/plugins/hello/` 提供零依赖 `index.mjs`、清单和 Node.js smoke test（含 `greet` 工具、`hello` 合成检索、参数校验、取消与 `dispose`）。

先在示例目录跑通 README 中的本地验证，再复制到独立公开仓库根目录，改好 ID、作者和版本后发布审核过的提交（不要直接把 Hanori 子目录当安装源）。完整 TypeScript 契约见 `packages/shared/src/plugin-runtime.ts`、`packages/shared/src/search.ts` 及清单校验代码。

发布前测完合法/非法参数、权限过滤、会话隔离、并发取消、大小上限和脱敏；外部 API 的真实可用性、授权与费用需另行实测。
