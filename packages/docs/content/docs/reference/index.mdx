用于快速查阅管理面板页面、权限角色、健康接口和部署约束。

## 面板入口

不同角色可见的导航不同，主要页面如下：

| 入口                                | 用途                                           |
| ----------------------------------- | ---------------------------------------------- |
| Bots                                | 创建、启停和编辑 Bot。                         |
| AI                                  | Provider、模型、系统提示词与 AI 设置。         |
| Governance                          | 群组、用户与资源的用量、冷却、并发及路由策略。 |
| Conversations / Profiles / Memories | 查看对话历史、人物档案与长期记忆。             |
| Generations / Files                 | 查看生图任务、状态与 Bot 收到的文件。          |
| RSS / Summary / Timers              | 配置订阅源、群聊总结与定时任务。               |
| Logs / Usage                        | 查看运行诊断、用量与成本统计。                 |
| MCP Servers                         | 管理外部 MCP 工具连接。                        |
| Backup / Data                       | 备份、导出与数据管理。                         |
| Settings                            | 工作区认证、成员与实例设置。                   |

前端隐藏按钮不代表放行，服务端会对每个 API 请求校验工作区角色、Bot 归属、群组范围和资源权限。

## 用量筛选

Usage 页的汇总与趋势跟随所选时间范围和 Bot；**按 Bot** 对比图始终比较所选时间内的全部 Bot；每日活跃度固定为近 365 天，只跟随 Bot 筛选。加载失败会在对应区域报错并提供重试，不沿用旧筛选数据。

## 角色边界

- **管理面板角色**：`owner`（高风险实例设置、部分 OAuth 与备份）、`admin`（日常 Bot 与集成管理）、`editor` / `viewer`（按当前资源策略受限）。
- **Telegram Mini App 角色**：按 Bot 作用域独立划分 `admin`、`operator`、`viewer` 和 `none`，见[Telegram Mini App](/docs/guides/mini-app)。

Web 面板角色、Bot 管理员身份与 Telegram 群内管理员互不等同。

## 健康接口

服务端暴露三个只读接口：

```text
GET /api/health
GET /api/health/live
GET /api/health/ready
```

- `/api/health`：进程可响应。
- `/api/health/live`：返回存活状态与版本。
- `/api/health/ready`：必需依赖全部就绪才返回 200，否则返回 HTTP `503`。

健康接口通过不代表外部模型 Provider、Telegram 投递或可选集成全部正常。

## 版本与构建标识

产品 SemVer 版本由根 `package.json` 管理，运行时同时通过 `APP_VERSION` 或健康接口暴露完整 Git commit SHA。前者对应发布说明，后者用于定位线上代码；报障时请一并提供两者及发生时间。

## 数据库与迁移约定

Schema 定义在 `packages/database`，迁移按顺序执行。改动 Schema 后生成并审查 SQL 迁移文件，**不要**修改已部署的迁移或手工删迁移记录。embedding 维度、加密密钥与数据库密码属于部署级参数，未做好备份前不要直接改动。
