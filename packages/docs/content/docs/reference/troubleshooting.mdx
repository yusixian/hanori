---
title: 故障排查
description: 按现象定位启动、登录、Telegram、AI、Mini App 与集成故障。
---

排障前先记下版本号、构建 commit、功能入口、聊天类型和发生时间，再尽量小范围复现。不要收集完整原始 Telegram update 或未脱敏日志。

## 服务无法启动

依次检查：

- `DATABASE_URL`、`BETTER_AUTH_SECRET`、`AUTH_OWNER_EMAIL` 是否齐全；
- 生产环境 `BETTER_AUTH_URL` 是否为真实 HTTPS origin；
- `DB_PASSWORD`、数据卷与 PostgreSQL 健康状态是否一致；
- `ENCRYPTION_KEY` 是否被意外更换；
- GitHub App 的 5 个环境变量是否只配了一半；
- 启用 `COMPOSE_PROFILES=coding` 时是否同时设置了 `CODING_WORKER_SECRET`。

对照应用日志与 `/api/health/ready`，把数据库迁移错误和外部集成错误分开排查。

## 登录后跳回登录页

先在浏览器 Network 面板看两个请求：

1. `/api/auth/sign-in/email` 是否成功；
2. 紧随其后的 `/api/authz/me` 返回什么：
   - **401**：检查会话 Cookie 属性与域名/`BETTER_AUTH_URL` 配置；
   - **403**：检查工作区成员资格；
   - **两者都 200 仍跳回登录页**：属于前端登录态判断或跳转问题，无需反复重置密码。

## 能登录但看不到工作区

受邀邮箱必须与实际登录邮箱完全一致。Google OAuth 测试用户名单、Better Auth 账号、工作区邀请是三层独立检查，缺一不可。请让 owner 重新发邀请，不要手工改数据库成员表。

## Bot 不回复

先在私聊发 `/help` 和 `/status`（管理员），再逐项核对：

1. Bot Token 是否有效、Bot 是否已启动；
2. AI 是否被 `/stop` 或面板开关暂停；
3. 当前聊天的 Provider / 模型是否存在且可用；
4. 群聊是否设为仅 `@提及/回复` 触发，当前消息是否满足条件；
5. 是否触发了用量、并发、冷却或权限策略。

若看到“接受任务”却迟迟没发最终回复，先查生成、工具和投递日志，不要连发重试。

- AI 还能回复时，管理员可直接问“为什么我上一条消息没有回复？请查询请求链路”，调用[只读运行诊断工具](/docs/reference/runtime-diagnostics)。
- 面板日志中可先选 Bot，再用群聊 ID 或关联 ID 过滤，详见[检索和清理日志](/docs/guides/panel-navigation#检索和清理日志)。

## Provider 或模型不可用

先核对 Provider 凭据与上游服务状态，再在聊天中重置覆盖：

```text
/provider reset
/model reset
```

若模型列表为空，检查面板默认配置是否已应用到该 Bot，或该 Provider 是否返回了可用模型。排障时只看诊断日志里的错误类别，勿泄露 API Key。

## Mini App 打不开

Mini App 只能从 Telegram WebView 打开并携带真实签名的 `initData`。普通浏览器访问、旧 Cookie、`MINI_APP_SESSION_SECRET` 轮换、Bot 停用、无群组授权或 Bot 无法查群成员都会被拒绝。

从 Telegram 菜单重新打开，检查 HTTPS、Bot 的 Mini App 开关、`MINI_APP_SESSION_SECRET` 和服务端日志；不要让用户把 Cookie 或 `initData` 发给管理员。

## RSS、群总结或定时器未发送

逐项确认：

- RSS Feed 可手动拉取且 URL 凭据未过期；
- 总结时间窗内有消息、访问模式允许当前用户、Provider 可用；
- 定时器处于启用状态且目标聊天允许发送；
- 时区、冷却与用量策略正常；
- 查日志确认失败落在拉取、模型、调度还是 Telegram 投递阶段。

## 发布后仍显示旧版本

GitHub Release 发布不会自动更新线上实例。核对 `/api/health/ready` 返回的完整 commit SHA：若仍是旧 SHA，先查部署平台对该提交的构建日志。构建失败时旧实例通常仍保持健康，不要误判为已上线或连续重推。

## 提交有效报障信息

提供以下脱敏信息即可：版本与 commit SHA、功能页面或命令、聊天类型、时间（注明时区）、复现步骤、错误类别及健康接口返回。提交前删除用户名、Telegram ID、消息全文、URL 密钥参数、Authorization、Cookie、Bot Token、API Key 和原始媒体。
