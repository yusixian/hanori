Hanori 同时有 Telegram Bot 和 Web 管理面板两个入口。Telegram 适合日常对话、群聊互动和执行单次命令；面板适合配置模型、权限、自动化、日志和备份。

## 你需要先确认什么

如果你只是使用别人维护的实例，通常需要：

1. 一个可访问的面板地址和登录账号，或者一个已经加入目标 Telegram 群组的账号。
2. Bot 已被拉入目标群，并且 Telegram 管理员允许它读取消息、发送消息或发起所需的操作。
3. 由实例管理员启用的 Provider、模型或其他工具。没有配置 Provider 时，Bot 仍可能能回复帮助命令，但不能执行 AI 任务。

如果你负责部署实例，还需要准备 PostgreSQL 数据库、稳定的认证和加密密钥，以及 Telegram Bot Token。可从[自托管总览](/docs/self-hosting)开始。

## 认识几个核心对象

| 对象     | 作用                                                                 |
| -------- | -------------------------------------------------------------------- |
| Bot      | 一个 Telegram Bot 配置，包含 Token、运行状态、AI 设置和工具能力。    |
| Chat     | 私聊、群组或超级群组。Provider、模型、回复行为和总结可以按聊天覆盖。 |
| 用户     | 通过 Telegram ID 识别的参与者，可有个人化模式、档案和长期记忆。      |
| 面板成员 | 登录 Web 面板的账户，通过工作区角色获得管理权限。                    |
| 集合     | RSS 订阅源的分组，或群聊总结、定时任务等自动化配置的逻辑单元。       |

## 推荐的阅读顺序

- 第一次使用已有实例：阅读[快速开始](/docs/getting-started/quickstart)。
- 想让 Bot 在群里更克制：阅读[群聊行为与参与控制](/docs/guides/group-behavior)。
- 想接入模型或工具：阅读[AI 对话与模型](/docs/guides/ai-chat)和[MCP 服务器](/docs/integrations/mcp)。
- 想运行自己的实例：阅读[配置说明](/docs/self-hosting/configuration)、[Docker 部署](/docs/self-hosting/docker)和[备份与升级](/docs/self-hosting/backup-upgrade)。

## 成功标准

一次完整的首次使用检查应至少包括：在面板中看到 Bot 状态正常；在 Telegram 中用 `/start` 和 `/help` 确认命令菜单；发送一条普通消息并看到回复；如果启用了群聊功能，再用明确提及或回复 Bot 的方式测试。遇到问题时，先记录聊天类型、命令、时间和面板错误信息，不要把 Token 或完整原始更新贴到公开场所。
