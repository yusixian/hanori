---
title: 快速开始
description: 用几分钟完成首次登录、Bot 配置和 Telegram 连通性检查。
---

下面的流程适用于一个已经运行、且你有面板访问权限的实例。若你要从零部署，请先阅读[自托管总览](/docs/self-hosting)。

## 1. 登录面板

打开实例维护者提供的面板地址，用邀请对应的邮箱和密码登录。首次登录后建议立即到 Settings 修改初始密码，并确认账号已经加入正确的工作区。

如果使用 Google 登录，还要同时满足 OAuth 服务商的允许范围（若该服务商配置了测试用户）和本项目的工作区邀请；具体以实例管理员的配置为准。

## 2. 创建或检查 Bot

在 Bot 列表中选择已有 Bot，或进入创建流程。检查以下内容：

- Telegram Bot Token 已保存且没有被截断；
- Bot 的平台和启用状态正确；
- 默认 AI Provider 与模型已经可选；
- 需要时再启用图片生成、RSS、群聊总结、MCP 或 Mini App。

Token 是敏感凭据。粘贴后不要把输入框截图发到群里，也不要把它写进公开的 issue 或文档。

## 3. 配置一个可用模型

进入 Bot 的 AI 设置，选择 Provider 和模型并保存。Provider 负责连接一类模型服务，模型决定具体能力和成本；不同实例公开的 Provider 列表可能不同。

保存后，可以在 Telegram 中发送：

```text
/provider
/model
```

这两个命令会显示当前聊天的选择和可切换列表。它们支持按编号或名称切换，也支持 `reset` 恢复默认值；修改权限取决于实例管理员的访问策略。

## 4. 在 Telegram 中测试

先打开 Bot 私聊，依次发送：

```text
/start
/help
```

再发送一条不包含秘密的普通问题。如果 Bot 没有回复：

1. 在面板确认 Bot 运行状态和 AI 是否启用。
2. 用 `/status`（管理员命令）检查运行信息，或在面板查看日志。
3. 检查当前聊天是否覆盖了一个不可用的 Provider 或模型。
4. 如果刚改过配置，等待 Bot 完成应用或重启，再重试一次。

## 5. 测试群聊时从低风险行为开始

把 Bot 加入测试群，先使用明确的回复或 `@Bot` 触发。确认它能读取所需消息、按预期回复后，再配置随机参与、触发词、群总结或 JEV。群聊治理和用量限制见[群聊行为与参与控制](/docs/guides/group-behavior)。
