---
title: RSS、总结与定时任务
description: 配置 RSS 集合、群聊总结和定时任务，了解执行状态与冷却规则。
---

RSS 订阅外部源，群聊总结读取 Telegram 历史，持久定时任务按计划触发执行。三者的数据来源和权限相互独立，建议逐项配置和验证。

## RSS 集合

在 Bot 的 RSS 页面创建集合并添加 Feed URL。集合可配置名称、描述、摘要提示词、定时摘要时间和最大条数；单个 Feed 可覆盖标题和条数上限。

建议按以下顺序验证：

1. 先添加一个公开稳定的 RSS/Atom 源。
2. 手动抓取一次，确认标题、链接和发布时间正常。
3. 在 Telegram 中让 Bot 列出集合或查看未读条目。
4. 确认无误后再开启定时摘要。

同一批次到期的集合会逐一检查：单个失败记录 ID 后继续处理其余集合，不立即重试。Feed URL 和标题会进入模型与工具流程，含私密参数的订阅地址切勿发到公开群，并留意日志脱敏与外部模型边界。

服务正常关停时，会停止新的抓取和摘要，等待已接纳的抓取批次、摘要投递和检查点写完后再关闭依赖。超时或 HTTP 错误时会自动中止遗留请求并释放重定向响应。

## 群聊总结

面板可按群配置开关、执行时间、时区、时间窗口、最多消息数、冷却和访问模式（所有成员或仅管理员）。

手动命令（单次上限 72 小时或 2,000 条消息）：

```text
/summary
/summary 6h
/summary 200
/summary today
/summary yesterday
```

失败时注意区分消息不足、未配置 Provider、命中冷却、权限不足和模型报错。

### 范围、预览与覆盖信息

`/summary` 和 `summarize_chat` 仅读取当前 Bot、聊天与明确的话题；不在话题内调用时，只读带主话题标记的记录，不汇总整个论坛，缺标记的旧记录不猜测归属。消息按作者当前隐私设置过滤，优先取原始正文；Bot 回复仅在能通过 `turnOrderId` 关联到同作用域允许读取的来源消息时纳入，系统与工具记录不参与。

总结使用独立总结模型及逐群覆盖，服务端按 24,000 token 分块（长单条继续拆分）并归并中间摘要，异常输出明确报错；取消聊天或任务时会同步取消总结请求。

站点所有者可在 **群聊总结 → 预览总结（不发送）** 中指定聊天、话题、起止时间、最多条数、是否仅用原始发言及本次格式要求（本次要求优先于默认风格，但不改变数据范围）。预览无需预先配置该群，不发消息也不消耗手动冷却，但计入用量与记录；可用消息少于 5 条直接返回“消息太少”，不调模型。

`coverage` 字段说明：

- `scope` / `returnedCount`：实际查询范围与过滤后读到的条数。
- `firstMessageAt` / `lastMessageAt`：选中消息的时间首尾，空窗口为 `null`。
- `complete=true`：范围内本地允许读取的记录已全部读完（刚好达上限时会多查一条确认）。
- `truncated=true` 且 `reason=message_limit`：确实因条数上限未读完。
- `collectionCoverage=unknown`：无法证明 Bot 采集了 Telegram 的全量历史。

所有者 API 为 `POST /api/bots/:botId/summary/preview`，参数含 `chatId`、可选 `threadId`、带时区的 `since` / `until`、`maxMessages`、可选 `instructions` 与 `sourceRoles: "original"`（上限 72 小时 / 2,000 条，受总结配置约束），只返回结构化摘要和 `coverage`，不发送消息，不接受伪造身份字段。

### 全局定时总结

在 AI 设置中启用总结并填好全局时间后，没有逐群配置的群会按该时间自动总结（时区默认 `Asia/Shanghai`）。仅针对运行中、仍在群内、未迁移的群聊/超级群，且最近 24 小时至少有 5 条符合角色过滤的已保存消息（不含系统与工具消息）。任何逐群配置（包括关闭或留空时间）都优先于全局设置；删掉逐群配置则恢复继承。

全局执行权落库保存，23 小时内不重复触发（多实例和重启共享）。失败仍保留冷却，不自动重试，停机错过的时刻不补发；批量处理时单个群出错不影响其他群。正常关停会等已开始的总结及 `/summary` 回复完成再退出；尚未拿到执行权的任务不消耗冷却。

**升级提示：此前保存但未生效的全局时间，在升级到包含此功能的版本后会开始触发。升级前请核对总结开关、小时、分钟和时区；不希望自动发送时，请关闭总结或清空全局时间。**

## 持久定时任务

群成员可直接用自然语言提出计划（如“每月 1 日早 9 点总结这个话题发到本群”）。Bot 会整理出包含内容、数据范围、目标、时区、首次执行时间、周期和执行 Agent 的计划卡；信息不足时先追问（配置对话开启后 10 分钟内不受普通接话冷却限制，仍受隐私、`/stop` 和聊天排队约束）。

任何人都能发起提案；批准、试跑和取消需要 Bot 管理员或已配置的群代理管理员（Telegram 群管理员不等于已授权）。跨聊天发送的计划必须由 Bot 管理员批准。

- **确认创建/变更**：批准当前版本卡片；修改已有任务需重新确认，审批前原计划继续运行。
- **试跑一次**：按待确认计划执行一次并保留记录，不启用周期任务。
- **修改计划**：回复卡片说明改动，Bot 生成新版本；旧卡、过期卡和重复确认无效。
- **取消提案**：作废待确认版本。已生效任务需通过聊天任务工具或面板暂停/取消。

计划卡有效期 24 小时。源话题只读明确归属该话题的消息，旧记录不猜测归属。

### 周期与时区

支持一次性时间、固定秒数间隔，以及按指定时区的每周、每月、每季日历计划（无 1 天或 7 天上限）。固定间隔按经过时间算，日历周期按当地日期算（如每季以起始月为锚点隔 3 个月；月末无该日取最后一天，如 31 日在 2 月落到月底）。夏令时导致时间不存在时顺延至首个有效分钟，重复时取第一次出现的时间。

### 单独配置执行 Agent

定时任务使用独立的任务 Agent 配置，可复用已有子代理，也可覆盖服务商、模型、提示词、工具列表、超时和最大步数。未覆盖项在执行时动态继承，执行记录保留本次实际配置。

任务不借用普通聊天的长对话记忆，只读取计划授权的数据范围：

- `read_task_history`：返回授权范围内的原始用户/上下文发言及覆盖信息。
- `summarize_task_history`：在服务端用同一固定窗口总结并返回摘要与覆盖信息，不自行发消息。

来源与发送目标分开绑定，读取量不超过批准值（上限 1,000 条），无法通过工具参数越权扩大范围。默认任务工具集已含 `summarize_task_history`；显式配置了工具白名单的任务需修改并重新批准才能使用。任务总结使用独立并发控制，不受 `/summary` 手动冷却影响，但关闭总结开关时仍不可用。

### 从面板立即运行并观察

进入 Bot 侧栏 **自动化 → 定时任务** 可管理当前 Bot 的计划（全局页查看全部 Bot）。已批准且未取消的任务（含已暂停的周期任务、已完成的一次性任务）均可点 **立即运行一次**，按已批准内容发真实结果，不改变周期、下次时间、暂停状态或失败计数，也不混入待审批修改。同一任务禁止重叠执行（手动与周期共享限制）。

任务卡按计划时区显示时间，每 3 秒自动刷新。展开 **执行记录** 可查看类型（手动/周期/试跑）、实际 Agent、输出、错误和 Telegram 消息 ID。注意“执行中”不等于成功，未记录消息 ID 不能仅凭输出文本认定已投递。

### 模型协议兼容

任务沿用普通聊天的服务商和模型配置（含思考、温度和输出限制），不通过换模型或关推理掩盖错误。

当 OpenAI 兼容端点明确返回 HTTP 400（提示 Chat Completions 不支持 `reasoning_effort` 与 function tools、需改用 Responses）时，系统仅将该次及后续步骤切到同服务商的 Responses 接口，不重放已执行的工具，并关闭服务端响应存储。其他错误不触发切换。明确的 `reasoning_effort` 会保留，但供应商专属的 thinking 开关或 token 预算不会静默转换或丢弃，遇到不可映射配置会直接报错。

### 恢复与失败

任务与执行记录持久化在数据库中，重启后继续调度：

- 停机错过多个周期时只补跑最近一期，不连续补发全部历史周期。
- 进程中断时的运行中记录标为中断，因可能已发出部分内容，不自动重放；后续周期正常继续。
- 周期任务连续失败 3 次自动暂停并通知，排查后手动恢复。
- 取消或暂停可中止后续调度并请求停止当前执行，但无法撤回已发出的消息。试跑和手动运行不影响正式周期状态。

### 旧定时器兼容

启用持久任务服务后，`set_timer` 会创建一次性**待审批计划**，不再绕过计划卡直接生效。`cancel_timer` 和 `/timers` 继续管理旧定时器；已有旧定时器不会自动迁移。兼容旧模式时 `set_timer` 去掉了 1 天/7 天上限，但无持久化服务的独立模式仍受 JavaScript 单次计时器范围限制。

## 自动化上线检查

- 外部订阅源手动抓取能正常返回内容。
- 目标聊天允许 Bot 发消息，必要时允许读历史。
- Provider、模型、时区和访问/治理规则已核对。
- 在面板日志或执行记录中能看到完整的成功/失败记录。
- 关闭集合、总结或任务后不再创建新执行，运行中的任务按正常流程结束。
