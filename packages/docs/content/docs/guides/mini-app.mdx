title: Telegram Mini App
description: Mini App 的签名登录、角色权限、群组范围与常见排错。
---

Mini App 是从 Telegram WebView 打开的轻量管理入口。它独立于普通管理面板：服务端校验 Telegram 传入的 `initData` 签名，签发按 Bot 路径隔离的短期会话 Cookie，再按实时授权决定可见页面和操作权限。

## 启用前提

- 在面板中为目标 Bot 启用 Mini App。
- 单独配置 `MINI_APP_SESSION_SECRET`（不要复用 Better Auth 密钥、Bot Token 或其他 API Key）。轮换该密钥会让现有 Mini App 会话失效，不影响 Bot 数据。
- Telegram 需能访问该 Bot，且 Bot 有权查询所需群组的成员关系。

## 访问流程

1. 在 Telegram 中点击 Bot 提供的 Mini App 入口。
2. WebView 将签名的 `initData` 传给前端。
3. 服务端校验签名、Bot 状态和用户身份，创建按 Bot 路径隔离的会话 Cookie。
4. 服务端实时解析该用户的角色（管理员、操作员或查看者）与已授权群组。
5. 前端仅展示有权限的页面，服务端对每次读写请求再次鉴权。

直接在普通浏览器打开 `/mini-app/...` 没有真实 `initData`，无法验证登录流程；也不要通过复制 Cookie 绕过校验。

## 角色与范围

| 角色   | 权限范围                                                   |
| ------ | ---------------------------------------------------------- |
| 管理员 | 管理该 Bot 下所有可授权范围。                              |
| 操作员 | 仅可操作已授予的群组。                                     |
| 查看者 | 仅可查看自己仍在群内的已授权群组；退群后在下次鉴权时失效。 |
| 无权限 | 无法进入 Mini App 工作区。                                 |

撤销授权在下次请求鉴权时生效。若 Telegram API 无法确认成员身份，服务端按无权限处理。

## 可用页面

根据当前角色，Mini App 会显示以下页面中的子集：

- **Groups**：查看和管理已授权群组。
- **Settings**：调整群组开关、触发条件、上下文和总结设置。
- **Access**：管理聊天与操作员授权。
- **Logs**：查看受限的 Mini App 运行日志。
- **Help**：查看可用命令与说明。

群组设置保存带修订版本号校验，遇到并发修改时需刷新最新值后再提交。Bot 启停、AI Provider/模型和日志访问仍受服务端角色策略限制。

## 安全与排错

- 生产环境必须使用 HTTPS，且 `BETTER_AUTH_URL`（或公开 origin）与 WebView 访问地址一致。
- 不要在日志中输出原始 `initData`、会话 Cookie 或 Bot Token。
- **提示签名无效**：从 Telegram 菜单重新打开，不要复用旧链接或手动拼参数。
- **角色为 `none`**：检查 Bot 是否启用 Mini App、用户是否获授群组权限，以及 Bot 是否能查询群成员。
- **保存失败**：排查修订冲突或权限错误，刷新页面后重试。
