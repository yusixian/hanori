图片能力由 Bot 工具、生成 Provider、Telegram 投递和面板记录共同组成。先在一个私聊或测试群验证，再开放群组图片权限；生成任务通常是异步的，发送“已接受”不等于图片已经成功投递。

## 两类图片路由

面板的治理和图片设置支持两类用途：

- `anime_illustration`：面向动漫插画等预设路线，可以绑定允许的 preset。
- `general_image`：面向通用或写实图片；默认可以关闭，启用前应确认对应 Provider。

路由会根据请求意图、启用状态和 preset 过滤。关闭某一路由后，它不应出现在可用的生成和 preset 列表中；已经存在的任务记录不会因此消失。

## PixAI

PixAI 是可选的图片 Provider。管理员需要在受保护的配置中提供 API Key，并选择支持的 API 模式；Key 不要放进聊天或前端代码。Bot 会创建后台任务、轮询状态、记录生成结果，并在完成后把图片发送回原聊天。

图片生成还可能经过内容安全检查、用量限制和并发限制。任务失败、超时、完成但没有图片、或者图片发送失败时，优先在面板 Generations 与日志页面查看同一个任务的状态和错误，不要对同一请求反复重试造成重复任务。

## Bot 中的常用操作

```text
/image
/draw
/imagegen
```

`/image` 用于查看预设和任务操作；`/draw` 按预设启动生成；`/imagegen` 管理群组图片生成权限。AI 也可能通过 `create_image` 工具创建任务，但具体工具是否可见取决于当前聊天和治理策略。

## 角色与提示词资产

在 Bot 的「生成资产」页面管理角色库和提示词资产。不同 Bot 的记录隔离；同一个 Bot 内共享可读，但共享不等于所有人都有编辑权限。

- Danbooru 查询返回的角色会按规范 tag 沉淀。查询命中次数表示该角色被工具返回的次数，缓存命中也算；它不是实际画图次数。来源缓存为 12 小时，过期回退会标明，来源摘要不等于人工确认的设定。
- 原创角色无需 Danbooru tag。明确告诉 Bot「记住这个角色」，保存名称、别名、外貌、默认服装和备注。创建者可编辑自己的角色，Bot 管理员可维护全部；同名角色不会自动合并。当前只保存文字设定，不保存参考图。
- 人物档案可以绑定多个「代表形象」和「喜爱角色」，代表形象中至多设一个默认。本人能维护自己的绑定，管理者能维护全部。绑定不会授予角色编辑权。
- 请求「画一下某位群友」时可使用其默认代表形象；明确选择其他角色优先。喜爱角色不自动代表本人；没有默认项时需要选择。临时服装或场景不会改写角色档案。

提示词资产支持画师串、画风、服装、外貌特征和构图配方。后台 owner/admin 或 Telegram Bot 管理员可维护共享资产；editor 与普通群友不能改写全 Bot 的画图默认项。

自动注入默认关闭。管理者启用后，可将常用资产设为 pinned；每次生成可以明确跳过默认项或指定排除项。同一资产只注入一次，超过提示词长度限制会报错，不会静默截断。库不可用时可以明确选择跳过素材库后重试。

资产必须标注 `safe` 或 `nsfw`。默认只使用 safe；管理者开启 Bot 的 NSFW 开关并且本次请求明确启用 NSFW 模式后，才能检索和注入 NSFW 资产。此分类用于素材选择，不替代图片供应商的内容策略。

成功使用次数按生成任务计：产物成功保存后，每任务每资产加一；一个任务多张图仍只加一。检索、提交、失败和取消不计数；Telegram 投递重试也不重复计数。任务保存当时的素材快照，之后编辑素材不会改写历史提示词。

删除角色会解除所有相关绑定；解绑不会删除角色。删除前查看受影响的绑定数量。关闭角色沉淀或自动注入开关不会删除已有记录。

导出后再导入 Bot 时，角色、人物档案、资产和生成记录会获得新的 ID，绑定与历史引用会同步转换。导出角色绑定时需同时包含对应的人物档案和角色；缺少依赖时导入会报错并回滚。已删除素材的历史内容仍保留，但不会关联到新建的同编号素材。

素材引用转换不等于完整历史任务恢复：同一实例已有的生成任务标识仍可能导致重复导入失败。

## 图片回执和审计

面板可以配置生成回执文案，并在 Generations 页面查看任务来源、状态、图片数量、错误及相关上下文。调试图片提示词时，只分享经过脱敏的 prompt；图片 URL、任务 ID、模型配置和用户消息仍可能暴露敏感信息。

## 贴纸、视频和其他媒体

Bot 可以理解收到的图片和贴纸，并在启用对应流程时使用贴纸表达回应。动画或视频类贴纸可能只提取元数据或有限的首尾帧，不能假设它会被完整理解。媒体下载和缓存受大小、超时、保留期与 Telegram 限制影响。

如果媒体处理异常：

1. 用普通静态图片或文字消息做对照。
2. 查看 Bot 是否仍在运行，文件缓存是否已被清理。
3. 检查生成任务与 Telegram 投递是否是两个不同的失败阶段。
4. 避免在公开渠道上传原始用户图片；用错误时间和任务状态协助管理员定位。

更多隐私边界见[隐私、历史与记忆](/docs/guides/privacy-memory)。
