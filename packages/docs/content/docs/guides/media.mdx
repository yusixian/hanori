图片链路串联了 Bot 工具、生图 Provider、Telegram 投递和面板记录。建议先在私聊或测试群跑通，再开放群组权限。生图任务是异步的，“已接受”不代表图片已经发到聊天里。

## 两类图片路由

治理与图片设置区分两类用途：

- `anime_illustration`：动漫插画等预设路线，可绑定允许的 preset。
- `general_image`：通用或写实图片，默认可关闭，开启前需配好对应 Provider。

路由按请求意图、启用状态和 preset 过滤。关闭某条路由后，它不再出现在可用列表中，但不影响历史任务记录。

## PixAI

PixAI 是可选的图片 Provider。在受保护配置中填入 API Key 并选好 API 模式（切勿把 Key 放进聊天或前端）。Bot 会创建后台任务、轮询状态、保存结果并把图发回原聊天与原 topic。加载 Skill、查预设、写提示词只是准备阶段，不算提交生成。

遇到失败、超时、成图为空或发送失败时，先去面板 Generations 和日志查原任务，不要盲目重试产生重复计费任务。

## 生成状态与投递状态

用 `/image status <任务 ID>` 或 `get_image_generation` 查询原任务。生成状态与 `deliveryState` 分开展示：

| 观测结果                                   | 含义                                               |
| ------------------------------------------ | -------------------------------------------------- |
| 未调用 `create_image` 或请求被拒           | 尚未提交；准备步骤成功不算“操作完成”               |
| `preparing`                                | 本地已接收，尚未确认供应商接单                     |
| `awaiting_approval` / `queued` / `running` | 已提交：待审批、排队中或生成中                     |
| `succeeded` + `pending` / `sending`        | 已出图，等待或正在投递                             |
| `succeeded` + `failed`                     | 图已保留且确定未发出；排障后可安全重试投递         |
| `attention_required` 或投递 `unknown`      | 生成或发送结果未知，先核对原任务，勿重提或盲目重发 |
| `delivered` 且存在 Telegram 消息回执       | 已交付                                             |

**重试投递**：只有确定未发送的失败任务（包括发送前本地读图或安全检查失败）才可用 `/image retry <任务 ID>` 或 `retry_image_delivery` 重试。重试复用原图、原聊天和原 topic，不重新计费生图，也不重复发已交付任务。投递结果 `unknown`（超时、断连或回执写库失败）不会自动重发；明确的 Telegram 限流会按等待时间重试。

**取消任务**：取消另有 `cancellationState`（`requested`、`rejected`、`unknown`、`confirmed`），只有 `confirmed` 且生成状态为 `cancelled` 才算确认取消。取消被拒、失败或供应商无取消接口时原任务继续跟踪。取消请求在发送前落库标记，重启后若结果不明只恢复查询，不重复发取消；无持久 operation 的通用后端重启中断后标为结果未知，不自动重画。

**正常关停**：停止接新任务、新查询和新删除，取消后续轮询，等已接纳的操作、快照、投递回执和管理员删除收尾后再关数据库。关停不等于远端已取消，强制 kill 不享受等待保证（重启按持久化状态恢复）。

## NSFW 图片遮罩

Bot 在发照片、相册、替换照片和作品图前统一做本地检测，不依赖 AI 自觉：

- 综合分数为 `porn + hentai + sexy`，默认达到 `0.5` 自动加 Telegram 剧透遮罩（沿用 PixAI 配置的 `nsfwThreshold`）。
- 检测超时、返回无效分数或未配置检测服务时，未确认安全的图片一律加遮罩；富文本与流式草稿的内嵌图统一遮罩，普通消息关闭链接预览。
- Telegram 不支持给 document 或 sticker 加同类遮罩，因此检出 NSFW 或无法确认安全的图片附件、贴纸及无法检测的动态贴纸会直接拒绝发送（请改用照片）；普通文档不受影响。

新生成的每张图都会保存真实检测分数或失败状态，可在生成记录的 **技术详情** 中查看 `artifacts[].nsfw`（接口同时返回 `nsfwScores`）。旧已投递图片不重评，旧未投递任务在恢复发送时补检。

## Bot 中的常用操作

```text
/image      # 查看预设、查询或管理任务
/draw       # 按预设发起生图
/imagegen   # 管理群组图片生成权限
```

AI 也可在聊天和治理允许时直接调用 `create_image`。

## 角色与提示词资产

可在「生成素材库」保存角色设定与画风资产，并通过人物档案绑定默认代表形象（按 Bot 隔离，自动注入和 NSFW 默认关闭）。

请求画虚构或作品角色时，不会自动套用请求者的默认代表形象；`personTelegramId` 仅在明确要求画本人或指定群友时使用（“帮我画”不等于画本人）。详见[角色与提示词资产库](/docs/guides/generation-library)。

## 图片回执和审计

面板可自定义回执文案，并在 Generations 页追踪来源、状态、数量和错误。任务持久化原消息/tool call、generation ID、供应商 operation、投递目标和消息回执，重启沿用原幂等 key：

- 同一消息重复提交相同实际输入会复用已有任务（省略默认预设与显式选该预设视为相同；改 prompt、预设、负面提示词或 seed 才会建新任务）。
- 普通状态查询只返回有权限的任务和脱敏字段，不含提示词、供应商原始响应或本地路径。
- 相册附加详情通知失败不会把已拿回执的图片判为未交付。
- 排查提示词时只分享脱敏内容，避免泄露图片 URL、任务 ID、配置或用户消息。

## 贴纸、视频和其他媒体

Bot 可理解收到的静态图和贴纸（并在启用时用贴纸回复）；动画/视频贴纸可能只取元数据或有限首尾帧。媒体下载与缓存受大小、超时、保留期和 Telegram 限制约束。

异常排查顺序：

1. 用普通静态图或纯文字做对照。
2. 确认 Bot 在运行、文件缓存未被清理。
3. 区分“生图失败”与“Telegram 投递失败”两个阶段。
4. 勿在公开渠道发原始用户图片，用报错时间和任务状态给管理员定位。

隐私边界见[隐私、历史与记忆](/docs/guides/privacy-memory)。
