一次 AI 回复通常由四层配置共同决定：Bot 是否启用 AI、当前聊天选择的 Provider 和模型、系统提示词，以及这次请求允许使用的工具。面板负责保存和审计配置，Telegram 命令适合快速查看和切换。

## 查找和分享某个设置

进入 Bot 的 **AI 设置**，在顶部搜索框输入设置名称，例如“超时”、`OCR` 或 `MCP`。搜索覆盖回复行为、记忆、工具、权限与群组中的折叠设置；选择结果会切换到对应分类、展开并定位到该设置。也可以用上下方向键选择结果、Enter 打开，Escape 关闭搜索结果。

打开设置后，地址会包含对应的分类和设置位置。复制当前页面地址，再次打开时可直接回到该设置；浏览器前进、后退也会恢复位置。分享链接不会授予接收者访问权限，也不会包含尚未保存的配置内容。

折叠行在手机上也会保留已有的状态摘要，便于检查开关、模式或数量。搜索和分类切换只负责查找设置；修改配置后仍需按页面提示保存或应用。

## 保存设置与保留草稿

页面顶部会持续显示已保存、未保存、正在保存或操作失败，手机上也能看到。没有更改时 **保存** 不可用；修改后可保存，保存过程中会暂时禁用编辑和重复提交。若按钮不可用，旁边会说明原因。

**当前回复选择** 单独使用 **应用选择**：它决定后续回复实际使用的服务商、模型和小程序展示方式。试选后不想应用，可以点击 **撤销选择草稿**，恢复最近读取到的已保存选择。此操作不撤销其他设置草稿。需要先应用或撤销当前选择，才能保存服务商目录等配置。

搜索设置、切换分类和展开项目会保留当前草稿。带着未保存更改跳转到其他管理页面时，会出现离开确认：**留下并继续编辑** 保留输入，**不保存并离开** 放弃草稿并跳转。主动退出登录前也会先确认；会话失效时仍需重新登录。刷新或关闭标签页时由浏览器提供离开提示。草稿仅保留在当前页面，不会自动保存，也不会包含在分享链接中。

普通保存失败会保留草稿并显示错误，可以修正后重试。若提示配置已经保存、但 Bot 未能应用，请按页面提示重试应用；若提示其他页面已修改配置，请重新载入并核对最新值后再操作。

## 提示词版本

在 **AI 设置 → 回复行为 → 提示词版本** 打开版本管理。先从工作副本或历史版本载入草稿，编辑通用行为、群聊行为、系统提示词、文件及 Skills，再填写名称并保存。**保存不会启用**，适合先保留原版，再制作候选。草稿属于版本管理器，修改草稿不会覆盖其他设置页的工作文件。

版本冻结文件的实际内容、注入开关和总字节上限，以及 Skills 的说明、正文、参考资源和启用状态。默认捕获人格文件和配置的注入文件；不会把数据目录里的动态笔记、报告全部收入版本。可在草稿中新增未注入的 Markdown 参考文件，供 `read_file` 按需读取。Skills 继续通过目录和 `load_skill` 渐进加载，无须把核心人格改成每轮调用的 Skill。

载入候选后，从 **比较基准** 选择原版或工作副本，可查看字段差异，并以当前程序规则重新计算双方私聊、群聊预览及 token 差值。保存时的预览和应用版本也会保留。预览含动态占位，不包含所有工具 schema，估算不等同于完整模型请求用量；程序生成的工具说明升级也可能改变估算。

点击 **启用／恢复此版本** 后，新开始执行的回合读取该版本；正在执行的回合连同后续文件和 Skill 读取继续使用已捕获内容。排队但尚未执行的回合在开始时读取当前版本。启用不重启 Bot，也不覆盖磁盘工作副本。定时任务保持审批后的独立 Agent 配置，并使用任务开始时捕获的 Skill 内容；任务仍不具备 Bot 私有文件或记忆访问权限。

版本不会恢复模型、服务商凭据、工具权限、动态用户或 Bot 记忆，也不会回滚程序生成的工具规则。启用版本内的文件对 AI 文件工具只读；修改设定需管理员编辑版本草稿、另存并启用。其他工作文件仍按现有权限读写。

可以载入旧版本另存，或直接恢复旧版本；若要恢复常规设置页的行为，选择 **切回工作副本**。当前启用版本不能删除，需先切换版本。版本接口仅限 owner/admin，版本按 Bot 隔离。普通顶部提示词预览仍预览设置表单和工作副本；查看实际启用内容请使用版本管理器。

## Provider 和模型

Provider 是模型服务的连接配置；同一个 Provider 可以暴露多个模型。面板会根据当前 Provider 返回可用模型，模型列表和能力标签取决于外部服务以及管理员配置。

新发现模型的能力标签会参考 models.dev 目录；目录中同名模型的能力不一致或没有匹配项时，回退到名称推断。标签是配置参考，不代表已对当前服务商执行能力测试。目录刷新失败或返回无效、空数据时保留上次有效缓存；HTTP 错误响应的未读取正文会被释放，不影响后续刷新；已有模型的手动能力配置不会被覆盖。

每次进入 **服务商与模型** 页面时，面板会自动获取所有已配置服务商的模型列表，并将新模型加入目录，无需再勾选导入。已有模型的名称、能力标签、参数和默认选择会保留；单个服务商获取失败不会清空已有列表，也不影响其他服务商更新。未配置模型发现路径或 API Key 的服务商仍可手动添加模型 ID。

手动移除模型后，该服务商会记录排除的模型 ID，后续自动获取或点击 **刷新模型** 都不会把它加回来。需要恢复时，在 **添加模型 ID** 中重新添加即可；改名也会排除原 ID。模型目录和排除记录沿用页面的 **保存** 流程，保存后才会用于 Bot，并在下次打开时保留。旧版本没有记录删除历史，升级后若曾删除的模型再次出现，需要重新移除并保存一次。

在 Telegram 中：

```text
/provider
/provider 2
/provider reset
/model
/model 2
/model reset
```

没有参数时只查看当前值和可用列表。编号从 `1` 开始；也可以使用模型 ID 或 Provider 名称。切换会写入当前聊天的覆盖值，`reset` 返回 Bot 或工作区默认值。不同实例可能把这些配置限制为管理员，或者允许所有参与者在治理范围内切换。

## 系统提示词和回复行为

系统提示词定义 Bot 的角色、语气和额外约束。修改前先记录原值，保存后在测试私聊和测试群分别验证：同一句问题在不同聊天可能因历史、权限、模型或群配置而不同。

回复模式、富文本增强和 AI 开关是独立设置。`/stop` 会停用 AI 回复并中断当前调用，`/resume` 恢复；管理员也可以在面板中查看 Bot 生命周期状态。停用 Bot 或 AI 不会删除已有对话和日志。

群聊消息补充图片识别等内容时，会清除原内容的检索向量，并为更新后的内容重新生成；迟到的旧结果不会覆盖新内容。内容不变的重复保存保留已有向量，新向量生成失败也不会恢复过期向量。

## 工具能力

根据配置和上下文，AI 可能看到以下工具类别：

- 历史搜索、人物档案和长期记忆；
- 网页搜索或网页读取；
- Telegram 回复、反应、贴纸和媒体操作；
- 图片生成、RSS 阅读和群聊总结；
- MCP 服务器、艺术作品检索和 GitHub 操作。
- 管理员专用的[运行状态、有效配置和请求链路诊断](/docs/reference/runtime-diagnostics)。

工具并不是“模型想用就能用”。运行时会按聊天、用户、Bot、管理员身份和功能开关组装可见工具；具有副作用的工具还会经过一次性保护、用量治理或确认流程。

检索默认通过 `search` 获取摘要，再按需读取引用。在 **AI 设置 → 工具 → 统一检索** 可切回旧工具；支持的来源、分页限制和权限说明见[统一检索指南](/docs/guides/search)。

### 对话选择按钮

AI 发出的选择按钮只接受原聊天、原消息上的有效选项。异常或过期回调不会推进对话；异常回调也不会消耗仍有效的选择。若选择指定了回答者，其他成员不能代答。

同一轮工具调用前后的正文都会保留，避免剧情只剩选择提示或收尾句。选择按钮由工具即时发送；分段回复的正文在本轮生成完成后投递。点击后若当前聊天仍有任务，续写会排队，日志中的 `AI continuation queued` 表示等待执行，并不表示回复已经发送。

若某一步正文已通过 `multi_message` 完整送达，收尾时只补发尚未送达的步骤。只确认部分内容送达时仍保留该步完整正文，避免去重误删尚未发送的内容。

### 步骤数与等待时间

在 **AI 设置 → 记忆 → 对话记忆** 调整主 AI 的最大步骤数，当前默认 128 步；**工具 → Agent 工具** 调整子 Agent 步骤数，当前默认 64 步。步骤是模型与工具交替执行的一轮，可以包含多个工具调用。达到主 AI 的最后一步时，Bot 会保留这一轮用于生成正文。升级后的默认值不会覆盖已经保存的配置；旧 Bot 若仍是 10 步或 15 步，需要在面板修改并保存。

**回复行为 → 超时设置** 控制单轮总等待、单次模型调用、搜索、网页获取、图片生成和子 Agent 等时间。单轮 AI 回复默认最多等待 1 小时；单步计时在工具执行期间暂停，单轮总计时仍继续。插件工具和检索、MCP 工具单次调用各最多等待 10 分钟，仍受当前调用的取消信号和单轮总时限约束。MCP 超时或取消会停止本地等待并向上游传递取消请求。

管理员确认后的 [ASR 转录](/docs/guides/plugins) 在独立后台运行，使用媒体任务自己的时限。PixAI 后台任务使用单独的任务轮询超时设置。

## 成本和失败排查

模型调用、图片生成、总结和 JEV 观察都可能产生外部服务费用。使用面板中的 Usage、日志和治理页面查看次数、并发、冷却以及错误；不要仅根据“消息已发送”判断模型任务完全成功。

常见检查顺序：

1. Provider 是否连接成功，模型列表是否为空。
2. 当前聊天是否保存了过期的 Provider 或模型覆盖。
3. AI 是否被 `/stop`、Bot 生命周期或群组开关停用。
4. 是否命中了用量、并发或冷却限制。
5. 日志中的请求、工具和错误是否显示外部服务拒绝、超时或返回格式错误。

模型在流式生成期间上报错误时，Bot 会立即结束当前模型请求并保留原始错误，避免继续等待连接关闭或本轮超时。已完成的工具调用不会因这类错误自动重放。延长时限可以允许更长的正常处理，但服务商返回的生成错误仍需单独排查。

### 模型等待与超时

一次回复的总超时和每次模型调用的单步超时可在 **AI 设置 → 回复行为 → 超时设置** 中配置。模型请求使用这些超时和取消信号；持续等待模型推理或总结时，客户端不会再额外施加固定五分钟的 HTTP 响应空闲限制。`/stop` 和停止 Bot 仍会中断正在等待的模型请求。

外部服务或其代理也可能主动断开连接，延长本地超时无法改变外部服务的限制。日志中的 `terminated` 是底层连接结束的通用文案，需要继续查看 `cause`：`UND_ERR_BODY_TIMEOUT`、`UND_ERR_HEADERS_TIMEOUT` 和 `UND_ERR_CONNECT_TIMEOUT` 会归类为超时，`UND_ERR_SOCKET` 表示连接断开。超时失败不会自动重跑整轮工具调用；确认工具是否已经执行后，再决定是否重试。

### 缓存用量的含义

一次 AI 回复可能经过多次模型调用，例如先调用工具，再根据工具结果作答。新记录的输入、输出和总 token 按整轮累计；缓存读取和写入也按整轮统计。修复前的历史记录不会自动回填，多步调用的旧记录可能低估总用量，甚至出现缓存 token 命中率超过 100%。

- **缓存观察率**：有完整缓存读取数据的回复数占全部用量记录的比例。
- **缓存 token 命中率**：仅在已观测记录中，用缓存读取 token 除以输入 token。
- **缓存请求命中率**：已观测记录中，缓存读取 token 大于零的回复比例。一次多步回复仍算一条记录。
- **未知与零**：服务明确报告零，才表示已观测到未命中。没有上报、SDK 未保留字段，或任一步骤缺少指标时，该整轮指标保持未知。读取和写入分别判断；没有可用数据时显示 `—`。

OpenAI-compatible 服务可以通过标准 `prompt_tokens_details.cached_tokens` 上报缓存读取量，也支持 DeepSeek 的 `prompt_cache_hit_tokens`。未命中的输入 token 不等于缓存写入 token。部分非标准字段（例如嵌套的 `cache_write_tokens`）可能被当前 SDK 丢弃，不能据此认为写入量为零。

缓存指纹用于比较模型、静态提示词及工具定义，指纹相同并不能证明服务端命中。工具 schema 的 hash 会忽略对象键顺序，但这不保证实际请求的序列化字节相同。

### 验证真实缓存效果

真实模型请求会产生费用。准备验证时，先确定服务、模型、预算，以及该服务的缓存门槛和有效期；使用不含私人信息的专用测试聊天，不要直接拿生产群试验。

1. 固定 Provider、模型、静态提示词和工具集，先执行一次预热，再在有效期内重复对话，分别记录普通回复与工具多步回复。
2. 对照已有日志和用量记录中的 provider、模型、缓存指纹、输入 token、缓存读取／写入量及未知记录数量。
3. 分开报告观察率、请求命中率和 token 命中率，并注明是否排除预热请求、样本数量和测试时间窗口；不能把某项比例直接称为“静态前缀命中率”。
4. 只有真实服务返回的缓存数据才能证明命中。要判断费用收益，还需对照服务实际计费；本地模拟响应只验证采集链路，不证明命中率、延迟或节省金额。

## 诊断时保护隐私

诊断日志可以帮助定位关联请求、工具调用和失败原因，但可能包含有界的消息正文或工具输入输出。分享日志前应先移除用户 ID、消息正文、URL 中的密钥、Cookie、Authorization 头和任何 Token。详见[隐私、历史与记忆](/docs/guides/privacy-memory)。

## 分析已缓存的人物头像

启用人物档案记忆后，AI 可在明确请求下通过 `get_profile_avatar` 读取当前 Bot 缓存的头像，并把图片加入本次视觉上下文。需要回复模型支持图像输入；只支持文本的模型无法保证视觉分析。隐私权限、缓存状态与角色保存步骤见[角色与提示词资产库](/docs/guides/generation-library)。

## 工具步骤与空回复

工具调用与最后的文字回答共用本轮步骤预算。最后一步保留给文字回答，以便 Bot 根据已经取得的字幕或检索结果输出总结。读取插件字幕属于只读操作；模型没有生成正文时，会明确显示“AI 未生成回复内容”，不会把字幕读取当作已经完成总结。实际修改或发送工具成功后，模型仍没有正文时，可以显示操作完成回执。

## 修改 Bot 已发送的消息

可以要求 Bot 修改上下文中带有 `[#消息ID]` 的自身回复。私聊与群聊都会为新保存的 Bot 回复提供 ID；分成多条发送的回复按实际消息分别保存和修改。开启对话历史时，重启后仍可识别这些记录。旧记录如果没有保存 Telegram 消息 ID，不会猜测或补造 ID；历史已清理或不在本轮上下文的目标也不能编辑。

编辑仅允许当前 Bot 在当前聊天发送且本轮可见的消息。普通文本编辑使用 Markdown 转 Telegram HTML，支持粗体、链接和代码块；只有 Telegram 明确拒绝实体格式时才重试纯文本。启用 Rich Message 时，复杂 Markdown 和 LaTeX 使用 Telegram 原生富消息编辑接口；权限、网络或限流错误不会触发重复编辑，也不会另发一条替代消息。照片说明等媒体内容不属于文本编辑工具的支持范围。

编辑成功后，对应历史内容会同步更新；同一轮刚发送的回复也会更新待保存文本。若 Telegram 已修改但历史保存失败，工具明确报告“历史同步失败”，可用相同内容重试修复；不会声称整个操作失败并另发消息。关闭历史或隐私设置不允许持久化时，不会为编辑额外保存聊天内容，也不能保证重启后的定位。

## 在聊天中总结历史

可以自然语言要求 Bot 总结当前聊天/话题的指定时段，并说明要关注的决定、待办或主题。`summarize_chat` 调用独立总结模型，支持既有最近条数、小时、今天/昨天模式，也支持带时区的明确起止时间和本次要求。它只返回摘要供当前 Agent 作答，不额外发送一份消息；权限、总结开关和手动冷却与总结服务一致。隐私关闭或隔离的当前回合不会注册这个跨消息总结工具。

工具不会读取其它聊天或话题；用户不能通过模型参数指定另一身份。长历史在服务端分块归并，返回 `coverage` 区分确认的数量截断和未知采集覆盖。`complete=true` 不承诺拥有 Telegram 的全部历史。具体边界及不发送消息的预览入口见[自动化指南](/docs/guides/automation)。

## 视频与音频的聊天上下文

视频、动图、音频、语音和视频笔记会保留说明文字（caption）、转发来源和标明“未解析媒体内容”的占位。群聊开启历史后，即使消息没有触发回复，也会保存这些信息；未使用持久历史时，后续追问能否看到它取决于近期群聊上下文设置与缓冲窗口。转发来源与实际发送者分别记录，转发内容不会归入发送者的个人历史投影。

说明文字中的 @Bot、关键词和回复 Bot 沿用现有触发及隐私规则。随后说“分析一下这个”时，AI 可以根据可见说明文字、链接和来源回应，但这不代表它已看过视频或听过音频。这条接收路径不会自动下载媒体、转写语音或分析视频帧；没有足够文字时，需要补充说明。图片、文件和贴纸沿用原有处理方式。

论坛群的近期上下文和本轮持久历史按话题隔离。全群压缩摘要没有话题归属，因此论坛话题请求只使用同话题仍保留的原始历史，不注入混合摘要；缺少话题标记的旧记录不会猜测归属，已被清理的旧内容可能无法找回。

## 其他 Telegram 内容

Story、付费媒体、投票、联系人、位置、地点、骰子、游戏、清单和富文本消息也会进入聊天上下文与已启用的群聊历史。Bot 保留 Telegram 提供的可见文字、链接、来源与必要元数据；富文本中的嵌套段落、列表、表格和媒体说明会转换为文本。投票票数是收到时的快照，选项计数为 0 也可能表示未知；实时位置只保留收到时坐标，不持续追踪。

Story 和付费媒体使用明确的未解析占位，不自动观看、购买或下载。富文本、投票与游戏里的媒体附件也不会自动解析；实况照片的静态图片沿用图片处理，动态部分标为未解析。联系人只保留姓名与电话号码，不将整份 vCard 放入 AI 上下文。所有内容继续遵守群聊授权、隐私设置与话题隔离；清单变更通知、支付回执等服务事件不会因此触发聊天。

新内容沿用现有私聊、关键词和回复触发规则；接收内容不等于一定主动回复。文字追问与局部引用可读取相应内容，局部引用不会重新附上未选中的整段富文本。入口日志仅记录有限的内容类型，不记录群聊正文、电话号码、坐标或原始更新。旧日志中的 `other` 不能用来确定当时的消息类型，已经跳过且未保存的旧消息也不会自动补回。

## 回复消息中的局部引用

在 Telegram 中选中原消息的一句话并回复时，Bot 会将选中的文字明确标为“局部引用”，作为本轮上下文数据，与当前输入区分。引用说明优先展示选中的片段，不再重复附上整段原文；原消息的附件说明仍会保留。群聊历史和排队期间合并的连续消息使用同样的引用内容。

没有选中文字或引用为空时，仍使用被回复消息的正文或附件说明。跨聊天回复等场景如果 Telegram 只提供引用片段、没有原消息，Bot 会保留片段，但不推测原作者，也不会自动获取原消息。

### AI 语录工具

实际语录渲染服务健康且个人化允许时，聊天 Agent 可使用 `create_quote_sticker`。参数 `message_ids` 必须来自本轮可见的真实消息；可选 `quote_text` 必须是单条原文子串，不能改写。工具使用本轮内容快照，后续编辑不会替换原文。`include_reply_preview` 也只引用本轮可见的父消息；没有来源时明确省略。`color` 支持命令中的预设与十六进制配色。

工具每回合最多发送一次，成功返回消息 ID、格式和实际条数。工具已发送后不需要再发同一张图；回执保存失败会单独标记，不重新发送。没有语言模型配置也可手动使用 `/q` 和 `/qcolor`。工具不会自动打开隐私权限，也不从格式化对话文本猜测作者或消息来源。
