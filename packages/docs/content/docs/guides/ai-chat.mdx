一次 AI 回复由四层配置共同决定：Bot 是否开启 AI、当前聊天选用的 Provider 与模型、系统提示词，以及本轮允许使用的工具。面板用来集中配置和审计，Telegram 命令适合随时查看和切换。

## 查找和分享某个设置

进入 Bot 的 **AI 设置**，在顶部搜索框输入关键词（如“超时”、`OCR`、`MCP`），可直接定位到回复行为、记忆、工具、权限与群组中的折叠项。支持方向键选择、Enter 打开、Escape 关闭。

打开某项设置后，地址栏会记录对应分类与位置，复制链接即可直达（浏览器前进/后退同样生效）。分享链接不包含访问权限，也不会带上未保存的草稿。折叠行在手机端同样保留状态摘要；搜索和切换分类只负责定位，改动仍需手动保存或应用。

## 保存设置与保留草稿

页面顶部会持续显示已保存、未保存、保存中或失败状态（手机端可见）。无改动时 **保存** 按钮禁用，旁边会标注原因；提交过程中会锁定编辑防止重复提交。

**当前回复选择** 独立使用 **应用选择** 生效，决定后续回复的服务商、模型和小程序展示方式。想放弃试选可点 **撤销选择草稿**（不影响其他设置草稿）。改动过当前选择时，需先应用或撤销，才能保存服务商目录等其他配置。

草稿在搜索、切换分类和展开折叠项时会保留，但只存在当前页面，不会自动保存：

- 带着未保存更改跳转其他管理页时，会弹出确认：**留下并继续编辑** 或 **不保存并离开**。
- 主动退出登录前会确认；刷新或关闭标签页由浏览器提示；会话失效仍需重新登录。
- 保存失败时保留草稿并报错，修正后可重试。若提示“已保存但 Bot 未能应用”，按提示重试应用；若提示其他页面已修改，先重新载入核对最新值。

## 重试与备用模型

在 **AI 设置 → 服务商与模型 → 重试与备用模型** 配置请求恢复策略：

- **每回合额外重试次数**：0–2 次，默认 1 次。同一回合内的多个模型步骤共享预算，不叠加 SDK 内部重试。
- **备用模型**：默认关闭，需明确选择服务商及其目录中已有的模型并保存。不会修改主模型，也不会自动挑选服务商。

在 **权限与群组 → 群组独立配置** 中展开指定聊天，勾选 **单独设置此聊天的恢复策略** 可覆盖全局值：关闭备用模型即仅用主模型，取消勾选则恢复继承。目录改名会同步更新引用；删除服务商后需重新选择或关闭对应备用模型。

遇到可恢复故障时，先在回合预算内重试，再尝试一次不同的已配置备用模型（同一服务商+模型不重复尝试）。取消、权限错误或确定的配置错误不重试；已开始输出正文或工具参数的步骤不重放。恢复时保留已完成的工具结果，不重复执行有副作用的工具。

该策略仅作用于聊天及其续写路径，不覆盖定时任务、群总结或子代理。日志会区分重试、切换模型和最终失败。

## 提示词版本

在 **AI 设置 → 回复行为 → 提示词版本** 打开版本管理。可从工作副本或历史版本载入草稿，编辑通用行为、群聊行为、系统提示词、文件及 Skills 后命名保存。**保存不会立即启用**，草稿改动也不影响其他设置页的工作文件。

版本会冻结以下内容：

- 人格文件和配置的注入文件（含实际内容、注入开关、总字节上限），以及在草稿中新增、供 `read_file` 按需读取的未注入 Markdown 参考文件。数据目录里的动态笔记和报告不会收入版本。
- Skills 的说明、正文、参考资源和启用状态。Skills 仍通过目录与 `load_skill` 按需加载。

在 **比较基准** 中选择原版或工作副本，可查看字段差异，并按当前程序规则重新计算私聊/群聊预览及 token 差值（预览含动态占位、不含完整工具 schema，与真实请求用量存在差异）。

点击 **启用／恢复此版本** 后：

- 新回合读取该版本，排队未开始的回合按启动时的当前版本执行，正在进行的回合继续沿用已捕获内容。
- 不重启 Bot，也不覆盖磁盘工作副本。定时任务保持审批后的独立配置及启动时捕获的 Skill，仍不能访问 Bot 私有文件或记忆。
- 启用版本内的文件对 AI 文件工具只读；修改设定需管理员编辑草稿、另存并启用。

版本不恢复模型、凭据、工具权限、动态记忆或程序生成的工具规则。要回到常规设置页行为，选 **切回工作副本**。当前启用版本不可删除，需先切换。版本按 Bot 隔离，仅限 owner/admin 操作。顶部普通提示词预览只反映表单与工作副本，查看实际生效内容请用版本管理器。

## Provider 和模型

一个 Provider 对应一套模型服务连接配置，可挂载多个模型。新发现模型的能力标签优先参考 models.dev 目录，无匹配或同名冲突时回退到名称推断（仅作参考，不代表已实测）。目录刷新失败或数据无效时保留上次有效缓存，已有手动配置不会被覆盖。

进入 **服务商与模型** 页面时，面板会自动拉取已配置服务商的模型列表并加入目录，无需手动勾选导入。已有模型的名称、标签、参数和默认选择都会保留；单个服务商失败不影响其他服务商。未配置发现路径或 API Key 时，仍可手动添加模型 ID。

手动移除模型（或改名）后，原 ID 会记入排除列表，后续自动拉取或 **刷新模型** 不会再加回；需要恢复时通过 **添加模型 ID** 重新加入即可。目录与排除记录随页面 **保存** 生效。旧版本未记录删除历史，升级后若已删模型重新出现，再移除并保存一次即可。

Telegram 中可随时查看或覆盖当前聊天的设置：

```text
/provider
/provider 2
/provider reset
/model
/model 2
/model reset
```

不带参数时列出当前值与可选项。支持从 `1` 开始的编号、模型 ID 或 Provider 名称；`reset` 恢复默认。不同实例可能将权限限制为管理员，或在治理范围内对成员开放。

## 系统提示词和回复行为

系统提示词决定 Bot 的角色、语气和约束。改动前先记下原值，保存后分别在测试私聊和测试群验证。

回复模式、富文本增强和 AI 开关彼此独立。`/stop` 停用 AI 并中断当前调用，`/resume` 恢复；停用不会删除已有对话和日志。

群聊消息补充图片识别等内容后，会清除旧检索向量并重新生成；迟到的旧结果不会覆盖新内容，内容未变时保留原向量，新向量生成失败也不会回退到过期向量。

## 工具能力

根据配置和权限，AI 可调用的工具包括：

- 历史搜索、人物档案和长期记忆
- 网页搜索与网页读取
- Telegram 回复、反应、贴纸和媒体操作
- 图片生成、RSS 阅读和群聊总结
- MCP 服务器、艺术作品检索和 GitHub 操作
- 管理员专用的[运行状态、有效配置和请求链路诊断](/docs/reference/runtime-diagnostics)

工具按聊天、用户、Bot、管理员身份和功能开关动态组装；有副作用的工具还受一次性保护、用量治理或确认流程约束。

检索默认走统一 `search` 先拿摘要再按需读原文，可在 **AI 设置 → 工具 → 统一检索** 切回旧工具；来源、分页和权限见[统一检索指南](/docs/guides/search)。

### 对话选择按钮

AI 发出的选择按钮仅在原聊天、原消息上有效。过期或异常回调不会推进对话，也不会消耗有效选项；若指定了回答者，其他人不能代点。

工具调用前后的正文都会保留，按钮由工具即时发出，分段正文在本轮生成完成后投递。点击按钮时若当前聊天仍在处理其他任务，续写会排队（日志中的 `AI continuation queued` 仅表示已入队）。某步正文已通过 `multi_message` 完整送达时，收尾只补发未送达步骤；只确认部分送达时保留整步正文，避免误删。

### 步骤数与等待时间

- **最大步骤数**：主 AI 在 **AI 设置 → 记忆 → 对话记忆** 配置（默认 128 步，最后一步保留给正文回答）；子 Agent 在 **工具 → Agent 工具** 配置（默认 64 步）。升级不会覆盖已保存的旧值（如 10 步或 15 步），需手动修改保存。
- **超时设置**：在 **回复行为 → 超时设置** 调整单轮总等待（默认 1 小时）、单步模型调用、搜索、网页读取、生图和子 Agent 时限。单步计时在工具执行期间暂停，总计时继续。插件工具、检索和 MCP 单次调用各上限 10 分钟，受总时限和取消信号约束；MCP 超时或取消会向上游传递取消。
- 管理员确认后的 [ASR 转录](/docs/guides/plugins) 与 PixAI 后台任务各自使用独立时限。

## 成本和失败排查

模型调用、生图、总结和 JEV 观察都会产生外部费用，可通过面板的 Usage、日志和治理页排查。

排查顺序：

1. Provider 是否连通，模型列表是否非空。
2. 当前聊天是否残留了过期的 Provider 或模型覆盖。
3. AI 是否被 `/stop`、Bot 生命周期或群组开关停用。
4. 是否触发了用量、并发或冷却限制。
5. 日志中是否有外部服务拒绝、超时或格式错误。

流式生成期间收到模型报错时，Bot 会立即中止请求并保留原始错误，不重放已完成的工具调用。

### 模型等待与超时

推理或总结长时间等待时，客户端不再施加固定 5 分钟 HTTP 空闲断开限制，完全按 **超时设置** 和取消信号控制（`/stop` 与停止 Bot 仍可立即中断）。

若外部服务或代理主动断连，调大本地超时无效。日志出现 `terminated` 时需看 `cause`：`UND_ERR_BODY_TIMEOUT`、`UND_ERR_HEADERS_TIMEOUT`、`UND_ERR_CONNECT_TIMEOUT` 属于超时，`UND_ERR_SOCKET` 表示连接断开。超时后不会自动重跑整轮工具，先确认副作用工具是否已执行再决定重试。

### 缓存用量的含义

多步调用的输入、输出、总 token 及缓存读写均按整轮累计。修复前的历史记录不会回填，旧多步记录可能低估总量或出现缓存命中率超过 100%。

- **缓存观察率**：具备完整缓存读取数据的回复占全部记录的比例。
- **缓存 token 命中率**：已观测记录中，缓存读取 token ÷ 输入 token。
- **缓存请求命中率**：已观测记录中，缓存读取 token > 0 的回复比例（多步算一条）。
- **未知与零**：仅服务明确上报 0 才计为未命中；未上报、SDK 丢弃字段或任一步缺失则保持未知，无数据时显示 `—`。读写分别统计。

OpenAI-compatible 服务支持标准 `prompt_tokens_details.cached_tokens` 及 DeepSeek 的 `prompt_cache_hit_tokens`。未命中输入不等于缓存写入；部分非标准字段（如嵌套的 `cache_write_tokens`）可能被 SDK 丢弃，不能据此认定写入为 0。缓存指纹只比对模型、静态提示词和工具定义（忽略 schema 键序），指纹一致不保证服务端命中。

### 验证真实缓存效果

先确认目标服务的缓存门槛、有效期与预算，在不含隐私的测试聊天中验证：

1. 固定 Provider、模型、静态提示词与工具集，先预热一次，再在有效期内重复测试普通回复和多步工具回复。
2. 对照日志和用量记录中的缓存指纹、输入 token、缓存读写量与未知记录数。
3. 分别记录观察率、请求命中率、token 命中率，以及样本量、时间窗口和是否排除预热。
4. 实际省钱效果以服务商账单为准，本地模拟响应只能验证采集链路。

## 诊断时保护隐私

分享诊断日志前，务必清理用户 ID、消息正文、URL 中的密钥、Cookie、Authorization 头和 Token。详见[隐私、历史与记忆](/docs/guides/privacy-memory)。

## 分析已缓存的人物头像

开启人物档案记忆且回复模型支持视觉输入时，可明确让 AI 通过 `get_profile_avatar` 读取当前 Bot 缓存的头像并加入本次视觉上下文。权限、缓存状态和保存角色步骤见[角色与提示词资产库](/docs/guides/generation-library)。

## 工具步骤与空回复

工具调用和正文回答共用步骤预算，最后一步保留给文字输出。读取插件字幕等只读操作完成后，若模型未输出正文，会提示“AI 未生成回复内容”；只有实际修改或发送类工具成功且无正文时，才会显示操作完成回执。

## 修改 Bot 已发送的消息

可让 Bot 修改本轮上下文中带有 `[#消息ID]` 的自身回复（私聊与群聊的新回复均记录 ID，多条分段分别记录；开启历史时重启后仍可识别）。未记录消息 ID、历史已清理或不在本轮上下文的消息不可编辑；媒体说明（caption）不支持文本编辑。

普通文本编辑将 Markdown 转为 Telegram HTML，仅在 Telegram 拒绝实体格式时回退纯文本；开启 Rich Message 时，复杂 Markdown 和 LaTeX 走原生富消息编辑接口。权限、网络或限流错误不重试也不另发替代消息。

编辑成功后会同步更新历史记录。若 Telegram 已改完但历史写入失败，会提示“历史同步失败”，可用相同内容重试修复。未开历史或隐私禁止持久化时，不会为此额外存库。

## 在聊天中总结历史

可直接用自然语言让 Bot 总结当前聊天或话题的指定时段，并附带关注重点。`summarize_chat` 调用独立总结模型，支持最近条数、小时、今天/昨天及带时区的起止时间，结果只返回给当前 Agent 作答，不额外发消息。权限、开关和冷却与总结服务一致；隐私关闭或隔离回合不注册此工具。

该工具不跨聊天或话题，也不接受覆盖身份的参数。长历史在服务端分块归并，返回 `coverage` 标注是否触发数量截断（`complete=true` 仅代表已读完本地可访问记录，不代表拥有 Telegram 全历史）。详见[自动化指南](/docs/guides/automation)。

## 视频与音频的聊天上下文

视频、动图、音频、语音和视频笔记会保留说明文字（caption）、转发来源和“未解析媒体内容”占位。群聊开启历史后即使未触发回复也会记录；转发来源与实际发送者分开记录，不混入发送者个人历史。

说明文字中的 `@Bot`、关键词和回复触发沿用原有规则。后续追问时 AI 只能依据可见文字、链接和来源作答，不会自动下载媒体、转写语音或抽帧。

论坛群的近期上下文和持久历史严格按话题隔离。全群压缩摘要没有话题归属，因此话题请求只用同话题的原始历史；缺话题标记的旧记录不猜测归属。

## 其他 Telegram 内容

Story、付费媒体、投票、联系人、位置、地点、骰子、游戏、清单和富文本消息也会进入上下文和群历史，保留可见文本、链接、来源与必要元数据（富文本结构会拍平为纯文本；投票票数和实时位置仅记录收到时快照；联系人只保留姓名与电话，不传整份 vCard）。

Story、付费媒体及富文本/投票/游戏中的附件标为未解析，不自动下载或观看；实况照片的静态图按图片处理，动态部分标为未解析。服务事件（清单变更、支付回执等）不触发聊天。入口日志只记内容类型，不记正文、电话、坐标或原始更新；旧日志中的 `other` 无法反推原类型。

## 回复消息中的局部引用

在 Telegram 中选中原消息片段并回复时，Bot 会把选中内容标为“局部引用”，不再重复附带整段原文，但保留原消息的附件说明。群历史与排队合并的连续消息采用相同处理。跨聊天回复若 Telegram 只给引用片段、没有原消息，则只保留片段，不推测原作者。

### AI 语录工具

语录渲染服务健康且个人化允许时，Agent 可调用 `create_quote_sticker`。`message_ids` 必须来自本轮可见真实消息；`quote_text` 须为单条原文精确子串；`include_reply_preview` 仅引用本轮可见父消息；`color` 支持命令预设和十六进制配色。

每回合最多发送一次，发送后不重复发图；回执保存失败会单独标记。无 LLM 配置时仍可手动用 `/q` 和 `/qcolor`。
