---
title: 统一检索
description: 通过统一入口检索多个来源、按需分段读取，以及在面板回退旧工具。
---

在 Bot 的 **AI 设置 → 工具 → 统一检索** 中可开关该入口（默认开启，修改后需保存；关闭则切回原来的独立搜索工具）。该开关只改变 AI 调用方式，各来源仍需各自配置和授权。

## 先检索摘要，再读详情

直接对 Bot 说要找什么即可（如“查一下刚才说的部署问题”或“找角色库里的这个角色”）。AI 会先调用 `search` 获取有界摘要，需要细节再用 `read_reference` 分段读取引用。

引用仅在当前一轮回复或委派任务内有效，过期、被缓存淘汰或进入新一轮对话后需重新搜索，且不跨聊天或跨用户生效。

## 支持的来源

| 来源       | `scope`         | 查询范围与边界                                                        |
| ---------- | --------------- | --------------------------------------------------------------------- |
| 网页       | `web`           | 已配置搜索服务的标题、链接和摘要；读完整网页仍用网页读取工具。        |
| 聊天历史   | `history`       | 当前 Bot、当前聊天的历史，无法跨聊天查询。                            |
| 人物档案   | `profiles`      | 原档案服务可见的资料。                                                |
| 长期记忆   | `memory`        | 受当前用户、聊天与记忆权限约束。                                      |
| 角色       | `characters`    | 本地角色库或 Danbooru 标签（按来源区分）。                            |
| 提示词资产 | `prompt_assets` | 当前身份有权查看的资产。                                              |
| GitHub     | `github`        | 已授权仓库的 Issue 列表或文件树（在有界列表内筛选，非全站代码搜索）。 |
| 艺术作品   | `artwork`       | 从受支持的作品链接读取信息；发图需另调发送工具。                      |

- 同一 `scope` 有多个来源时，AI 需显式指定 `provider`。未授权或已关闭的来源（如关闭个性化记忆）不会因开启统一检索而开放；研究助手仍限于网页、角色和资产来源。
- GitHub Issue、文件树和提示词资产可省略关键词直接浏览列表，其余来源必须提供关键词或作品链接。
- 本地角色和提示词资产支持分页，其余来源目前只返回一页有界结果（单次最多 **20 项**，部分来源上限更低）。返回结果会区分“还有下一页”和“已被截断”。

## 行为与状态

- 返回状态包括：成功、无匹配、来源不可用、权限不足、限流、上游错误和参数无效。
- 统一检索**只读无副作用**：不会保存角色、更新查询计数、沉淀 Danbooru 资产、发消息或启动下载/转录任务（旧工具模式保留原有行为）。
- 检索结果与正文视为外部不可信资料，其中要求执行操作、泄露配置或提权的指令均不生效。

## 排查与回退

1. 核对底层来源是否可用（如网页搜索配置、GitHub 仓库权限、记忆开关）。
2. 查看工具诊断日志中的查询、状态、分页和条数（统一检索的结果正文和完整链接不进普通工具日志，但输入的搜索词不视为秘密）。
3. 如影响现有流程，在面板关闭 **统一检索** 并保存，确认 Bot 已加载新配置。

中途停止回复会中止统一检索并阻止迟到结果建引用，但部分旧来源无法取消已发出的底层网络请求，外部服务仍可能计费。
