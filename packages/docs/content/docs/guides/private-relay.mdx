---
title: 管理员私聊代发
description: 配置 /cosinside 目标群、回复指定消息及历史写入规则。
---

`/cosinside` 允许管理员通过 Bot 私聊向预先配置的 Telegram 群发文字。命令只认配置的别名、不接受原始 Chat ID，避免误发到其他群。

## 配置目标

在 Bot 编辑页的**私聊代发目标**中添加群组，每条包含：

- **别名**：1–32 位，仅支持字母、数字、连字符和下划线（不区分大小写，不可重复）；
- **群 ID**：负整数，且 Bot 已进群并有发言权。

面板会优先列出 Bot 已识别的群，也支持手动填 ID（最多配置 **20** 个）。未配置目标时 `/cosinside` 会提示不可用；清空目标并保存即停用入口。保存目标后，运行中的 Bot 可能会自动重启以应用变更。

## 命令格式

```text
/cosinside <别名> <正文>
/cosinside <别名> reply:<消息ID> <正文>
```

示例：

```text
/cosinside ops 明早九点发布维护通知
/cosinside ops reply:1234 请在这条消息下补充结果
```

只配置了一个目标时可省略别名：

```text
/cosinside 单一目标的通知正文
```

`reply:<消息ID>` 会回复目标群里的指定消息（消息 ID 必须属于该群，否则发送失败）。目前仅支持纯文本命令，不支持写在图片或文件 caption 中。

## 权限与限制

- 仅限管理员在私聊中使用，服务端和 Bot 运行时双重鉴权。
- 单条正文最多 **4,000 字符**；每管理员每 **60 秒** 最多尝试 **5 条**。超长、未知别名、无目标或限流时直接拒绝。
- 审计日志只记目标、别名、发起人、正文长度、是否带回复以及结果状态，**不保存正文**。

## 发送与写入历史

Telegram 发送成功后，若目标群开启了对话历史，消息会记入上下文并标注为“管理员代发的人类消息”（带发起人 Telegram ID 与显示名），AI 不会将其误认为自己的回复。

- 目标群关闭对话历史时，消息照常发出但不进 AI 上下文。
- 发送成功但写历史失败时，Bot 会提示“已代发但历史保存失败”，不会重复发送。
- 发送本身失败时返回截断原因，勿盲目连发重试。

## 上线前核对

1. 只加必要目标群，起清晰别名。
2. 用测试文案验证普通发送和 `reply:` 回复。
3. 在群里确认 Bot 能正常发言且回复指向正确消息。
4. 如需 AI 感知代发内容，确认目标群已开启对话历史。
