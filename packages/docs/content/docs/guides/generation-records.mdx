---
title: 生成记录与问题恢复
description: 查找图片任务、查看参数，并确认读取和删除结果。
---

在 Bot 工作区打开 **生成记录**，可以回查该 Bot 的图片任务、Prompt、参数、任务状态和仍保留的图片。访问和删除遵循管理面板的账号权限。

## 查找任务

搜索支持任务 ID、Prompt、预设标识和 Provider 名称，忽略大小写与首尾空白，最多200字符。可以组合状态、来源和日期筛选，再用底部分页继续浏览；总数对应完整筛选结果。

**当前生图任务** 与 **旧版 PixAI** 是不同来源。进入详情后，可以查看任务时间线和复现参数；旧记录只展示当时保存的信息。图片已经按保留策略清理时，页面仍可能保留任务元信息，详见[隐私、历史与记忆](/docs/guides/privacy-memory)。

自动清理过期图片遇到权限或存储故障时，会保留该记录的文件引用，待后续清理周期重试；其他记录仍继续处理。已不存在的文件视为清理完成，任务元信息仍保留。

## 供应商与任务恢复

任务会记录实际使用的 PixAI、GPT 或 Gemini，切换用途的默认供应商不会重定向旧任务。供应商请求超时且无法确认是否接单时，平台冻结任务供 owner 核查，Bot 不会自行改用另一供应商。存图失败时平台复用已经保存的供应商结果恢复，不重新发起生图。

旧版 PixAI 图片保存与清理只接受生成目录中的单个有效文件名。任务 ID 或文件记录包含目录跳转、嵌套路径或空字节时，会跳过该文件并记录错误；同批其他正常图片仍继续处理。

## 加载失败时

首次读取失败会显示错误和 **重试**，不会把失败当作“没有生成记录”。已有内容刷新失败时，页面会保留同一条件下的旧内容，并提示它可能不是最新结果。

切换来源、搜索或分页后，显示的结果属于新条件；旧请求较晚返回时不会覆盖当前结果。重新读取成功后再确认总数和任务状态。

## 删除与核对结果

删除前会要求确认。只有允许删除的结束状态才能操作；活动任务需要先处理其运行状态。删除会移除任务记录，并尝试清理仍保留的本地图片文件；Telegram 中已经收到的消息仍保留。

删除进行中，相关操作暂时禁用，避免重复提交。遇到连接或服务错误时，页面会保留记录并提示删除结果尚未确认。先使用 **刷新并核对**，它只重新读取原任务和当前范围，不会自动再次删除；核对失败时继续保留提示。

若列表提示 **已删除，但未能刷新页面数据**，表示删除已经确认，后续读取失败。此时刷新核对只需重新读取当前列表，避免对旧卡片再次发起删除。

核对未确认的删除时，若服务端确认原记录已经不存在，列表会说明这一状态，详情页会返回生成记录列表；这不表示先前某次未确认的删除一定成功。若原记录仍存在，读取成功后可以继续操作。

## 从记录返回生成流程

记录中的参数用于回查与复现，实际再次生成仍受当前模型、预设、额度和权限约束。角色与画风素材的维护见[角色与提示词资产库](/docs/guides/generation-library)；排查整体配置可回到[管理面板导航](/docs/guides/panel-navigation)。
