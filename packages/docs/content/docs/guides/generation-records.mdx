title: 生成记录与问题恢复
description: 查找图片任务、核对参数，以及处理读取和删除异常。
---

在 Bot 工作区的 **生成记录** 中，可查看该 Bot 的图片任务、Prompt、参数、状态和本地保留的图片。访问和删除受管理面板权限控制。

## Telegram 生图确认

确认卡展示提示词、负面提示词、后端、预设、Seed 以及尺寸、比例和质量（未指定项显示“默认”，长提示词截断并标出总字数）。修改提示词或 Seed 后可在卡片上核对草稿再确认；确认前后共用同一个任务 ID，方便在生成记录中追踪。

## 查找任务

搜索支持任务 ID、Prompt、预设标识和 Provider 名称（忽略大小写与首尾空白，上限 200 字符），可组合状态、来源、日期筛选与分页。

**当前生图任务** 与 **旧版 PixAI** 是分开的来源。点进详情可查看时间线和复现参数；图片按保留策略清理后，任务元信息仍会保留，详见[隐私、历史与记忆](/docs/guides/privacy-memory)。自动清理过期图片遇到权限或存储故障时，会保留文件引用待下个周期重试，不阻断同批其他记录；文件已不存在则直接视为清理完成。

## 供应商与任务恢复

每个任务记录实际使用的 PixAI、GPT 或 Gemini，后续切换默认供应商不影响旧任务。供应商请求超时且无法确认是否接单时，任务会冻结供 owner 核查，Bot 不会私自改走其他供应商。存图失败时，平台复用已拿到的供应商结果恢复，不重新生图。

旧版 PixAI 的保存与清理仅接受生成目录下的单个合法文件名；含目录跳转、嵌套路径或空字节的记录会跳过并报错，不影响同批其他正常图片。

## 加载失败时

首次加载失败会显示错误与 **重试**，不会误判成空列表。已有内容刷新失败时，页面保留当前条件下的旧数据，并提示可能已过期。

切换来源、搜索或翻页后，迟到的旧请求不会覆盖新条件的结果；等新请求成功后再核对总数和状态。

## 删除与核对结果

删除前需要确认，仅允许对已结束状态的任务执行（活动任务需先处理运行状态）。删除会移除任务记录并尝试清理本地图片，已发到 Telegram 的消息不受影响。

删除进行中会暂时禁用相关操作防止重复提交。若遇连接或服务错误，页面保留记录并提示结果未确认：此时点击 **刷新并核对**，只重查原任务和当前列表，不会再次发起删除。

若列表提示 **已删除，但未能刷新页面数据**，说明删除已确认、只是后续列表刷新失败，直接刷新核对即可，不要对旧卡片重复点删除。

核对未确认的删除时，若服务端返回原记录已不存在，列表会提示该状态，详情页退回列表（注意这不直接等同于前一次未确认请求一定成功）；若记录仍在，刷新后可继续操作。

## 相关入口

记录里的参数用于回查与复现，重新生图仍受当前模型、预设、额度和权限约束。维护角色与画风见[角色与提示词资产库](/docs/guides/generation-library)，排查全局配置见[管理面板导航](/docs/guides/panel-navigation)。
