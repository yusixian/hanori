实例所有者或管理员可在 **插件** 页安装扩展，再按 Bot 单独配置和启用。安装与启用分两步：装好插件不会自动向所有 Bot 开放工具。

## 安装可信插件

在 **插件** 页选择内置插件，或填入公开 GitHub 仓库及提交：

- 第三方来源仅接受 `https://github.com/owner/repository` 和完整 **40 位小写 Git SHA**，不支持分支名、tag、短 SHA、私有仓库、带凭据 URL 或子目录。
- 目标提交必须包含已构建产物，服务端不会自动装依赖或跑构建脚本。

> 安装前需确认授权服务端访问。插件代码直接运行在 Hanori 服务端进程内，**不是沙箱**；工具上的“只读”标记仅限制模型可见能力，无法隔离插件代码本身。只安装审核过的可信提交。

## 为 Bot 配置和启用

1. 选择已安装插件和目标 Bot，填写配置字段。
2. 先保存配置，再启用（必填项未齐可存为停用草稿，但无法启用）。
3. 在测试聊天中发真实输入验证返回结果。

各 Bot 配置相互独立。启用后工具仍按身份和上下文过滤：管理员专用工具不对普通用户开放，只读上下文只暴露只读工具。

- **秘密字段**：Cookie、API Key 等加密存储，保存后仅显示“已配置”不回显；留空保留原值，点清除才删除。保存前仅暂存于页面内存，不写浏览器本地存储。
- **测试已保存配置**：仅针对已保存且启用的配置运行。有检查钩子时执行钩子，否则只校验能否创建会话；通过测试不代表 Cookie 有效或外部资源可访问。
- **并发与变更**：清单变更后，已有 Bot 配置需重新审核并保存才会生效。保存修改、更新、卸载或停服都会取消旧会话，迟到结果不再建立引用。
- **超时**：单次工具或检索调用最多等 **10 分钟**，并同时受调用方取消信号和 AI 单轮总时限约束（确认后的后台 ASR 见下文独立时限）。

### 扫码登录并保存 Cookie

Bilibili 和网易云音乐插件在 Bot 配置页提供 **扫码登录**：

1. 先保存当前配置草稿（有清单变更提示时先审核保存）。
2. 点 **扫码登录**，用对应平台手机 App 扫码并确认。
3. 面板显示已连接后，服务端校验账号并将 Cookie 加密存到当前 Bot，原文不返回前端。

- 插件停用时也能扫码，扫码不会自动启用插件、ASR 或视频下载；重登仅替换凭据，保留其他配置，并取消依赖旧配置的未完成任务（已开始上传到 Telegram 的视频无法撤回）。
- 二维码最多有效 **5 分钟**（平台可能更早过期）。保存开始前关闭弹窗可取消，失败或过期不覆盖旧 Cookie；一旦进入保存阶段关闭窗口不会撤销。如提示无法确认结果，刷新配置页再决定是否重试。
- 扫码由服务端发起，不读取本机浏览器登录态，也不保存账号密码；如遇风控可改用手动填写 Cookie。目前无后台自动续期，失效需重登。
- Bilibili 确认后优先用扫码返回的 Cookie 校验，仅返回跨域票据时再兑换校验；游戏站跳转参数不会被误存为 Cookie。

## 更新、回滚与卸载

- **更新**：第三方插件需指定新的完整提交 SHA，不自动追踪分支；若清单变化，需逐个 Bot 重新审核配置。内置插件随 Hanori 版本更新。
- **回滚**：切回保留的上一版提交与清单（非任意历史选择），回滚后同样检查是否需要重审配置。
- **卸载**：停用插件在所有 Bot 上的配置，但保留已下载文件和加密草稿以便恢复；重装后需重新确认并手动启用，修订号持续递增。卸载不会清除秘密或回收磁盘文件。

## Bilibili 与网易云音乐读取

| 插件       | 支持输入                              | 读取能力                                               |
| ---------- | ------------------------------------- | ------------------------------------------------------ |
| Bilibili   | 完整视频/分享 HTTPS 链接、BV/av 号    | 视频元数据、分 P、平台字幕；可选后台音频转录与视频下载 |
| 网易云音乐 | 完整歌曲、专辑、歌单或分享 HTTPS 链接 | 元数据、有界曲目预览、原文／翻译／罗马音歌词分页       |

两者均用于链接解析和资源查询（非关键词搜索），启用后接入[统一检索](/docs/guides/search)：先查元数据获得当前轮有效的引用，再调用字幕或歌词工具读正文。

- 字幕与歌词每页最多 **40 条 / 4,000 字符**，超长单条会标明截断；内容按不可信资料处理。
- Cookie 只发往对应受信 API 源；空字幕会区分“需要登录 / 认证未确认 / 确实无字幕”，空歌词不默认判为纯音乐；歌单与专辑预览带截断标记。
- Bilibili 字幕优先走固定版本的 yt-dlp B 站提取器（含平台字幕与自动字幕，排除弹幕），失败或超时时回退 B 站接口，共用同一份登录凭据。
- 不绕过付费、DRM、账号权限或地区限制。音频转录仅听音轨，不看画面，也不保证可靠区分说话人。

## 通用 yt-dlp 视频读取与下载

安装内置 **yt-dlp**（`hanori.ytdlp`）后按 Bot 启用，即可调用 yt-dlp 全量内置提取器（含 YouTube 等站点）以及普通网页的 HTML5 视频/直链，无需手动维护站点白名单。Bilibili 专用插件及其扫码、分 P、ASR 功能可独立并用。

### 快速开始：总结视频

1. 选中目标 Bot，**站点 Cookies 留空**、**视频下载保持关闭**，其余保持默认。
2. 点底部 **保存配置**，再点上方 **启用**。
3. 给 Bot 发一条具体视频链接并要求总结；仅在站点提示需要登录时再补 Cookies。

**测试已保存配置** 只校验插件能否启动，不会访问 YouTube 或测 Cookies。总结依赖可读字幕，无字幕不会自动触发语音转录；下方的时长、大小和次数限制只管视频文件下载，不影响字幕总结。

总结时 Bot 会先读取标题、简介、章节及推荐字幕（优先原语 + 平台 CC），元信息和同轨字幕在当前轮复用，不下载整段音视频；只有简介时会明确标为元信息。格式列表只给编码、分辨率和预估大小，不暴露签名直链。

### 查找字幕与失效引用

- `lookup_video` 返回 `primaryTrackReference` 及推荐轨道信息，可直接交给 `read_transcript`；无可用字幕时返回 `null`。
- `list_subtitles` 支持按 `language`（如 `en` 同时匹配 `en-US`）和 `source`（`platform_cc` / `platform_auto`）先筛再分页，平台 CC 排前。YouTube 自动翻译默认按原轨折叠并用 `translationCount` 提示数量，指定语言或传 `includeTranslations: true` 可展开；`total` 和 `nextOffset` 基于当前筛选与折叠结果。
- 正文里的 `track: translation` 标明这是自动翻译。引用仅在当前轮有效：跨轮或清理后返回 `reference_expired`，不存在返回 `unknown_reference`，两种情况都需用原链接重新调用 `lookup_video`；上游格式异常返回 `invalid_response`。引用不跨 Bot 复用。

### 需要登录时填写 Cookies

在浏览器登录目标站点后，用支持 Netscape 格式的扩展导出 `cookies.txt`（参考 [yt-dlp 官方指南](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#exporting-youtube-cookies)），用文本编辑器打开并把**文件内容**（首行通常为 `# Netscape HTTP Cookie File`，保留换行和制表符，非文件路径，也非单行 `Cookie` 头）粘贴到多行秘密输入框：

- 仅导出所需站点，最多 **16,384 字符**；保存后输入框清空并显示“已保存密钥”，留空即保留原值。
- 凭据按 Bot 加密，仅按域名匹配发送，跨站跳转不转发认证头；不读取服务器浏览器，也无通用扫码。匿名或 Cookie 登录均不保证绕过机器人校验、限流或地区限制。切勿把 Cookies 发到聊天里。

### 开启视频文件下载

开启 **允许下载视频并发回 Telegram** 后，仅在管理员明确要求下载单个视频时创建后台任务：

- 默认单视频最长 **600 秒**、最大 **45 MB**（受 Telegram 50 MB 上限约束），与 Bilibili 下载共用队列和磁盘预算。
- 支持原生 HTTP、HLS、DASH，音视频在无网络的 `media` 转换服务中合并/转为 H.264/AAC MP4（仅读元信息和字幕不需要 `media` 服务）。无上游时长时按字节、时间和磁盘预算下载，转完再核对时长。
- 播放列表需指定单条视频，直播不入队；DRM 或需浏览器模拟的站点可能不可用。遇到 `login_required`、`rate_limited`、`unsupported_url` 等错误时直接说明原因。
- Docker 镜像已内置固定版本 `yt-dlp[default]` 与 YouTube EJS；源码开发请在运行服务的 Python 环境安装 `infrastructure/bilibili-ytdlp/requirements.txt`。所有请求均做公网地址校验、DNS 固定和字节上限控制。

## 可选 Bilibili 音频转录

转录默认关闭。流程上先查平台字幕；确认已登录且无字幕时，Bot 可向管理员提出转录建议（仅建待确认任务，不下载也不上传）。

### 配置公共 ASR 账户

先按 [Docker 部署](/docs/self-hosting/docker#可选音频转换服务) 启动 `media` 转换服务，再由所有者或管理员在 **设置 → 公共音频转录** 配置供应商（全实例 Bot 共用，独立于聊天 Provider）：

| 供应商      | 预置模型                  | 凭据                                            | 币种 |
| ----------- | ------------------------- | ----------------------------------------------- | ---- |
| 腾讯云      | 常规录音文件识别 `16k_zh` | `SecretId`、`SecretKey`，地域默认 `ap-shanghai` | CNY  |
| 阿里云百炼  | 北京地域 `paraformer-v2`  | 百炼 API Key                                    | CNY  |
| Groq        | `whisper-large-v3-turbo`  | Groq API Key                                    | USD  |
| OpenAI 兼容 | `whisper-1`               | 公网 HTTPS API 根地址与 API Key                 | USD  |

- 供应商默认停用且单价为 0（0 表示价格未知，非免费）；填好凭据、当前每分钟单价并启用后才参与候选。Groq 仅在明确勾选“此密钥属于免费计划”时允许零单价。
- 候选顺序为：腾讯云 → 阿里云 → Groq → OpenAI 兼容，并参考本实例记录的免费政策用量；确认卡会锁定最终供应商和模型，确认后不静默切换。
- 费用预留按完整时长 × 单价 + 10% 余量保守计算（Groq 付费最少按 10 秒算），不抵扣免费额度，上传前再按转换后实际时长复核；CNY 与 USD 分开统计。账户默认单任务 / 每日 / 每月上限为 CNY `1 / 3 / 10`、USD `0.2 / 0.6 / 2`，月分钟数默认 `600`。

以下公开计费规则于 **2026-10-03** 核实，具体以各控制台为准：

- 腾讯云常规录音文件识别每月 10 小时免费（大模型 1.0/2.0 不适用），后付费首档 1.75 元/小时（[计费规则](https://cloud.tencent.com/document/product/1093/35686)）。
- 百炼北京地域 `paraformer-v2` 每月 36,000 秒当月有效，单价 0.00008 元/秒（0.0048 元/分钟）（[模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)）。
- Groq Whisper 免费计划公开限额为每日 28,800 秒、每小时 7,200 秒（组织共享），限流时不自动切付费供应商（[速率限制](https://console.groq.com/docs/rate-limits) / [计费说明](https://console.groq.com/docs/speech-to-text)）。

接着在 **插件 → Bilibili → 目标 Bot** 配置可访问目标视频的 Cookie，启用音频转录与音频外传并核对 Bot 限额（默认单视频 5 分钟；每管理员每日 3 次 / 10 分钟 / 1 货币单位，每月 120 分钟 / 10 货币单位；每 Bot 每月 600 分钟 / 50 货币单位，同时受公共账户上限约束；不截断超长音频）。

- **长音频与签名链接**：音轨流式下载限 **512 MiB**。腾讯云与百炼通过公网 HTTPS `BETTER_AUTH_URL` 签名链接转录，单段最长 **5 小时**（16 kHz 单声道 PCM WAV 约 576 MB），全链路流式处理；腾讯云 5 MiB 以内直接提交；Groq / OpenAI 兼容直传限 **20 MiB**（约 10 分 55 秒），暂不自动分段。转录保存成功后自动删临时音频副本（失败则后台重试），失败或恢复中的副本在 24 小时链接过期后清理。
- **清单升级注意**：Bilibili 清单 `1.3.0` 起预置改为公共腾讯云 ASR，`1.3.1` 更新了长音频说明。旧版 Bot 配置需先迁移凭据到公共设置并复核保存（旧未提交任务会失效）；提高单视频时长不会自动抬高每日/账户预算。

### 管理员逐次确认、取消与恢复

- 发起转录时 Bot 发出待确认卡片（含标题、时长、供应商、模型、预估费用和上限），有效期 **15 分钟**且只能点一次。仅限发起人本人在原 Bot、原聊天与话题中点击确认；口头回复或转发无效。
- 确认后服务端复核权限、配置版本与预算，再进入独立后台执行（实例一次跑一个音频任务）。聊天结束不中断转录：下载与转换各限 **30 分钟**，腾讯云/百炼异步任务最多轮询 **24 小时**（遇到临时超时或腾讯频控会等待后继续查原任务，不重复上传）。
- 取消会停掉本地后续步骤，但无法保证撤回已提交给供应商的任务或费用。配置变更、插件停用/更新/卸载会使未完成任务失效；重启后仅查询已有 `TaskId`，不重复建单。

### 查看与下载

在插件配置页下方的 **转录任务** 可看最近 50 条任务、刷新状态、取消或分页搜索正文（每页最多 40 条 / 4,000 字符）。

- 结果从创建起保留 **24 小时**，读取要求插件仍启用且配置版本未变。终态通知发回原聊天与话题（至多一次投递，只含任务 ID、状态和错误码，不发全文）。
- 下载 SRT / VTT 需先在该 Bot 配置中开启授权全文导出，并在网页对当前任务单独勾选版权确认。

> 本地合成测试已覆盖配置、任务流、取消恢复与导出；真实 Bilibili Cookie 与外部 ASR 的端到端可用性需自行验证。

## 可选 Bilibili 视频下载

视频下载默认关闭，与 ASR 独立。在 **插件 → Bilibili → 目标 Bot** 填好 Cookie、开启 **视频下载并发回 Telegram** 并保存（清单 `1.2.0` 升级后需重审配置）。

- **默认限额**：单视频最长 **600 秒**、最大 **45 MB**（十进制，1 MB = 1,000,000 字节；Telegram 托管 Bot API 上传硬上限为 50 MB）；每 Bot 每用户每 UTC 日限 **5 个任务**（取消和失败同样计数）。超时长或超大小直接拒绝，不截断。
- **触发方式**：仅在管理员明确要求时创建，例如：

> 下载这个B站视频并发给我：`https://www.bilibili.com/video/你的BV号`

- **执行链路**：优先用 yt-dlp B 站提取器拉取单个视频/分 P 的 DASH 流（失败回退原接口），在隔离 ffmpeg 中 stream copy 合并为 MP4 后上传至原聊天与话题。不重编码，不支持合集、直播或绕过 DRM/付费。
- **查询与取消**：用 `get_video_download` 查状态、`cancel_video_download` 取消（状态保留 7 天，管理面板暂无视频任务详情页）。任务进入 `sending` 后取消无法保证阻止发送；状态为 `delivery_unknown` 时先去 Telegram 核对，系统不会自动重发。
- **缓存与磁盘**：默认缓存 **30 分钟**、预算 **512 MB**、保留至少 **1024 MB** 空闲磁盘（缓存预算须 ≥ 单视频上限 × 2 + 1 MiB）。实例一次跑一个下载任务，与 ASR 共用转换服务按序执行；启动清残留，失败/取消立即清临时文件，过期清理不影响已发往 Telegram 的文件。

## 排查问题

先确认三件事：插件已安装、目标 Bot 已启用、清单没有待审核提示；再核对链接格式和 Cookie。资源引用仅在当前回复有效，新一轮需重新查。

- 扫码失败可按服务端日志里的**登录会话编号**定位阶段和错误码（日志不记录 Cookie、登录链接或平台原始错误）。
- 分享报错前务必清除 Cookie、Token、授权头和 URL 密钥。
- 开发第三方插件见[插件开发契约](/docs/integrations/plugin-development)。
