插件页面让实例所有者或管理员安装能力扩展，再为每个 Bot 单独保存配置和启用。安装与 Bot 启用是两步：安装成功不会自动把工具开放给所有 Bot。

## 安装可信插件

在管理面板打开 **插件**，选择内置插件，或填写第三方公开 GitHub 仓库及提交。

第三方来源只支持 `https://github.com/owner/repository` 格式和完整 40 位小写 Git SHA。不能用分支名、tag、短 SHA、私有仓库、带凭据的链接或仓库子目录。发布内容必须已经构建好；服务器不会自动安装依赖或执行构建脚本。

安装前需要明确接受服务端访问权限。插件代码在 Hanori 服务端进程中运行，能够获得该进程的权限；这不是沙箱。只安装你信任并审核过的发布提交。工具上的“只读”声明用于限制可见能力，不能隔离插件代码本身。

## 为 Bot 配置和启用

1. 选择已安装插件和目标 Bot，填写该插件声明的字段。
2. 保存配置，再启用。必填字段不完整时可以保存停用草稿，但不能启用。
3. 在测试聊天中使用插件支持的输入，并检查实际返回状态。

配置对每个 Bot 独立保存。插件启用后，工具仍按当前身份和聊天上下文筛选；声明为管理员专用的工具不会向普通用户开放，只读上下文只开放声明为只读的工具。管理插件与调用插件工具是不同权限。

Cookie、API Key 等秘密字段保存后只显示“已配置”，不会回显原值。留空表示保留已存秘密；点击清除才会删除。新输入在保存前只保留于当前页面内存，不写入浏览器本地存储。服务器加密保存秘密，并仅在已启用、已审核配置的服务端运行时解密。

**测试已保存配置** 使用已保存且启用的配置。插件有专门检查钩子时运行该钩子；没有钩子时，只验证它能创建合法会话。测试通过不一定说明 Cookie 有效、账号已登录或真实资源可访问。

若其他页面已修改配置，请重新载入并核对最新值。插件清单变化时，已有 Bot 配置会要求重新审核和保存，审核完成前不会执行。每次工具或检索调用都检查当前安装与 Bot 配置；保存更改、更新、卸载或服务停止后，会取消旧会话，迟到结果不会继续建立引用。

### 扫码登录并保存 Cookie

支持扫码的插件会在目标 Bot 的配置中显示 **扫码登录**。Bilibili 和网易云音乐提供该入口：

1. 先保存当前配置草稿；如有清单变更提示，先审核并保存。
2. 点击 **扫码登录**，使用对应平台的手机 App 扫描面板上的二维码，并在手机上确认。
3. 等待面板显示已连接。服务器会验证平台账号，再将 Cookie 加密保存到当前 Bot；页面不会收到 Cookie 原文。

插件停用时也可以登录，登录不会自动启用插件、音频转录或视频下载。重新登录会替换该 Bot 已保存的平台凭据，其他普通配置和启用状态保持原样。确认保存后，旧工具会话和依赖旧配置的未完成媒体任务会取消；已开始向 Telegram 上传的视频无法承诺撤销。

二维码会话最多保留 5 分钟，平台可能更早使其失效。过期后重新获取；保存开始前，关闭弹窗可以取消登录，失败、取消或过期不会覆盖旧 Cookie。手机确认并验证通过后会自动保存，进入保存阶段后关闭窗口不会撤销保存。如果页面提示无法确认保存结果，先关闭弹窗、重新加载配置再判断是否重试。服务器重启、插件更新或配置发生变化后，需要重新开始。

扫码来自服务端的独立平台登录会话。它不会读取你浏览器里已有的登录信息，也不要求把账号密码填写到 Hanori。平台可能要求手机确认或额外验证；遇到平台拒绝或风控时，可以继续手动填写 Cookie。Cookie 失效后需要重新登录，目前不提供后台自动续期。

Bilibili 手机确认后，服务器优先使用扫码接口返回的 Cookie 验证账号；接口仅返回跨域登录票据时，再兑换票据并验证。游戏站的后续页面跳转不影响已取得凭据的账号校验，登录链接中的参数不会被当作 Cookie 保存。

## 更新、回滚和卸载

第三方插件更新仍指定完整提交 SHA，不会自动追踪默认分支。更新前审核目标提交的代码与配置变化；如果清单变更，逐个 Bot 重新审核配置。

回滚使用已保留的上一版本提交与清单，不是任意历史版本选择器。回滚后也要检查 Bot 配置是否需要审核。内置插件随 Hanori 更新，不通过第三方仓库更新按钮切换版本。

卸载会停止插件并停用它在所有 Bot 上的配置，保留已下载版本和加密配置草稿以便恢复。重新安装后仍需确认配置并手动启用；修订号继续递增，旧页面中的保存操作不会覆盖新状态。卸载不等于清除秘密或回收磁盘文件。

## Bilibili 与网易云读取

| 插件       | 输入                                  | 当前读取能力                                           |
| ---------- | ------------------------------------- | ------------------------------------------------------ |
| Bilibili   | 完整视频或分享 HTTPS 链接、BV/av 标识 | 视频元数据、分 P、平台字幕；可选后台音频转录与视频下载 |
| 网易云音乐 | 完整歌曲、专辑、歌单或分享 HTTPS 链接 | 元数据、有界曲目预览、原文／翻译／罗马音歌词分页       |

这两个内置来源是链接解析与资源查询，不是关键词搜索引擎。启用后可通过[统一检索](/docs/guides/search)查询元数据，返回当前轮有效的资源引用，再明确调用字幕或歌词工具读取正文。元数据成功不代表字幕、歌词或音频可用。

兼容接口与平台要求可能改变。Cookie 只发送到对应受信 API 源；空字幕响应会区分登录要求、认证未确认和确认没有字幕。空歌词不自动判为纯音乐。歌单与专辑预览会标注截断与未知总数，不能视为完整列表，也不能假定存在下一页。

字幕和歌词每页最多 40 条、4000 个正文字符；过长单条内容会标注截断。平台字幕、平台自动字幕和歌词保留来源，内容只作不可信资料阅读。默认检索不读取完整正文，也不自动把整首歌词或整段字幕复制到回复。

插件不提供付费、DRM、账号权限或地区限制绕过。音频转录只处理 Bilibili 音轨，不代表已经观看视频画面，也不能据此可靠识别说话人。

## 可选 Bilibili 音频转录

转录默认关闭，与平台字幕读取独立。先查询平台字幕：有字幕时使用现有字幕；只有确认已登录且没有字幕，才允许创建音频转录任务。没有 Cookie、登录状态无法确认或音频无权访问时，不会通过 ASR 绕过限制。检索和字幕缺失都不会自动启动下载或付费转录。

启用前，由实例维护者按 [Docker 部署](/docs/self-hosting/docker#可选音频转换服务)启动 `media` 转换服务。然后在 **插件 → Bilibili → 目标 Bot** 配置：

1. 扫码登录或手动保存可访问目标视频的 Cookie，并填写单一 ASR 服务的 API 地址、API Key 和模型；语言代码可选。Cookie 和 API Key 是秘密字段，保存后不会回显。
2. 明确启用音频转录，并允许向所选外部 ASR 服务发送音频。只处理你有权下载和转录的内容；这个开关不会授予平台下载权限。
3. 填写每分钟单价，以及每用户每日任务数、音频分钟数和预估费用上限，再保存并启用插件。

ASR 服务须支持 OpenAI 兼容的音频转录接口、`verbose_json` 和分段时间戳。API 地址填服务根路径，例如 `https://api.openai.com/v1`，不要填写末尾带 `/audio/transcriptions` 的请求地址。必须使用公网 HTTPS 地址；不接受带凭据、查询参数或自定义端口的地址。仅使用你配置的服务与模型，失败时不会换用其他供应商或模型，也不复用聊天模型的 Provider 配置。处理前请自行核对该服务的隐私政策和费用。

单视频默认限 5 分钟；每用户每日默认 3 个任务、10 分钟和 1 美元预估费用。这些数值都可在插件配置中自行设置，没有额外的 10 分钟、10 次或 60 分钟配置上限；时长、次数和每日分钟数须为正整数。服务器仍按你保存的限制拒绝超时长、超次数或超预算的任务，超时长内容不会进入下载和付费转录。单价默认是 0，必须按供应商实际价格填入正数后才能运行。预算按 Bot 和用户、以 UTC 日期统计，并按完整视频时长预留；取消和失败任务也占用当天预留。预估费用用于限制任务量，不是实际账单或退款承诺。

配置上限与单次处理容量是两件事：下载音轨仍限 64 MiB，转换后的 16 kHz 单声道 PCM WAV 限 20 MiB，约能容纳 10 分 55 秒音频；另有处理超时与供应商限制。当前不会自动分段，调高配置值不会扩大这些容量；超出容量会失败，不会截取一部分后当作完整转录返回。

当前转录链路是下载 Bilibili 音轨，将音频交给隔离的 ffmpeg 转换服务，再发送给你配置的外部 ASR。它不下载视频画面，也没有使用 yt-dlp 本体。

### 创建、取消与恢复

在 Bot 对话中，由管理员明确请求转录指定 Bilibili 视频。验证链接、登录状态、字幕和预算后，Bot 返回任务 ID；相同用户、聊天和当前配置下，排队中、运行中或已完成且未过期的任务会复用。下载、转换和转录在后台执行，实例一次处理一个音频任务。

可凭任务 ID 查询进度、取消或分页读取结果。Bot 工具只访问当前 Bot、聊天和用户自己的任务；实例所有者或管理员还可在网页管理该 Bot 的任务。取消会停止本地后续工作，但不能撤销供应商已经收到或收费的请求。

插件停用、卸载、更新或保存配置会取消关联的未完成任务。下载或转换阶段中断后可以有限恢复；一旦进入外部转录阶段，中断或重启都不会自动重试，以免重复收费。确认旧请求状态与费用后，才手动发起新任务。

### 查看与下载

在插件配置下方的 **转录任务** 查看最近 50 个任务，刷新状态或取消。完成后可分页查看、按关键字查询，每页最多 40 条字幕和 4,000 个正文字符；超长单条会标注截断。AI 转录可能有误，低置信度内容不能当作核实过的原文。

结果从任务创建起保留 24 小时，过期后正文会被清除。读取要求插件仍启用、配置仍有效且与任务创建时一致；保存新配置或更新插件后，旧结果可能不再可读。完成通知只包含任务 ID 和状态，不向聊天自动发送全文；通知失败后仍可在网页查看有效结果。

若要下载 SRT 或 VTT，先在该 Bot 配置中启用授权全文导出，再对网页当前任务单独勾选你有权处理和下载其转录内容。切换任务需要重新确认。导出全文不等于允许传播受版权保护的视频或字幕。

当前已实现配置、持久任务、取消恢复、分页和导出流程，并有本地合成内容测试。真实 Bilibili Cookie、平台音频访问和外部 ASR 的端到端可用性尚未验证；**测试已保存配置** 也不能证明这些链路已通过。

## 可选 Bilibili 视频下载

视频下载默认关闭，与音频转录独立，不需要启用 ASR 或允许向 ASR 供应商发送音频。在 **插件 → Bilibili → 目标 Bot** 保存可访问视频的 Cookie，启用 **视频下载并发回 Telegram**，核对下载和磁盘预算，再保存并启用插件。Bilibili 清单升级到 `1.2.0` 后，已有 Bot 配置须重新审核并保存。

默认单视频最长 600 秒、文件大小 45 MB；每 Bot、每用户按 UTC 日期限 5 个任务，取消和失败任务也占用当天预留。MB 使用十进制单位，1 MB 为 1,000,000 字节。面板数字字段没有人为上限，但须满足最小值、整数及服务端安全计算要求；Telegram 托管 Bot API 的 50 MB 上传上限仍有效，设置更大的文件上限不会突破它。超时长、超大小的视频会拒绝或失败，不会截取一部分后当作完整视频发回。

只在管理员明确请求时创建任务，例如：

> 下载这个B站视频并发给我：`https://www.bilibili.com/video/你的BV号`

验证通过后立即返回任务 ID。后台从 Bilibili 取得选定单个视频或分 P 的 DASH 音视频流，以流式方式下载，再交给隔离 ffmpeg 使用 stream copy 合并为 MP4，最后以文件流上传到发起请求的 Telegram 聊天与话题。当前没有使用 yt-dlp 本体，也不重新编码、下载合集、直播或绕过 DRM、付费及账号权限。检索、读取字幕、字幕缺失和下载完成都不会自动触发下载或 ASR。

可通过 `get_video_download` 查询自己的任务状态，通过 `cancel_video_download` 请求取消；任务状态记录保留 7 天，文件保留时间由缓存 TTL 单独控制。工具绑定当前 Bot、聊天、用户及话题，模型不能指定另一个发送目标或服务器路径。当前管理面板提供下载配置，尚无视频任务详情页面。聊天轮次结束不会取消已经创建的后台任务；插件停用、卸载、更新或配置改变会停止尚可取消的工作。进入 `sending` 后，取消不能承诺阻止发送，也不撤回消息。若状态为 `delivery_unknown`，先检查 Telegram 中是否已有文件，不会自动重发，以免重复投递。

服务器默认将成功文件缓存 30 分钟，缓存预算为 512 MB，保留至少 1024 MB 空闲磁盘空间。缓存预算至少须覆盖有效单视频大小上限的两倍再加 1 MiB，以容纳下载输入和合并输出的临时峰值；不足时不会启动任务。实例一次处理一个视频下载任务，并核对全局缓存占用及磁盘余量；音频转录和视频合并共用转换服务，按到达顺序一次处理一个转换任务。启动时清除残留文件，失败或取消后立即清理临时文件，成功缓存过期后定期清理；正在发送的文件保留到发送结束后再清理。缓存过期只删除服务器副本，已经发送到 Telegram 的文件不会撤回。

本地合成测试覆盖配置、工具和任务流程；真实平台访问及 Telegram 视频投递须单独验证。**测试已保存配置** 不会下载和发送视频。

## 排查问题

先检查插件是否已安装、目标 Bot 是否启用、清单是否待审核，再确认输入格式与 Cookie 状态。引用只属于当前回复；开始新一轮后，重新查询资源。

插件异常可能包含秘密，面板返回有界错误状态。分享诊断前移除 Cookie、Token、授权头和链接中的密钥。服务端插件故障、本地测试通过与真实平台可用性应分别判断。

扫码失败时，服务端日志会记录插件、Bot、登录会话编号、失败阶段和固定错误码，可按会话编号定位。该诊断不记录 Cookie、登录链接或平台原始错误内容。

开发第三方插件见[插件开发契约](/docs/integrations/plugin-development)。
