title: 群聊行为与参与控制
description: 从明确触发开始，逐步配置群聊回复、总结、治理限制和 JEV。
---

群聊同时包含公开消息、多人上下文和外部服务成本。推荐先用明确触发验证，再逐步放开自动参与；每个聊天都应有一个可回滚的配置。

## 触发方式

群聊配置通常可以组合以下触发条件：

- 回复 Bot 的消息；
- `@Bot`；
- 管理员配置的触发词；
- 受冷却时间限制的随机参与。

触发方式只决定“是否进入一次 AI 回复流程”，并不绕过 Provider、模型、AI 开关、权限或用量治理。测试时先使用回复或提及，最容易确认消息链路是否正常。

## 对话上下文

群聊上下文包括当前消息附近的对话、群历史上限和可选的群总结。管理员可以分别设置是否启用群对话、上下文消息数量以及历史 token 上限。上限越大不一定越好：它会增加模型输入成本，也可能让回答变慢。

`/clear` 清除当前对话历史。它不会撤回 Telegram 中已经发送的消息，也不会把共享群历史从其他参与者的可见范围抹去。

## JEV：让参与决策先观察再启用

JEV 是群聊参与决策层，用于分别判断“这条消息是否应该由 Bot 回复”和“如果参与，属于直接招呼、延续对话还是加入话题”。当前实现把回复判断与参与路由分开，因此参与方式不确定时不会直接把一条高置信度的回复判断变成沉默。它支持三种状态：

| 状态   | 行为                                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------------------- |
| 关闭   | 不调用 JEV，沿用原有回复、提及、触发词和随机参与规则。                                                            |
| shadow | 记录判断建议，但实际回复行为保持原样，用于观察分类质量和成本。                                                    |
| active | 让 JEV 的回复判断和参与路由参与准入；私聊、明确 `@` 和回复 Bot 的消息可直接进入回答流程，权限和隐私规则仍然生效。 |

建议只为一个测试群启用 shadow，观察参与样本、回复与参与路由、置信度、延迟、错误和费用，再决定是否 active。shadow 也会调用分类服务，因此可能产生费用；不要把 shadow 当成零成本预览。需要校准时，在样本页复核“应该回复”“应该沉默”或“不确定”，并注意上下文有保留期限。

### 配置接话门槛与偏好

在「AI 设置 → 回复行为 → 智能群聊接话」调整 Bot 默认策略，也可以在群组覆盖中使用不同值。高级设置把回复准入、参与路由和请求预算分开：

| 设置                    | 默认值            | 作用                                                                                     |
| ----------------------- | ----------------- | ---------------------------------------------------------------------------------------- |
| 最低回复置信度          | 0.8               | JEV 先选择回复，且其回复判断置信度达到该值，才通过回复门槛。                             |
| 直接招呼置信度          | 0.8               | 原始参与判断是直接招呼且达到该值时，可跳过主动插话冷却。                                 |
| 延续对话置信度          | 0.8               | 原始参与判断是延续对话且达到该值时，按延续对话路由处理。                                 |
| 续聊窗口                | 120 秒            | 窗口内有 Bot 发言时，高置信度延续对话可跳过主动插话冷却；范围 0–300 秒，0 关闭这项豁免。 |
| 主动插话冷却            | 60 秒             | 普通主动加入及未满足上述豁免条件的回复遵守此冷却。                                       |
| 上下文消息数 / 判断超时 | 20 条 / 1000 毫秒 | 控制分类请求的上下文及总等待预算。上下文仍限制为最近 5 分钟、最多 6000 字符。            |

这些是缺失配置时的默认值，升级不会覆盖已有自定义设置。所有路径仍然遵守权限、隐私、用量和并发限制；明确 `@` 和回复 Bot 的直达流程不受这些参与门槛控制。

**置信度不是回复概率，也不是实测准确率。** 降低参与门槛只会影响参与路由和冷却豁免，不能把 JEV 已选择沉默的结果变成回复。参与方式不确定时按主动加入处理，不会仅因此否定已通过的回复判断。

JEV 的「补充接话偏好」决定什么时候适合接话；回复模型的群聊提示词决定准入后怎么回答，两者独立。面板提供偏好示例，先预览，再明确应用到草稿；已有偏好不会因为查看示例而被替换，最后仍需保存设置。

希望 Bot 更像活跃群友时，可以允许它接生活吐槽、完整故事后的梗、技术交流和情绪表达，同时要求对纯附和、重复内容、其他成员之间的定向问答及明确拒绝回复保持沉默。希望克制帮助时，优先允许明确求助和有具体补充价值的问题。不必把整份角色提示词复制给 JEV。

### 经常不接话时怎么调

先看记录的原因，再一次调整一个因素：

1. **模型选择沉默**：先检查有限上下文及接话偏好是否符合预期。参与方式概率再高，也不代表应该回复；仅降低参与门槛无效。
2. **回复置信度不足**：检查模型已经选择回复的边界样本，再小幅降低最低回复置信度。低门槛会同时增加不必要的接话，没有适用于所有群的最佳值。
3. **主动插话冷却**：核对原始参与建议、参与置信度、实际路由及续聊窗口，再决定调整相应门槛或冷却。
4. **超时或错误**：查看请求预算和服务状态。失败会沿用原有触发规则，不能当作模型主动选择沉默。

用同一个群、同一配置版本的当前两阶段样本复核效果。既标注漏接，也标注本该沉默的内容；少量挑选出的案例不能代表整体准确率。观察模式仍有分类费用，且不会实际采用新准入结果。

## 查看和批量标注接话决策

回复会参考本次参与方式，区分直接招呼、延续对话和加入话题。最终内容仍由配置的聊天模型生成；这不代表已经实现新的群聊节奏控制，实际接话效果需要结合群内表现评估。

在 Bot 的「调试器 → 接话决策」查看记录，也可以从「AI 设置 → 回复行为」的「查看决策记录」进入。JEV 配置仍在 AI 设置中；接话记录对所有者和管理员开放，运行调试功能仍仅限所有者。

列表显示当前消息摘要、策略结果、实际准入状态和原因。展开详情可查看有限上下文、两组独立概率与配置快照。新记录另外保留原始参与建议及其置信度，可以和经过门槛处理后的参与路由比较；历史记录未保存的字段会明确提示，不能从舍入后的概率反推。上下文过期后不再显示正文。「已进入回复流程」不代表 Telegram 已成功发送消息。

可按群组、未标注、策略结果、时间、决策格式或完整配置版本筛选，也可从一条记录的配置版本进入同配置记录，再选择当前页记录，批量标为「应该回复」「应该沉默」「不确定」，或清除已有标注。选择不会跨页保留，筛选或翻页后需要重新选择；筛选结果更新期间不能标注旧记录。

人工标注只用于评估，不会训练模型、自动调整阈值或改变下一次回复。人工评估分别展示当前两阶段判断和历史三分类记录，旧标签不会混成当前算法的误插话与漏回复率；同一格式下不同配置仍可能混合，比较调参效果时应进一步筛选配置版本。误插话与漏回复使用已人工判断的对应 JEV 样本作为分母，例如「3/4」表示四条相应人工样本中有三条判断不符，并非全部记录的错误比例。

## 治理和用量限制

面板的 Governance 页面可以按 Bot、群、用户或“群与用户组合”设置 AI 回复、图片和主动回复的冷却、小时、日、月及并发上限。更具体的覆盖值优先于默认值时，要记录它的作用对象，避免把某个用户的限制误以为全局配置。

私聊 AI、群聊 AI、图片生成和 proactive reply 是不同的资源维度。遇到“有时能回、有时不回”，先检查是否命中其中一类限制，再查看 Provider 错误。

## 群总结

群总结可以手动触发，也可以按时间表运行。可配置总结窗口、最多消息数、冷却、时区和访问模式；访问模式可以是所有成员或仅管理员。

手动用法示例：

```text
/summary
/summary 200
/summary 6h
/summary today
/summary yesterday
```

一次总结最多覆盖 2,000 条消息或 72 小时。消息太少、没有 Provider、触发冷却或模型调用失败时，Bot 会返回相应原因；总结内容仍然属于共享群空间。

## 回滚建议

新配置上线前记下原值。出现误回复或费用异常时，按顺序关闭 JEV active、关闭随机参与、暂停总结计划，必要时使用 `/stop` 暂停 AI；保留日志和样本，修正后先回到 shadow 或明确触发测试。
