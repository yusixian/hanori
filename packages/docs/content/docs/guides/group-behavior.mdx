群聊涉及公开消息、多人上下文和外部费用。建议先从明确触发跑通，再逐步放开自动参与，改动前记下原值方便回滚。

## 触发方式

群聊支持组合以下触发条件：

- 回复 Bot 的消息
- `@Bot`
- 管理员配置的触发词
- 带冷却的随机参与（概率 0–100%，冷却 0–86,400 秒 / 最长 24 小时）

触发只决定“是否进入回复流程”，不绕过 Provider、模型、AI 开关、权限或用量限制。联调时优先用回复或 `@Bot` 验证链路。

## 对话上下文

管理员可分别控制是否开启群对话、上下文消息条数和历史 token 上限。上限并非越大越好，过大既费钱又拖慢响应。

`/clear` 只清空 Bot 的对话历史，不撤回 Telegram 消息，也不影响其他群友的聊天记录。

## JEV：先观察，再启用

JEV 是群聊参与决策层，把“要不要回”和“怎么接（直接招呼 / 延续对话 / 加入话题）”拆成两步判断，避免参与方式拿不准时把高置信度的回复直接按掉。它有三种模式：

| 状态   | 行为                                                                                        |
| ------ | ------------------------------------------------------------------------------------------- |
| 关闭   | 不调用 JEV，沿用回复、提及、触发词和随机参与规则                                            |
| shadow | 只记录判断建议，不改变实际回复行为，用来评估质量和成本                                      |
| active | 由 JEV 决定准入和参与路由；私聊、明确 `@` 和回复 Bot 仍直达回复流程，权限和隐私规则照常生效 |

建议先在一个测试群开 `shadow`，观察样本、路由、置信度、延迟和费用后再切 `active`。`shadow` 同样调用分类服务、会产生费用。校准时可在样本页标注“应该回复 / 应该沉默 / 不确定”（上下文有保留期限）。

### 配置接话门槛与偏好

在「AI 设置 → 回复行为 → 智能群聊接话」配置 Bot 默认值，也可在群组覆盖中单独设置：

| 设置                    | 默认值            | 作用                                                                                 |
| ----------------------- | ----------------- | ------------------------------------------------------------------------------------ |
| 最低回复置信度          | 0.8               | JEV 选择回复且回复置信度达到该值时，才通过回复门槛                                   |
| 直接招呼置信度          | 0.8               | 原始参与判断为直接招呼且达到该值时，跳过主动插话冷却                                 |
| 延续对话置信度          | 0.8               | 原始参与判断为延续对话且达到该值时，按延续对话路由处理                               |
| 续聊窗口                | 120 秒            | 窗口内有 Bot 发言时，高置信度延续对话跳过主动插话冷却（范围 0–300 秒，0 为关闭豁免） |
| 主动插话冷却            | 60 秒             | 普通主动加入及未满足上述豁免条件的回复遵守此冷却                                     |
| 上下文消息数 / 判断超时 | 20 条 / 1000 毫秒 | 分类请求的上下文条数和等待预算（同时受最近 5 分钟、最多 6000 字符上限约束）          |

以上为缺省默认值，升级不覆盖已有自定义配置。明确 `@` 和回复 Bot 不受这些门槛限制。

**置信度不是回复概率，也不是实测准确率。** 调低参与门槛只影响路由和冷却豁免，不能把 JEV 已判沉默的消息改成回复；参与方式不确定时回退为主动加入，不会否定已通过的回复判断。

「补充接话偏好」决定**什么时候该接话**，群聊系统提示词决定**接话后怎么说**，两者分开配置，不必把整段人设贴进 JEV。面板提供偏好示例，可先预览再决定是否应用到草稿，最后需点击保存。

想要活跃群友风格，可允许接生活吐槽、接梗、技术讨论和情绪表达，同时对纯附和、复读、他人定向问答和明确拒回保持沉默；想要克制助手风格，则聚焦明确求助和有增量信息的问题。

### 经常不接话时怎么调

先看决策记录的原因，每次只改一个变量：

1. **模型选择沉默**：检查有限上下文和接话偏好；仅调低参与门槛无效。
2. **回复置信度不足**：翻看模型已选回复的边界样本，再小幅下调最低回复置信度（门槛越低误插话越多）。
3. **主动插话冷却**：核对原始参与建议、置信度、实际路由和续聊窗口，再决定调门槛还是调冷却。
4. **超时或错误**：检查判断超时预算与服务状态；分类失败会回退原有触发规则，不是模型主动沉默。

复核时用同一群、同一配置版本的两阶段样本，漏接和误插话都要标，别只挑个别案例下结论。

## 查看和批量标注接话决策

在「调试器 → 接话决策」（或「AI 设置 → 回复行为 → 查看决策记录」）查看记录；记录对所有者和管理员开放，运行调试仍仅限所有者。

列表展示消息摘要、策略结果、准入状态与原因；展开详情可看有限上下文、两组独立概率、配置快照，以及原始参与建议与实际路由的对比（旧记录缺字段会明确标注，上下文过期后不显示正文）。注意“已进入回复流程”不代表 Telegram 已成功发消息。

支持按群组、未标注、策略结果、时间、决策格式或配置版本筛选，也可在当前页批量标注「应该回复」「应该沉默」「不确定」或清除标注（选择不跨页保留）。

人工标注仅用于离线评估，不训练模型也不自动调参。统计面板将当前两阶段记录与历史三分类记录分开展示；比较调参效果时记得按配置版本筛选。误插话与漏回复的分母是对应已标注样本数（如 `3/4` 表示 4 条人工样本中 3 条不符），不是全量消息比例。

## 治理和用量限制

面板 Governance 页面可按 Bot、群、用户或“群+用户”设置 AI 回复、图片和主动回复的冷却、小时/日/月配额与并发上限。私聊 AI、群聊 AI、生图和 proactive reply 分别计数；遇到“时回时不回”，先查治理配额再查 Provider 错误。

## 群总结

群总结支持手动和定时运行，可按群设置窗口、条数、冷却、时区与访问模式（全员或仅管理员）。单次上限 2,000 条或 72 小时：

```text
/summary
/summary 200
/summary 6h
/summary today
/summary yesterday
```

更多范围、预览和全局定时细节见[RSS、总结与定时任务](/docs/guides/automation)。

## 回滚建议

出现误回复或费用异常时，依次关闭 JEV `active` → 关闭随机参与 → 暂停定时总结，必要时发 `/stop` 停掉 AI；保留日志和样本，修正后先回 `shadow` 或明确触发复测。
