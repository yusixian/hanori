---
title: 群聊行为与参与控制
description: 从明确触发开始，逐步配置群聊回复、总结、治理限制和 JEV。
---

群聊同时包含公开消息、多人上下文和外部服务成本。推荐先用明确触发验证，再逐步放开自动参与；每个聊天都应有一个可回滚的配置。

## 触发方式

群聊配置通常可以组合以下触发条件：

- 回复 Bot 的消息；
- `@Bot`；
- 管理员配置的触发词；
- 受冷却时间限制的随机参与。

触发方式只决定“是否进入一次 AI 回复流程”，并不绕过 Provider、模型、AI 开关、权限或用量治理。测试时先使用回复或提及，最容易确认消息链路是否正常。

## 对话上下文

群聊上下文包括当前消息附近的对话、群历史上限和可选的群总结。管理员可以分别设置是否启用群对话、上下文消息数量以及历史 token 上限。上限越大不一定越好：它会增加模型输入成本，也可能让回答变慢。

`/clear` 清除当前对话历史。它不会撤回 Telegram 中已经发送的消息，也不会把共享群历史从其他参与者的可见范围抹去。

## JEV：让参与决策先观察再启用

JEV 是群聊参与决策层，用于分别判断“这条消息是否应该由 Bot 回复”和“如果参与，属于直接招呼、延续对话还是加入话题”。当前实现把回复判断与参与路由分开，因此参与方式不确定时不会直接把一条高置信度的回复判断变成沉默。它支持三种状态：

| 状态   | 行为                                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------------------- |
| 关闭   | 不调用 JEV，沿用原有回复、提及、触发词和随机参与规则。                                                            |
| shadow | 记录判断建议，但实际回复行为保持原样，用于观察分类质量和成本。                                                    |
| active | 让 JEV 的回复判断和参与路由参与准入；私聊、明确 `@` 和回复 Bot 的消息可直接进入回答流程，权限和隐私规则仍然生效。 |

建议只为一个测试群启用 shadow，观察参与样本、回复与参与路由、置信度、延迟、错误和费用，再决定是否 active。shadow 也会调用分类服务，因此可能产生费用；不要把 shadow 当成零成本预览。需要校准时，在样本页复核“应该回复”“应该沉默”或“不确定”，并注意上下文有保留期限。

active 下，JEV 的最低回复置信度和参与路由阈值仍然独立：低置信度的 `continue` 不会获得延续对话的冷却豁免，`addressed` 和 `continue` 的快捷路径也必须满足固定参与置信度门槛。具体阈值由面板当前配置和实现决定，不要把模型置信度当成实测准确率。

## 查看和批量标注接话决策

回复会参考本次参与方式，区分直接招呼、延续对话和加入话题。最终内容仍由配置的聊天模型生成；这不代表已经实现新的群聊节奏控制，实际接话效果需要结合群内表现评估。

在 Bot 的「调试器 → 接话决策」查看记录，也可以从「AI 设置 → 回复行为」的「查看决策记录」进入。JEV 配置仍在 AI 设置中；接话记录对所有者和管理员开放，运行调试功能仍仅限所有者。

列表显示当前消息摘要、策略结果、实际准入状态和原因。展开详情可查看有限上下文、两组独立概率与配置快照；上下文过期后不再显示正文。「已进入回复流程」不代表 Telegram 已成功发送消息。

可按群组、未标注、策略结果或时间范围筛选，再选择当前页记录，批量标为「应该回复」「应该沉默」「不确定」，或清除已有标注。选择不会跨页保留，筛选或翻页后需要重新选择；筛选结果更新期间不能标注旧记录。

人工标注只用于评估，不会训练模型、自动调整阈值或改变下一次回复。人工评估中的误插话与漏回复使用已人工判断的 JEV 样本作为分母，例如「3/4」表示四条相应人工样本中有三条判断不符，并非全部记录的错误比例。

## 治理和用量限制

面板的 Governance 页面可以按 Bot、群、用户或“群与用户组合”设置 AI 回复、图片和主动回复的冷却、小时、日、月及并发上限。更具体的覆盖值优先于默认值时，要记录它的作用对象，避免把某个用户的限制误以为全局配置。

私聊 AI、群聊 AI、图片生成和 proactive reply 是不同的资源维度。遇到“有时能回、有时不回”，先检查是否命中其中一类限制，再查看 Provider 错误。

## 群总结

群总结可以手动触发，也可以按时间表运行。可配置总结窗口、最多消息数、冷却、时区和访问模式；访问模式可以是所有成员或仅管理员。

手动用法示例：

```text
/summary
/summary 200
/summary 6h
/summary today
/summary yesterday
```

一次总结最多覆盖 2,000 条消息或 72 小时。消息太少、没有 Provider、触发冷却或模型调用失败时，Bot 会返回相应原因；总结内容仍然属于共享群空间。

## 回滚建议

新配置上线前记下原值。出现误回复或费用异常时，按顺序关闭 JEV active、关闭随机参与、暂停总结计划，必要时使用 `/stop` 暂停 AI；保留日志和样本，修正后先回到 shadow 或明确触发测试。
