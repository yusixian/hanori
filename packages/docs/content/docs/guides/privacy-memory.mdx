title: 隐私、历史与记忆

Hanori 将**当前对话**、**共享群历史**、**人物档案**和**长期记忆**分开管理。个人化模式只控制与你个人相关的读写行为，不会改变 Telegram 群聊本身是共享空间的事实。

## 三种个人化模式

在私聊发送 `/privacy` 或 `/privacy status` 查看当前模式：

| 模式       | 行为                                                       |
| ---------- | ---------------------------------------------------------- |
| `normal`   | 开启个人化，可参考你在其他聊天中的近期发言与个人资料。     |
| `isolated` | 仅在当前聊天开启个人化，不跨聊天读取。                     |
| `off`      | 关闭个人化与被动触发；共享群历史仍可能被保存用于群聊功能。 |

切换命令：

```text
/privacy normal
/privacy isolated
/privacy off
```

模式切换只影响后续行为，不会回溯修改已生成的摘要或群内既有消息。

## Bot 可能保存的数据

在对应功能和权限开启时，Bot 会保存：

- 对话消息与群历史（用于上下文、检索和总结）；
- 人物档案（显示名、备注、兴趣、特征、关系等）；
- AI 保存的长期记忆；
- Telegram 媒体缓存、生图记录、工具与运行日志；
- 管理员配置的 RSS、群总结、定时器和治理数据。

保留周期由实例配置决定；日志、图片与生成记录有各自清理策略，导出、备份与删除受面板角色限制。

## 在面板查看与清理对话

在 Bot 工作区的 **对话** 页，可输入完整 **Chat ID** 或历史参与者名称片段，按 Enter 或点 **搜索对话**。搜索覆盖当前 Bot 的全部会话，并按最近活动排序；数字 ID 精确匹配，名称忽略大小写，`%`、`_` 和反斜杠按字面字符匹配。

- 名称仅匹配聊天记录里存过的历史显示名或当时 username，不查实时群名、Telegram 当前 username、人物档案或消息正文。命中后仍展示该会话的完整消息、参与者和摘要。
- 搜索会回到第 1 页；继续输入需再次提交才生效，点 **清除搜索** 返回全部会话。搜索条件和页码仅保留在当前页，刷新或切 Bot 会重置。手机端用详情左上角返回列表。
- **清空此 Bot 的全部对话** 会删除该 Bot 下的全部会话（包括搜索结果之外的）；只删单个会话请点该行删除按钮。
- 列表、消息和摘要分别加载：加载失败显示错误和 **重试**，不误报为空态；刷新失败保留已有内容并提示可能过期。切换 Bot、条件或页码时，较早返回的请求不会覆盖当前视图。
- 单条消息和非活动摘要需点击两次确认删除，整会话或全部会话需弹窗确认，当前使用中的摘要不能单独删除。
- 删除结果不确定时，界面保留记录并提供 **刷新并核对**（只重读数据，不重发删除；即使已切条件或页码也会核对原范围）。若服务端已删但刷新失败，会提示 **已删除，但未能刷新页面数据**，先核对再决定后续操作。删除与核对期间相关交互暂时禁用。
- **系统**、**工具** 两个显示开关只作用于当前已加载的消息页。

### 管理压缩摘要

压缩摘要是会话压缩时生成的上下文快照，**当前使用**的版本会进入后续对话，其余仅为历史记录。管理员编辑当前摘要会生成新版本并保留旧版；若同时发生自动压缩或他人编辑，页面会提示冲突并刷新，避免覆盖。

新摘要只保留当前版本及最近几个历史版本。升级前积压的旧摘要不会自动清理，可在会话 **摘要** 页先看只读预览，再分批确认删除（每批最多 **100** 个，当前版本始终受保护）。清理摘要不会删原始消息，也不改长期记忆。编辑与批量清理仅限所有者或管理员。

## 在面板维护档案与记忆

在 Bot 工作区的 **人物档案** 或 **记忆** 页可增删改查当前 Bot 的记录：

- 人物档案搜索走服务端分页并显示真实总数（管理页不再限于前 10 条；AI 工具内部搜索仍最多返回 10 条以控上下文）。点击人物卡的 **查看记忆** 会直接打开该人物的记忆范围。
- 列表加载失败显示错误和 **重试**；刷新失败保留已有内容并提示可能过期。
- 创建、保存或删除结果不确定时，表单输入或原记录会保留；点错误旁的 **刷新列表** 先确认服务端状态，再决定是否重试。提交中暂时禁用表单；写入成功但随后刷新失败会分别提示。
- 切 Bot 或改筛选时，迟到响应不会覆盖当前列表；表单草稿仅存于当前页面内存，离开或刷新不保留。

### 筛选记忆

支持组合三个条件：

- **范围**：全部记忆、仅通用记忆，或指定整数 Telegram 用户 ID；
- **分类**：已有分类；
- **搜索**：按记忆内容检索。

改完条件后点 **搜索** 生效，已应用的范围会显示在列表上方并同步到 URL（支持刷新、分享和前进/后退）。点 **清除筛选** 移除条件并回到第 1 页。

- 从人物卡进入记忆页时会自动填好用户 ID，点 **添加记忆** 也会预填该 ID（提交前可修改或清空，清空即为通用记忆）。
- 编辑记忆带版本冲突检查，被他人或 Bot 并发修改时需先刷新核对。
- 编辑中须先保存或取消才能切换筛选；写入或删除待确认刷新期间，新筛选和 URL 变更会延后应用。

### 修改和整理长期记忆

记忆可标注类型（事实、偏好、经历、约定、关系）、适用聊天、来源和有效期，并支持**停用**（停用或过期的记忆不再被召回，但可在列表查看或永久删除）。未设有效期的旧记忆不会随升级自动过期。

- **范围与权限**：经历、关系和未完成约定限定在当前聊天；个人偏好和事实遵循个人化模式。`isolated` 模式不读取升级前无聊天范围的旧个人记忆（管理员可核对后补填范围）。仅当用户明确要求忘记自己的记忆时，Bot 才开放个人记忆永久删除工具；群聊共同记忆可由 Bot 停用或管理员删除。
- **重复记录清理**：在记忆页可只读预览**完全相同**的活动记录（内容、用户、聊天范围、类型、分类、有效时间全部精确一致），确认后每批最多停用 **50** 条（优先保留带向量的，其次保留创建时间较新或 ID 较大的）。预览后若记录被修改，执行会被拒绝。
- **后台自动整理**：开启 AI 与记忆后，后台按游标分批从已完成、有来源的消息中提炼少量长期记忆。多人群聊只生成限定该聊天的共同记忆，不推断个人档案；关闭 AI、记忆或个人化时不再提炼个人记忆。普通消息到期删除不会连带删已提炼的记忆；群成员隐私模式变化会让相关自动记忆停止召回供管理员核对。
- **整理预览接口**：所有者与管理员可调用 `GET /api/bots/{botId}/memories/consolidation-preview` 查看待整理批次及摘录（`limit` 最多 5 批，用返回的 `nextAfterMessageId` 作为下次的 `afterMessageId`，为 `null` 表示到底）。该接口只读，不调模型也不推进游标。

## 删除个人数据

先发送：

```text
/privacy forget
```

确认后发送：

```text
/privacy forget confirm
```

这会删除数据库中可直接归属于你的对话消息、人物档案、缓存头像、个人长期记忆，以及你创建的原创角色及其所有绑定（含他人对这些角色的绑定），并将个人化模式设为 `off`。

不会影响：Telegram 群内已发原消息、已发布的共享群总结、独立 Bot 角色、Danbooru 角色、共享提示词资产，以及已生成图片和历史生图记录中的素材快照。之后你在群内继续发言，新消息仍可能进入共享群历史。

关闭个人化后不会新建或使用个人角色绑定；`isolated` 用户的个人绑定不对其他用户可见。

## 管理员与诊断日志

管理员可在面板查看受权限保护的日志、会话、档案、记忆和生成记录。日志可保留有界的消息与工具内容以辅助排障，但凭据、授权头、Token、Cookie 和大体积二进制数据会被脱敏或摘要化。

在公开 issue、群聊或截图反馈问题时，只提供时间、功能、错误类别和脱敏短片段，勿贴整段更新、完整日志或数据库导出。

## 数据边界

外部模型、搜索、生图和集成服务按各自条款处理发往它们的数据。启用工具前请确保群成员知情；敏感话题建议关闭个人化、禁用外部工具或使用隔离聊天。

## AI 读取缓存头像

`get_profile_avatar` 仅在明确要求分析指定人物头像时调用，只读当前 Bot 档案中的缓存图片，不生成公开链接，也不跨 Bot 读取：

- 请求者为 `off`：禁用。
- 目标为 `off`：拒绝读取。
- 目标为 `isolated`：仅本人可读。
- 目标为 `normal`：同一 Bot 下其他用户也可请求读取。

权限在每次读取时实时检查，授权快照仅保留到本轮结束。允许读取的图片会发往当前视觉模型分析（遵循所选模型服务的数据条款）；图片二进制本身不写入日志或持久历史，模型生成的外貌描述按常规对话与角色规则保存。示例与失败状态见[从缓存头像整理外貌](/docs/guides/generation-library)。
